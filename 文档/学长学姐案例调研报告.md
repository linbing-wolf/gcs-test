## 三、智能搬运技术路线情报 🛠️

### 系统架构（多队共识）
```
上位机（视觉）：Jetson Nano / 地瓜派RDK X5 / 树莓派 + Python3 + OpenCV/numpy/pyserial/pyzbar
      ↕ UART 多线程串口通信（协议：0xFF + 9字节ASCII + 0xFE）
下位机（运动）：STM32F407/F103 + RTOS，编码器闭环，PID控制
```

### 各环节推荐方案
| 环节 | 主流方案 | 反例/踩坑 |
|------|----------|-----------|
| 底盘 | 麦克纳姆轮（全向）+编码器闭环+陀螺仪 | ⚠️ 不加悬挂走不直（四轮不着地、摩擦力不均） |
| 机械臂 | 塔吊式（步进升降+齿条伸缩）定位准 | 多舵机机械臂现场易断夹爪（多队中招） |
| 扫码 | ① **独立专用扫码模块**（XM1601 / GM65 一类）② OpenCV QRCodeDetector / pyzbar 连续 3 帧一致 + 130°广角 2MP USB 摄像头 | OpenMV 扫码=送分（分辨率低、曝光差）；**MaixCAM 属 Linux 平台、算力远强，但短板同样在镜头视场角，不宜扛扫码** → 详见《硬件选型评估.md》 |
| 颜色识别 | HSV两段色相（红=156-180 + 0-6）+ 面积判定 | 单一色相阈值扛不住色差 |
| 色环定位 | CLAHE限对比度直方图均衡+形态学梯度+多次高斯模糊+霍夫圆；粗定位640×480→精定位1920×1080 | 直接依赖绝对颜色，光线一变就挂 |
| 导航循迹 | 灰度/巡线传感器+视觉闭环修正+陀螺仪航向 | 视觉扫线定角的全图导航思路 |
| 电源 | 18650电池组（成本仅为航模电池1/5） | 单一内部电源全程不可更换 |
| 创新实践 | 熟练3D打印/激光切割/PCB设计，工具系统提前备 | 现场现学来不及；未安装新加工零件扣50%决赛成绩 |

### 通信协议参考（gongchuangsai_MBH 开源）
- 帧格式：`0xFF + 9字节ASCII + 0xFE`，不足9字节补 `0x00`
- STM32 发单字符任务码，视觉端回传 9 字节结果：
  - 任务码结果：`132+3120` 一类7位码补齐
  - 物块/色环坐标：`XXXXYYYYC`（X、Y各4位，C为颜色）
  - 就绪/确认：`987654321`；识别失败：`000000004`
- 下游摄像头扫二维码（如 `/dev/video0`），上游摄像头识别物块/色环（如 `/dev/video2`），波特率9600 8N1

### 视觉识别思路（往届获奖方案）
1. **二维码**：转灰度 → pyzbar 解码 → 连续3帧相同才认定（抗闪烁）
2. **转盘物块**：Hough圆 + HSV红绿蓝面积识别；红用两段色相；位置和颜色稳定后才回传
3. **色环精定位**：半分辨率粗检 + 全分辨率局部精修圆心（灵活切换）
4. **码垛**：Z轴高度补偿，第二批堆叠在第一批上、颜色一致

### ⚠️ 高频失败点 TOP8（多篇经验帖交叉验证）
1. **扫码环节翻车**（国赛初赛重灾区，摄像头选型不当+光线干扰）
2. **机械臂夹爪断裂**（省赛/决赛断爪；结构强度+夹爪冗余备件）
3. **上位机烧毁**（Jetson Nano供电/电源管理问题，有位学长省赛前两天烧板）
4. **代码逻辑缺陷**（`while(1)`死循环导致第二轮不运行、状态未复位）
5. **机械反复改导致视觉联调太晚**（校赛就在联调阶段出局）
6. **麦轮走不直**（无悬挂/四轮不着地/摩擦力不均）
7. **3分钟超时**（任务调度不紧凑，码垛方案选型失误浪费时间）
8. **规则理解分歧**（尤其创新实践环节，决赛现场命题理解不一致）
