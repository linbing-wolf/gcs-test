## 一、清单总评

| # | 器件 | 结论 | 一句话理由 |
|---|------|------|-----------|
| 1 | 麦克纳姆轮 | ✅ 通过（附条件） | 全向移动契合场地需求，但**必须加悬挂**，否则四轮不着地走不直 |

## 二、逐项评估

### 1. 麦克纳姆轮 ✅（附条件：必须加悬挂）

**支持依据**
- 命题场地：2400×2400mm，十字车道宽 400mm，需在启停区 / 原料区 / 粗加工区 / 暂存区间往返，并绕行随机位置黑色障碍物（φ50×100mm）
- 往届共识：麦轮可自由平移、精准自转、斜向行驶，为路径规划提供更多选择
- 第十二届参赛队原话："为小车提供了无与伦比的全向移动能力……极大地提升了空间利用率和操作效率"

**必须注意（⚠️ 高频失败点 TOP4）**
- 麦轮四轮不着地、摩擦力不均 → **走不直**
- 解法：**独立悬挂或前桥悬挂** + 编码器闭环 + 陀螺仪航向修正

**验收标准**：直线走 2m，无陀螺仪偏移 < 2cm，加陀螺仪 < 1cm

### 2. STM32F407 ✅（较往届升级）

**支持依据**
- 主控负载不轻：编码器闭环 + 多环 PID + 舵机 PWM + 多路 UART + 陀螺仪 + 显示驱动
- 往届对照：第十二届队伍用 STM32F103C8T6（无 FPU）；2023国一用 F407ZGT6；2026广东队用 F407 —— **F407 是当前主流选择**
- F407 带硬件 FPU，PID 浮点运算更从容

**注意**
- 若采用 CAN 总线步进驱动，F407 自带 CAN 外设，无需外扩

### 3. 张大头42闭环步进电机 ✅（方向正确）

**支持依据**
- 往届共识：**塔吊式（步进升降 + 齿条伸缩）优于舵机臂**，定位准、刚度高、防断爪
- 闭环步进的本质优势：内置编码器实时监测并补偿位置偏差 → 解决传统步进"丢步"
- 第十二届队伍原话："基本解决了传统步进电机丢步的问题，极大的增加了小车的灵活性与控制精度，包括但不限于自由平移、精准自转、斜向行驶"
- 资料可参考：2026广东队仓库含 `can_ZDT` / `Emm_V5` 相关模块（Emm_V5 为张大头/Emm 系列步进闭环驱动所用协议），例程可借鉴

**须确认（待办）**
- [ ] 42 步进的保持转矩是否满足整车负载（含机械臂与满载物料）
- [ ] 驱动方式：CAN 总线 还是 脉冲+方向（直接影响 STM32 侧代码结构）
- [ ] 供电电压与电流预算，纳入单电源总功耗核算

### 4. MaixCAM ⚠️（定位可用 / 扫码需另配）

**先分清一件事**
MaixCAM 与 OpenMV **不是一个量级**：MaixCAM 是 Linux 平台的 Python 视觉开发板（Sipeed），可用 OpenCV 生态、算力更强；OpenMV 则是跑在 MCU 上的 MicroPython 模块。把两者简单并列、同等看待并不准确。

**建议交给它的任务**

| 任务 | 可行性 | 说明 |
|------|--------|------|
| 物料颜色识别（红黄蓝绿，含色差） | ✅ 强 | OpenCV HSV 两段色相（红 = 156-180 + 0-6） |
| 色环定位（1-6 环） | ✅ 强 | CLAHE 抗光 + 形态学梯度 + 霍夫圆 |
| 码垛 / 放置位置定位 | ✅ 可 | 粗定位（640×480）→ 精定位（1920×1080 局部） |
| 车道 / 直线识别 | ✅ 可 | 配合循迹与航向修正 |

**它不宜扛的：扫码**

原因不在算力，在**物理条件**：
- 二维码为 A4 纸、贴赛场**内侧垂直**位置、**位置随机**
- 需稳定解出 **80×80mm** 的码 → 关键指标是**视场角 / 分辨率 / 曝光**
- MaixCAM 为**板载 CSI 定焦摄像头**（不可更换），视场角通常不及 130° 广角 USB 摄像头
- 调研结论：OpenMV 类方案在扫码环节"国赛大量队伍止步"

**扫码方案二选一（决策待定）**

| 路线 | 做法 | 优点 | 代价 |
|------|------|------|------|
| **A. 独立专用扫码模块**（第十二届队伍选择） | 加一个 XM1601（或同类 GM65）专管扫码，串口把任务码直接送 STM32 | 毫秒级解码、不占视觉算力、抗污损/模糊/倾斜；该队已写进创新点 | 增加一个模块与一路串口 |
| **B. 广角 USB 摄像头 + OpenCV**（2026广东队选择） | 另加 130° 广角 2MP USB 摄像头，OpenCV QRCodeDetector 连续 3 帧一致才认 | 分辨率高、可换镜头、光线鲁棒可调 | 需上位机接 USB；**须先核实 MaixCAM 是否支持外接 USB 摄像头** |

> ⚠️ **红线**：10 月中旬前必须完成"真实光照下 100 次扫码测试"，成功率 ≥ 99%。此项未通过前，其余优化的意义有限。

## 三、清单缺口（还需补齐的器件）

| 类别 | 待定项 | 参考依据 |
|------|--------|----------|
| **扫码模块** | 专用模块（XM1601/GM65）或 广角USB摄像头 | 见二.4；**当前最大缺口** |
| 陀螺仪 | HWT101 或 MPU6050 | 第十二届用 MPU6050 + 卡尔曼滤波解算欧拉角；往届另推荐 HWT101（约 300 元） |
| 电源 | 单电源、支撑 3 分钟高强度 | ⚠️ 第十二届踩坑：电池功率不足 → 降压模块停止输出。解法：大功率锂电池 + **电源与舵机输入端并联电容储能** |
| 显示装置 | OLED / 串口屏 | 命题硬性要求：上部醒目、字体 ≥12mm、不被遮挡；第十二届用 OLED 显示"同色装配/异色错配" |
| 夹爪 | 冗余备件 | 现场不可换件，多备几套；塔吊式优于舵机臂 |
| 旋转自由度 | 角度舵机 + 舵盘 | 第十二届决赛第二阶段要求物料**翻转 90° 水平放置** → 末端需增旋转自由度，建议**结构上提前预留** |

## 六、风险登记

| 风险 | 等级 | 触发后果 | 缓解措施 |
|------|------|----------|----------|
| 扫码方案迟迟不定型 | 🔴 高 | 省赛/国赛第一失分点 | **本周内**在路线 A/B 中定一条并下单 |

| 决赛要求翻转 90° 未预留自由度 | 🟡 中 | 需改结构，时间来不及 | 末端预留旋转舵机安装位 |
