# 测试横移参数应用比赛

用户要求把test l/r调好的横移应用到比赛，并明确速度仍使用比赛速度。主程序入口为runimu A/C；保留连续过路口和圆角路径，不把比赛变成每段停一次的测试。

## 共用参数

参数入口为src/car_config.h。

| 项目 | 当前值 | 生效范围 |
|---|---|---|
| 横移标定CALIBRATED_PPM_X | 10.72脉冲/mm | 测试、比赛横移 |
| 前向补偿标定CALIBRATED_PPM_Y | 9.68脉冲/mm | 测试、普通比赛横移、连续纯横移直线 |
| 左移前向补偿 | 28mm/米 | 共用LEFT_FORWARD_MM_PER_M |
| 右移前向补偿 | 35mm/米 | 共用RIGHT_FORWARD_MM_PER_M |
| 横移起步加速率 | 150RPM/s | CAR_LATERAL_ACCEL_RPM_PER_S引用CAR_DRIVE_ACCEL_RPM_PER_S |
| 连续同向横移总长≤1200mm | 比赛250RPM | 到1200mm仍属短档 |
| 连续同向横移总长>1200mm | 比赛200RPM | 跨E等中间节点及临近终点不改成短档 |

test的上电默认60RPM、临时rpm命令仍只控制测试。比赛速度分档没有改成这些值。前后道路240RPM/s、圆弧几何、同步转头弧内300RPM/s、减速200RPM/s及原障碍返回逻辑保持。圆角/渐变段不是纯横移，不套用直线补偿；出弯进入纯横移直线后升速仍限150RPM/s，终点只剩定角修正时沿用原控制。

## 换算修正

以前test将横移前向补偿按9.68生成脉冲，连续路线则把补偿毫米与正常前后运动一起按10.00/9.98换算，因此同一个28/35参数并不产生相同的补偿。

现在car_lateral_forward_pulses统一生成补偿。连续路径先把基础前后量转换为道路脉冲，再加补偿脉冲；CPOS逆算做对应减法，然后按结果方向转回道路单位。这样既保留前进10.00/后退9.98标定，也不会让位置闭环抵消新增补偿。前后误差修正跨零时也能正确反算。

普通比赛横移与test使用相同的150RPM/s平移斜坡；连续路径仍对四轮混控结果同比例限斜率和限速，因此不能据共用参数声称两种模式的每个瞬时轮速完全相同。

## 验证

tools/verify-lateral-production.ps1覆盖连续模式开/关、左右方向、四个车头方向、分段与连续斜坡、前后误差修正正负及跨零、实际CPOS注入反算、终点纠角与弧段隔离，并运行原连续横移补偿用例。

tools/verify-lateral-speed-tiers.ps1保留完整分档和运动断言，将过时的左30/右10固定检查更新为当前已标定左28/右35；核对1200/1201mm边界、实际单段结束、混控单轮上限、F→E→D和H→E→B连续长档，以及A/C发车与回程换向。

以上为主机模型。专项通过不代表烧录或真实地面横移已经验收；综合回归结果须与各自本轮记录分开报告。

本轮两个横移专项均在连续模式开/关下通过；72单元ARM完整构建成功，30条警告，AXF与HEX的510136个加载字节一致。配置对照确认原有比赛速度、标定及地图数值均保留。航向综合回归仍在原598行失败，机构综合回归仍在原161行失败。[本轮构建与验证记录](../evidence/merged-keil-20261120T132125986Z/validation-lateral-production.json)。未烧录或实车验收。
