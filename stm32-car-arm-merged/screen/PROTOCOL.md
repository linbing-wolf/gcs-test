# 串口显示协议

适用工程：`robot-status.HMI`，目标 TJC4827T143_011N_P20，480×272 横屏。启动设定 9600 baud、普通指令模式、100% 背光、`bkcmd=0`；车端串口采用 9600 / 8N1。

下面代码块中的每一行都是一条独立指令。真实串口发送时，每条 ASCII 指令后追加三个字节 **`FF FF FF`**；换行不能代替结束符。模拟器 String 输入区可直接分行粘贴，选择“当前模拟器”，点击“执行所有代码”。工程文字编码为 GB2312，本接口只需发送英文变量名和整数。

## 切换显示

比赛页：

```text
page 0
```

调试底盘：

```text
group=0
page 1
```

机构改用 `group=1`，感知改用 `group=2`。已经在 page1 时，写入 `group` 后发送 `click b0,1` 即可刷新分类。页面初始化自动隐藏内部按钮并刷新；切页保留全局数据。断电或重启不保留数据，主控需重新发送。

本工程接收的是屏幕协议。通过主控的调试串口切页时，需要主控将经校验的显示指令转发至屏幕 UART；本次没有实施该转发程序。不能将两个发送器的 TX 同时直接接到屏幕 RX。

## 任务码与统计

示例 `134+123+314+231`：前两组去掉加号写入 `taska`，后两组写入 `taskb`。先写完整任务，再设有效标志，最后刷新。

```text
taska=134123
taskb=314231
taskok=1
phase=6
elapsed=78
pick=0
place=3
click b0,1
```

`taskok=1` 时显示完整任务；其他值显示等待扫码。比赛中有效任务应保持到本轮结束，不能因传感器超时清空。HMI 不验证任务合法性：主控应验证四组三位数、颜色编号 1～4 和位置编号 1～3，完成校验后才设 `taskok=1`。每批任务写完后再发一次 `click b0,1`，避免显示混合的新旧值。

| 变量 | 含义 | 初始值 |
| --- | --- | --- |
| `taska` / `taskb` | 两个六位整数，保存全部四组任务码 | 0 / 0 |
| `taskok` | 任务有效标志 | 0 |
| `elapsed` | 主控计时，单位秒；屏幕不自行计时 | 0 |
| `pick` / `place` | 抓取/放置正确次数；非负为有效，负值显示 `--` | -1 / -1 |
| `phase` | 阶段枚举，见下表 | 0 |

| phase | 显示 | phase | 显示 |
| --- | --- | --- | --- |
| 0 | 待启动 | 6 | 第二批粗加工 |
| 1 | 扫码 | 7 | 第二批码垛 |
| 2 | 第一批抓取 | 8 | 返回启停区 |
| 3 | 第一批粗加工 | 9 | 已完成 |
| 4 | 第一批暂存 | 10 | 故障 |
| 5 | 第二批抓取 | 其他 | 阶段未知 |

## 调试变量

| 变量 | 显示内容和单位 | 未知值 |
| --- | --- | --- |
| `lf_t` / `lf_r` | 左前目标 / 实际速度，RPM | -32768 |
| `rf_t` / `rf_r` | 右前目标 / 实际速度，RPM | -32768 |
| `lr_t` / `lr_r` | 左后目标 / 实际速度，RPM | -32768 |
| `rr_t` / `rr_r` | 右后目标 / 实际速度，RPM | -32768 |
| `lift` / `push` | 升降 / 平推目标，mm | -32768 |
| `grip` | 夹爪指令角度，° | -32768 |
| `tray` / `pan` | 置物盘编号 / 云台指令角度，° | -32768 |
| `mechanism` | 主控汇总的机构反馈状态 | -1 |
| `yaw` / `yaw_t` | 当前 / 目标航向，0.1°，如 -905 表示 -90.5° | -32768 |
| `color` | 0 未知，1 红，2 黄，3 蓝，4 绿 | 0 |
| `dx` / `dy` | 视觉偏差，px；color=0 时隐藏为 `--,--` | 由 color=0 表达无有效识别 |
| `vision_age` / `imu_age` | 主控报告的视觉 / IMU 数据年龄，ms | -1 |
| `voltage` | 驱动电压，mV，如 12345 表示 12.345 V | -1 |
| `comm` | 0 未知、1 正常、2 超时；主控报告 | 0 |

`mechanism`：0 未使能，1 运动中，2 已到位，3 堵转，4 回零中，5 回零失败；其他值显示 `--`。只有可靠反馈才能报告“已到位”。

所有变量都只是显示值。写 `grip=90` 不会让舵机运动；实际动作仍由现有车端程序管理。`*_r` 必须来自有效速度反馈；没有反馈就发送 -32768。这组变量没有自动过期逻辑，数据年龄和通信标志需由主控更新，通信中断后画面会保留最后一次收到的数据。不能把保留值当作实时有效数据。

底盘更新示例：

```text
lf_t=120
lf_r=118
rf_t=-120
rf_r=-117
lr_t=0
lr_r=0
rr_t=150
rr_r=-32768
click b0,1
```

建议只发送有变化的字段，每批结束后刷新一次，调试起始刷新周期可用 200～500 ms，再按实屏速度调整。该周期是集成建议，未经过真实串口性能验收。串口命令不要插入空格，如使用 `lf_t=120`。

当前状态背景只绘制 y=144～271 的下方区域；有效任务字形按固定位置绘制，状态刷新不使用全屏白底覆盖任务码。原生 page 切换仍有初始化绘制过程，比赛期间推荐保持 page0；实际切页瞬态及刷新效果需要实屏验证。
