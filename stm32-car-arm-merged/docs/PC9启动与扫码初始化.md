# PC9启动与B点扫码初始化

对应 `20261023-merge2-r66`；保留r65配置发送/FAULT独立接收，并兼容现场已捕获的CR结束符。

- **PC9按下高电平，消抖30 ms后请求 `runimu C`。** 与手动串口完全共用命令入口；当前自动作业要求先完成已有 `arm on`、实际收拢姿态和载物台1号位声明，并有新鲜IMU数据。按钮不代替实际姿态确认，也不自动声明坐标。
- 长按只触发一次，稳定松开30 ms后才能再次触发；上电时已按住先忽略，松开再按才启动。已有路线/作业占用时按下只会按原串口规则拒绝，不重置路线，也不排队等将来启动。
- 同一轮主循环同时收到急停和按钮时，急停优先，当前按钮事件不会发车；`!`行为保持。
- **自动路线首次到达扫码B点时，自动执行一次与 `qr init` 相同的初始化**，使用当前波特率；未指定时为9600。清空扫码接收半包、丢弃状态及扫码统计，重新配置CRLF和连续扫码模式。已有手动预置任务码保留。
- 扫码初始化与B点转向并行，不额外插入阻塞延时。配置状态与文本接收独立：BOOT、配置过程中或FAULT时均可解析完整CR或CRLF任务码；只有真实配置ACK才能进入READY。首次B点收到合法码即可锁定任务，随后仍按原路线朝向完成转向再继续。
- 一轮两批作业共用任务码；返程经过B点不再次初始化，也不重新扫码。下一轮首次B点才再次初始化。手动 `qr`、`qr init`、`qr baud ...` 继续可用。

## r65配置发送与故障恢复

两条9字节配置命令、7字节正确ACK和波特率保持原值。USART1的TXE中断逐字节连续发送；末字节TC中断记录实际发送完成时刻，然后才开始1000 ms ACK等待。每条命令另有1000 ms发送限时，便于区分发送未完成和应答未收到。中断不打印、不解析任务；主循环仍有界处理接收队列。

配置超时只标记扫码配置FAULT，不调用底盘停机或故障接口，不自动重发。文本接收继续工作：收到真实完整任务码后沿用原任务格式验证、首次B点接收窗口、首码锁定和急停规则；不从超时生成任务，不将FAULT伪装为READY。二进制应答整体分流，错误应答的尾字节不进入二维码；应答插入半条文本时，该受影响文本需到换行重新同步，不能拼接成新任务。既有UART错误/溢出仍先丢弃受影响数据并在换行处恢复，物理断线或持续乱码仍需检查硬件。

## r66现场CR帧修复

操作者实际日志的32字节为两条`213+213+213+213\r`：每条以`0D`结束，没有`0A`。r65虽然在FAULT中继续接收，却仍等待CRLF，因此多条CR帧不断拼接，最终触发超长丢弃。

r66在CR处立即结束并校验本条文本，兼容模块尚未成功配置为CRLF时的实际输出；若后面还有LF，仅清空帧边界，不重复提交。正文126字节上限、任务格式验证、首码锁定及二进制应答隔离保持，不接受无结束符的半包，也未扩展为LF单独结束。FAULT后的受损/超长帧在CR或LF处重新同步，后续完整合法CR帧可接收，不必靠`qr init`清除半包。

测试先用现场32字节在r65复现`results=0,length=32`，修复后验证`results=2,length=0`且任务为两批`213213`；另覆盖各配置状态、连续CR帧不累积超长、CR/LF分次到达不重复、无效/无结束符/LF单独结束拒绝、二进制插入不拼码，以及A/C两条路线在CRLF配置或连续模式ACK缺失后收到实际CR码继续。

`qr`在原状态字段后增加`phase=TX/WAIT_ACK/IDLE`、`tx=N/9`、`ack=N/7`及`text_rx=enabled`。`ack`表示本配置阶段正确前缀的最高匹配进度；FAULT额外显示失败阶段和当时的发送/匹配进度。示例：

```text
[scanner] configuration fault stage=CRLF reason=ACK_TIMEOUT tx=9/9 ack=0/7; text receiver remains active; qr for status
[scanner rx hex] oldest_to_newest=...
```

`stage`为`BOOT/CRLF/CONTINUOUS`，`reason`为`TX_TIMEOUT/ACK_TIMEOUT/RX_ERROR`。最近32个主循环实际处理的RX字节仅在故障或手动`qr`时按HEX输出，不在中断或每个字节到来时打印。发生FAULT后收到合法任务码，配置状态仍显示FAULT，任务可以在满足原转向完成条件后继续；这些是两个独立状态。

`tools/verify-scanner-recovery.ps1`覆盖独立TXE/TC事件、发送与ACK计时分离、两个配置阶段缺ACK、FAULT后分包合法码、无效/重复码、二进制分流、旧ACK半包、相邻ACK、计时回绕及真实A/C路线B点恢复。本地模拟及ARM构建状态见`evidence/current-validation.json`；不代表模块实际串口时序或实车已经验收。第一次现场ACK失败的物理原因仍须结合新增诊断核实。

## 参数位置

[car_config.h](../src/car_config.h) 中 `CAR_START_BUTTON_GPIO/PIN` 对应PC9，`CAR_START_BUTTON_DEBOUNCE_MS` 为按下/松开的消抖时长，单位ms。原有 `CAR_SCANNER_UART_BAUD`、`CAR_SCANNER_BOOT_MS`、`CAR_SCANNER_ACK_MS` 数值保持；新增 `CAR_SCANNER_TX_MS=1000` 单独限制配置发送时间。GPIO输入仍为下拉、高电平有效。
