# 暂存抬升并行核查（r96补充验证）

当前r96源码中，两次暂存都在松爪后安排固定移位请求，再开始抬升收回。`station_parallel_index_update()`与末尾离站都使用`arm_station_clearance_ready()`检查实际125mm净空，没有要求机械臂升至135mm或完整归位后才移车。

第一次放置高度为5mm，第二次为65mm；到125mm净空前的升降距离分别为120mm和60mm。两者放行时离最高位都只剩10mm。因此该逻辑允许重叠，但不保证实车上能看到明显的“边升边走”：中间高度反馈是否及时到达、四轮新鲜位置基线采集耗时及机构实际速度都会影响窗口。后面这些是待实车日志核实的因素，不是已确认故障原因。

运行`tools/verify-storage-lift-overlap.ps1`可核查A/C两方案、两批暂存、每批第1/2/3次放下，以及反馈缺失/恢复和人工`!`。共36个受控模型用例：将实际升降反馈停在124mm时不放行，更新到125mm后，在仍未到135mm且机械臂动作未完成时检测到底盘非零运动指令。

本轮没有修改生产源码、净空门槛或版本号，没有重新构建或烧录。2026-10-26复核时，当前本地`CAR_HEADING_KP_X100=300`、`CAR_HEADING_MIN_RPM=7`，而上次r96构建时为200/5；保留当前本地调参，并按300/7重新跑通36个专项用例。旧r96的Keil产物不包含这两项变化，旧完整路线验证不代表新调参已经完整回归。

受控模型通过只证明软件路径存在且可触发。当前无法取得车上版本及运行日志，因此“实车看似等到顶”的原因尚未确认；反馈是否及时到达、四轮预检耗时和车上固件版本都是待核实因素，不能当作已确认根因。

本地`keil/OBJ`下的AXF、HEX、MAP也已更新。本次保留这些产物并登记哈希变化，没有用它们替代原独立r96构建的验证结论，也未确认它们与当前300/7源码对应。
