# CAN自动Bus-Off恢复（r97）

按操作者指定，`vendor/stm32/can_ZDT/board.c`的`CAN_InitStructure.CAN_ABOM`由`DISABLE`改为`ENABLE`。bxCAN在检测到规定的总线恢复条件后自动退出Bus-Off，无需仅为退出该状态重启主控。

保持现有500kbit/s位时序、自动重发、FIFO发送顺序及64帧软件队列。自动故障停机策略、人工`!`、控制流程和运动参数不在本次修改范围。当前本地原地转向KP=300、最低7RPM随本次完整构建保留。

收到的`ESR_dec=16253015`对应`0x00F80057`，BOFF=1、LEC=5。该配置修复的是线路恢复后控制器缺少自动重入总线的能力；终端电阻、线束、供电、位时序或节点冲突等引起的原始位错误仍须排查。

保留队列意味着恢复后既有积压帧可能继续发出。此版不自动清除旧运动命令，也不新增任务自动重启；队列溢出时原来已被拒绝的请求不会凭空补回。总线故障期间，经CAN发送的`!`停车命令不保证及时送达，应先确保机构和底盘安全静止，再做断线恢复等实车测试。

核对依据：ST RM0090的CAN_MCR.ABOM定义，以及项目标准库`CAN_Init()`对ABOM位的配置。主机CAN队列测试可以检查邮箱阻塞期间保留命令及邮箱释放后的FIFO提交，无法仿真实际收发器、错误计数和硬件Bus-Off恢复。Keil构建和AXF/HEX核对也不能替代实车故障恢复验证。
