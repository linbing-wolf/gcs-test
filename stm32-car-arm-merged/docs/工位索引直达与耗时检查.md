# 工位索引直达与耗时检查

日期：2026-10-21；当前版本r43。r42索引优化的历史对比保留在前半部分。扫码问题暂缓，见[待处理问题](待处理问题.md)。

## 已完成的流程优化

粗加工两批与暂存两批共用push_station_index：相邻环150mm，1→3或3→1一次300mm到达，不在2号停靠、重取互锁、重新预检和加减速。总移动距离、目标/颜色顺序、最终回2号、126.5°工作角、D/E/F次数及抓放参数保持。途中仍保持高位收回；到目标后等待当前编码器/IMU动作和反馈交接完成再抓放。没有删除底层等待或改变速度参数。

## 前后电脑对比

同一基线模拟器对粗加工/暂存、两批、6种环序共24组进行前后配对；本次改变仅为跨环合段。总索引距离均保持，少掉的移动段数恰好等于300mm直达次数。

| 作业 | 单次作业节省（电脑模拟） |
| --- | --- |
| 粗加工 | 2.547～5.154秒 |
| 暂存 | 0.000～2.577秒；原路径无需跨环时不变 |

四次工位作业之和在所选24组配对中每轮减少7.641～15.432秒。该统计不包含原料区和道路行驶，使用理想相机回复，不是实车整轮计时或节拍承诺。

原始CSV和对比见[evidence/direct-index-benchmark-20261021T035650836690Z](../evidence/direct-index-benchmark-20261021T035650836690Z/comparison.json)。覆盖真实生产工位函数、编码器目标及独立场地坐标的回归另见当前evidence/current-validation.json。

## r43已经删除的等待

完整作业表先按原规则检查，再对粗加工/暂存2/3/5/6号作业去重。比较的是本表之前指令的已安排目标，不使用人工声明的进站姿态推断首次动作已完成。执行器仍只有在前一步完成后才推进，所以删掉的后续步骤没有新的物理目标。

- 同一个云台角重复：删除整条重复步骤，包括其600ms插值和重复双轴反馈预检。
- 已open后没有close又open，以及同状态重复夹爪命令：删除重复步骤及其200ms插值；全部实际open↔close变化保留。
- 升降/平推重复同位置：删除重复步骤和相应预检；首次动作、实际位置变化和到位反馈保留。
- 载物台+云台复合步骤：只有角度和杯位都已知且都没变化才删除；只转角、只换杯位、杯位首次未知均保留。
- D/E/F/LOAD1、底盘索引和F回程等事件不去重；若遇到宏动作，之后的姿态重新视为未知。原料与手动动作不调用此优化。

同一24组电脑对比中每次粗加工或暂存作业均比r42减少2.691秒，四个工位合计10.764秒；总索引距离、索引段数和直接300mm次数完全相同。未计真实识别/夹持误差，不是实车节拍承诺。

基准数据：[r43前后对比](../evidence/station-dedup-benchmark-20261021T054537106395Z/comparison.json)。独立语义回归覆盖首次目标、复合动作单边变化、所有抓放变化、重复视觉/底盘事件、宏动作、224步边界和重复执行去重；完整站点回归继续检查各颜色/环序、实际模拟位置、互锁和抓放。

## 不能直接删除的原因

| 等待 | 保留原因与进一步优化边界 |
| --- | --- |
| 实际云台/载物台600ms、夹爪200ms | 代码在此期间逐步更新PWM，且机构无舵机到位传感器。删掉后只会瞬间给出终值，无法证明转到位/夹紧就开始下一步，可能在旋转中伸出下降或夹紧前抬升。精确600/200ms不是永远不可调，但当前没有更短时间的实测依据；本次删的是重复动作，不是实际动作时间。 |
| 升降/平推到位与CAN轮询 | 等待真实轴位置和arrived；删掉会将未完成动作当作完成。10ms是查询节奏，不是等待10ms就假定完成。 |
| 停车100ms/稳定300ms、互锁200ms | 属于现有零输出后新反馈和状态交接判据。直接清零会改变“可开始机械臂/下一次移动”的条件，不能靠电脑模型证明实车已停稳。这些精确数值可实测后调整，本次不增加或扩展保护。 |
| CAN每轮1ms | can_SendCmd只提交CAN_Transmit邮箱，没有等待发送完成或发送队列；连发四轮命令及同步可能出现CAN_TxStatus_NoMailBox并触发总线提交故障。不能直接删；若后续优化，应改为等待可用邮箱/有界非阻塞队列，不能忽略发送失败。 |
| 调试串口TXE | 表示发送寄存器可写。直接删等待会覆盖未发字节、破坏日志；需要有界异步发送队列才能同时保留日志。本次不重构串口所有权和中断。 |
| 扫码启动及配置ACK | 等模块启动和真实应答，不是每个动作都等；扫码故障按操作者要求暂缓，本次不改该路径。 |
| 视觉800ms、300ms回显、1200mssettle | 回显300ms纯显示用途可删；800/1200需按实际机械/相机节拍验证。本地只有已留存的视觉快照，没有确认当前板程序；不改证据文件冒充上位机生效。这些等待不包含在STM32 HEX中。 |
| 15/20/25/40/60秒TIMEOUT及8000ms yawtest | TIMEOUT主要是异常日志期限，正常流程不等满；yawtest只在显式诊断执行。删除它们不会给正常自动作业提速。 |

当前源码、完整ARM和测试结果以evidence/current-validation.json为准。所有保留理由针对当前实现，未宣称精确时间为驱动器硬性要求或实车已经标定。
