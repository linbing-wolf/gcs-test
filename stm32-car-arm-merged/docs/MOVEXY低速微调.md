# MOVEXY低速微调（r68，2026-10-23）

用户在独立视觉调试F2中发出 `MOVEXY,18,-11`，换算为前后-18mm、横移-11mm；观察到接近目标时抖动。日志中的两轴最终到位，没有打印到平移指令反复变号。500ms日志不足以确认实车抖动的唯一原因。

## 已复现的指令切换

末端两轴均为-3RPM时，未叠加旋转的四轮分量为6,0,-6,0。现有航向PD把不足1RPM的微弱输出也保留为±1RPM，因而被抵消的第二、四轮可能反复换向。用真实控制函数和F2入口重放角差-0.09°、角速度正负1.5°/秒，四个移动方向各32次样本，旧代码累计产生248次这类轮速命令换向；r68同样重放为0次。

这是软件重放中消除了一种低速换向触发源，不代表已经确认或消除了全部实车震荡。

## 行为范围

- 仅工位双轴 `MOVEXY`，且仍有平移指令、两轴速度幅值都不超过6RPM时生效。配置为 `CAR_MOVEXY_FINE_MAX_RPM`，单位RPM。
- 此时原始航向PD量幅值不足1RPM，则输出零旋转修正；幅值达到1RPM的控制量继续沿用原PD和现有限幅。
- 两轴平移目标、距离增益、最低3RPM、加减速、两轴1mm完成窗口、停车和互锁不变。平移归零后沿用原停车对齐函数。
- 普通路线前后/横移、原地转向、单轴 `MOVE`/`MOVEY` 及较快的双轴运动不使用这项抑制；没有增加积分或停机条件。
- 保留用户任务开始前已设置的USART2波特率230400。模块回传50Hz由用户设置，固件不会自动修改模块回传速率。

## 日志和验证

`turn_ref` 仍是原PD结果，`turn_cmd` 是低速处理和现有限幅后的旋转分量。因此低速时出现 `turn_ref=1 turn_cmd=0` 可以是预期行为。

`wheel_rev=a,b,c,d` 是本次MOVEXY中四轮成功提交的非零命令换向次数。中间的零命令保留上一非零方向；同一批次不重复计数，计数到65535饱和，新段清零。正常的末端反修或较大偏航恢复也可能增加它；这是诊断数据，不是报警或停车条件，不等同于真实轮子反转次数。

专项检查包含微小控制量的边界、有效角差/阻尼保留、速度和工位范围、计数输出、F2的18/11mm四方向独立惯性模型、D/E/F双轴几何、编码器极性、队列、取消、急停和缺反馈处理。专项脚本为 `tools/verify-movexy-fine.ps1`。当前验证和新固件位置见 `evidence/current-validation.json`。

工位视觉套件配置9仍有继承的 `push_move_to` 测试编译错误；配置0至8通过，不能宣称整个套件通过。
