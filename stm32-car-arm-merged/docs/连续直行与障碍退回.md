# 连续直行与障碍退回（20261018-merge2-r1）

> 本版合入自动工位；底盘行驶期间的连续过点与障碍退回不变。工位期间发送 `obstacle` 会停止整个作业，不会在机构伸出时自动倒车；准备与恢复见 [自动作业说明](merged2功能合并与自动作业.md)。

## 本轮行为

`runimu A/C` 对下一段做预看：只有目标航向、车身平移轴、正负方向均相同，而且中间不是当前任务点，才连续通过。减速依据当前段剩余距离加上可连续段的距离计算；经过节点时更新逻辑道路和里程偏移，保留同一个IMU目标、编码器基线、速度斜坡和CAN反馈检查。

当前A/C路线每圈有3处：两次 `F→E→D` 各连续1670mm，最后 `H→E→B` 连续1770mm。转弯、前后换向、横移切直行、工位对位和最终停车仍停稳。地图、路线表、任务次序及机械机构命令不变。旧 `run A/C` 入口已移除；人工 `nav/go` 不使用这项连续直行逻辑。

```text
[route segment] from=F to=E ... distance_mm=860 ... continue_mm=810
[route pass] node_est=E; no stop; physical_pose=unconfirmed
[route segment] from=E to=D ... distance_mm=810 ... continue_mm=0
```

`continue_mm` 为当前段后还能同向连续通过的距离。`[control]` 的距离/目标和 `yaw_win` 极值里程仍相对当前逻辑段；跨节点时输出旧段剩余窗口，再改成新段相对里程，底层编码器不重置。`[route pass]` 替代该中间段的停车完成消息，因此18个逻辑平移段只有15次平移停稳，不要把逻辑段数或 `step` 当成起停次数。

## 障碍信号边界

**当前没有接入自动障碍检测信号。** 本版不会自行发现障碍物；仅提供现有串口命令 `obstacle` 作为外部触发入口。命令需换行，只有现场操作者明确发送才触发；代理没有向车辆发送命令。后续传感器/视觉接入需要再明确引脚或协议。

在 `runimu A/C` 运行期间发送 `obstacle` 后：

1. 立即请求四轮停止，绕过正常速度斜坡和正在等待的速度ACK。
2. 等待四轮新的停稳/位置反馈及有效IMU，不通过等待时间猜测停车位置。
3. 依据实际编码器记录的当前道路动作，反序、反方向退回**触发时最近已记录的节点**。例如已出现E的 `[route pass]` 后在E→D遇障碍则退回E；尚未记录经过E时，退回F。触发附近的节点判断仍依赖轮询编码器，不是地面绝对定位。
4. 起终点道路的“横移＋直行”按已走路径反序退回，不把一段直线倒车冒充回到前一个节点。若仍在节点转向/启动预检且没有平移，不凭空后退一段距离。
5. 结束进入 `WAIT_OBSTACLE`，不推进工位计数、不自动重新出发、不自行绕行。记录本趟道路封禁；不自动修改人工 `nav/go` 的封禁表。

```text
obstacle
[obstacle stopping] return_node_est=E; ...
[obstacle returning] node_est=E distance_mm=... remaining_parts=... rpm_limit=60; ...
[obstacle return stopped] node_est=E; encoder-based; physical_pose=unconfirmed; waiting; no automatic resume
[run] WAIT_OBSTACLE ...
```

退回基础平移速度上限为 `CAR_OBSTACLE_RETURN_RPM=60`；轮速仍叠加航向纠偏，不等同于每轮一律60RPM。退回和停稳过程中再收到 `obstacle` 会故障停车，不递归退回；`!` 始终停止整个系统。IMU过期、反馈/ACK丢失、堵转、CAN故障、退回距离超差等均停车，不报告退回完成。

`WAIT_OBSTACLE` 下直接重发 `runimu` 被拒绝。操作者检查现场、清除障碍并确认车辆实际位置后，自动作业会话下先确认机构收拢并 `arm off`，再用 `nav` 切换模式，再按人工确认流程操作；若要重跑整圈，必须先摆回对应启停区并核对初始朝向。没有“自动从断点恢复”的隐含动作。

人工导航 `nav/go` 下原来的 `obstacle` 行为保持不变：请求停车、封禁道路、等待操作者实际返回确认；该模式没有新增自动倒车。

## 速度配置与验证范围

按操作者明确选择，保留 `CAR_RUN_RPM=3000`，没有改回90或300。四轮混控实际仍最多输出300RPM，正常直行还受120RPM/s斜坡、预测制动和距离比例限制；配置3000不代表车辆或电机能达到3000RPM。旧 `run` 及原始脉冲转向已按操作者确认清理，见 [清理范围](runimu全程入口与旧代码清理.md)。

交付验证使用本目录实际3000配置：`tools/verify-heading.ps1` 默认运行保留的单步调试/导航入口及完整 `runimu` 航向/反馈/故障回归；`tools/verify-continuous.ps1` 验证连续穿越节点及障碍退回；另跑直行动态、机构互锁回归和完整ARM构建。不再需要 `-SkipLegacy` 参数。报告见 [当前验证](../evidence/current-validation.json)。

IMU记录与地面真实车头方向仍有操作者报告的5～10°差异，本轮没有修复该测量问题。编码器推算退回不等同于实车准确返回，侧滑和真实路径仍需现场验证。未接障碍传感器、未由代理烧录或执行车辆动作、未上传本版到GitHub。
