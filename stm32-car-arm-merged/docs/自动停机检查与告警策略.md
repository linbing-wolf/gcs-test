# 自动停机检查与告警策略

r40：5号升降、7号平推轴的未使能/堵转/保护状态仅记录，不再由该状态调用arm_stop或进入FAULT。日志包含addr、flags_dec、enabled/arrived/stalled/protected、步骤与升降/平推目标；同一步内相同轴相同异常不重复刷屏，状态变化或恢复后再异常重新记录。原始flags与实际位置/到位完成判据保持；不自动清除驱动器保护、不自动重新使能、不虚构动作完成。急停、CAN发送/总线故障、位置命令拒绝、行程限制和底盘驱动故障处理保持。MOVEY仍正左负右，抓放参数不变。未烧录或实车验收。

当前版本：20261020-merge2-r40；以下基础策略沿用r29，5/7轴状态异常改为上述仅日志行为。范围是本合并工程的应用代码；原底盘、独立机构工程和厂商驱动未做批量修改。

本次**没有按字面删除一切停止条件**。超时、轮速读数、反馈时效、视觉等待和接收溢出等监控项改为告警与恢复；显式停止、已报告的底盘驱动器故障、机械超行程、严重定位错误、无法提交完整命令和非法作业仍停止或拒绝。这是保留实际动作依据的工程判断，不能把没有完成的动作记成完成。

| 路径 | r29行为 |
| --- | --- |
| 底盘单次查询150ms无匹配回包 | 打印地址、命令、等待时间，结束该查询等待并继续轮询；暂停输出但保留当前段与里程，实际数据恢复后继续 |
| 底盘速度ACK缺失 | 告警，刷新下一批命令；不填写虚假ACK掩码 |
| 四轮/IMU数据过期、IMU接收错误 | 不进入RUN_FAULT；缺有效底盘数据时零输出，保留目标/阶段/编码器基线，恢复后继续 |
| 航向样本突跳 | 同一坏样本持续暂缓，不在下一轮冒充有效测量；下一份有效样本可恢复 |
| 底盘/工位/机构动作等待期限 | 告警；不再凭等待时间取消任务，也不按估时自动宣布完成 |
| 机械臂查询超时 | 记录轴号和查询种类，继续轮询；两轴有效状态/位置齐全后执行原动作 |
| 5/7轴未使能/堵转/保护标志 | r40仅记录原始状态及目标，不进入FAULT；保留实际位置/到位完成条件 |
| 机构位置ACK丢失 | 告警；仍必须有实际位置变化及驱动器到位状态才能完成 |
| 轮速幅值/持续时间 | 手动、自动会话和普通预检都仅记录；已删除15RPM/3000ms旧配置和计时字段 |
| CAN接收队列/FIFO溢出 | 丢弃不完整接收数据，继续实际轮询；底盘和机构层保持一致 |
| 视觉CRC/格式/错误/未找到目标/迟到回包 | 拒绝坏数据但保留当前等待，不取消工位；迟到有效PICK/DISC仍可继续 |
| D/E对准60s和75mm名义预算 | 仅告警；同次进站仍只有一次D或E，不新增R或自动重发 |
| 手动位置模式估时超限 | 留在WAIT_CONFIRM，等待绑定本次命令代号的实际/人工确认，不自动停车或完成 |
| 主动obstacle | 遵守用户停止命令，确认已停稳再倒车；等待超时只告警，不取消回退现场 |

仍保留的停止或拒绝：`!`、`stop`、`arm stop`、作业中主动`obstacle`，底盘驱动器禁用/堵转/保护，CAN bus-off及不完整命令提交，机构超行程/未收臂/未声明姿态，编码器方向错误/严重里程异常、失控偏航、非法任务与路线、数组和协议内存边界。它们没有被伪装成“日志后成功完成”。

验证包括：正常A/C两批路线、150mm移动到40mm后丢失一轮反馈35秒并恢复（基线不重置，最终149mm，在原1mm容差内）、机械臂缺反馈超过15秒后恢复、缺ACK但实际位置到位、视觉跨越20/25/60秒仍保留请求、同次进站D/E只发一次、持续非零轮/轴速度、接收溢出恢复；真实驱动故障和用户停止仍需停机。详细当前结果以`evidence/current-validation.json`的源码哈希和报告为准。本地模拟/构建不等于烧录或实车验收。
