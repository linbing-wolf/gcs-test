# 视觉上位机指令执行（r47）

本次按操作者要求，由视觉端决定纠偏的轴、方向、幅值、次数和结束时机，STM32只执行收到的离散位移。修改范围为D/E/F视觉收包和工位执行；机械臂参数、路线、索引距离和速度参数保持r46。

已读取用户提供的QUICKSTART及视觉目录，并核对同仓库的`AI_HANDOFF_STM32.md`（视觉3.9.1）与`maixcam_app_v2/tasks.py`、`protocol.py`、`config.py`。对应公开提交为`cedd4ca4d784a61b25ae4b4a5279a0239f6964d4`，快照与SHA256见`evidence/vision-handoff-r47-context.json`所指目录。QUICKSTART仍有旧版`STACK,x,y`说明，当前实际源码发送`STACK,x,y,dx,ok`，以源码和详细交接文档为准。

## 收到什么就执行什么

D/E/F统一接收`MOVE`、`MOVEY`。数值为像素，沿用操作者此前指定的假设：**1px=1mm**（`STN_VISION_MM_PER_PX_X1000=1000`），未做实测标定。

| 上位机指令 | 当前车体动作 |
|---|---|
| `MOVE,+300`或`MOVE,300` | 后退300mm |
| `MOVE,-40` | 前进40mm |
| `MOVEY,+40`或`MOVEY,40` | 向左横移40mm |
| `MOVEY,-40` | 向右横移40mm |
| `MOVE,0` / `MOVEY,0` | 本条不移动，不撤销前面指令 |

视觉源码已经应用`ALIGN_GAIN=0.65`、轴比例和方向配置，下位机不再乘一次视觉增益，不压成固定3mm，不根据偏差幅值限幅、设死区或决定再修正几次。方向以这张线协议表为准；视觉端需要反向时使用其D/E/F方向配置。F现在也执行`MOVEY`正左负右，已删除旧的“根据STACK的y大于240自行向右修正”规则。

每条位移按收包顺序进入同一FIFO。比如`MOVE,11 → MOVEY,13 → MOVEY,-23 → MOVE,40 → MOVE,0`，依次执行五条；同轴新数值和0不会覆盖旧指令。底盘一次执行一条，实际编码器/IMU运动结束并完成原有互锁交接后才开始下一条。启动暂缺反馈时保留队首，不提前消费。FIFO为32项；当前上位机每次任务最多两轮、每轮两轴，最多四条。超过容量会明确记录`motion queue full`，不能保证异常无限突发均被接收。

## 谁决定结束

- D/E收到上位机成功终包`DISC,x,y,dx,1`，结束本次接收。
- F收到`STACK,x,y,dx,1`，结束本次接收；兼容旧`STACK,x,y`作为结束报告。
- 不以640×480范围、`dx=cx-320`、残差大小或本地视觉行程预算否决上位机成功通知；坐标只记录/显示，**不产生额外移动**。
- 已接收的全部指令、当前移车和互锁交接完成后才进入抓放；终包不清空待执行队列。终包之后的新MOVE不属于本次已结束任务。
- CRC、帧长、整数格式、成功字段及当前会话归属仍按协议解析。失败/缺失回包保留原请求并打印日志；不伪造完成，不自动重发D/E/F，不发R，不等READY，不回复运动ACK。
- 急停`!`取消整个任务及队列；原有机构姿态和底盘故障处理保持。这里取消的是下位机的视觉纠偏决策，不是更改整车急停或运动完成依据。

## 暂存第二批的交接

第二次暂存继续跳过E，每块在目标环位发送一次`F,颜色`，收到并执行MOVE/MOVEY，收到STACK结束报告后排空动作，再进行平台100mm夹取、65mm叠放。原有放完后空爪高位恢复环位基准的动作保持：记录本次F期间实际交付底盘的累计前后/横移毫米数，再逆序恢复横移、前后，以便下一段150/300mm索引仍以原环位为基准。这属于放置后的既有工位路线，不是依据STACK坐标再次纠偏。

## 验证与边界

当前结果见`evidence/current-validation.json`和`evidence/vision-authority-r47-verification.json`。覆盖D/E/F连续两轴、多轮同轴、0、提前终包、无MOVE时非中心坐标终包、等待反馈重试启动、急停、队列容量、正负位移及0.5mm/px测试变体；F多轮累计位移恢复与后续索引另有联合测试。完整A/C路线、全部颜色/环位、机械臂和六套主机回归继续检查。另从本次上位机`protocol.py`的纯打包函数生成真实字节帧，送入当前STM32解码器核对D/E/F。

主机测试与ARM构建不代表实车通过。未连接视觉板或车辆，不能确认板上应用版本。上位机仍按800ms间隔重拍且没有运动ACK；若实际移动耗时更长，下一轮图像可能拍在移动途中。STM32按收到的顺序执行、不丢正常协议内指令，但不因此保证相机再次测量时车已停止，也不自行追加纠偏。像素标定、轴方向、实际停稳和叠放效果仍需实车核验。
