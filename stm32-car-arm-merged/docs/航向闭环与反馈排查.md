# 航向闭环与电机反馈排查

更新：2026-10-14。适用当前 `stm32-car-test`。本次仅修改、电脑测试和 ARM 编译，没有下载、连接车辆或修改驱动器配置。

## 已完成到什么程度

`runimu A/C` 沿用固定路线和道路距离，现改为转向及直行中的连续IMU调速，不再每500 mm停车。四轮编码器位置计算行程，接近终点减速；完成要求IMU稳定和四轮新零速反馈。当前参数、日志及4号到位位处理见 [连续转向与直行航向闭环](连续转向与直行航向闭环.md)。

这是连续航向PD闭环及轮端行程反馈，没有场地XY绝对定位。轮子完成行程不能证明车身没有打滑，陀螺仪也不能确认车辆到达哪个节点；最终仍输出 `physical_pose=unconfirmed`。电脑模拟不能证明实车比赛耗时。

旧 `run A/C` 仍采用脉冲标定转向；`test`、`tl/tr`、`nav/go` 保留原行为。`turn` 模式中的 `left90/right90/left180/right180` 已接入共用IMU闭环，详见 [定角闭环共用说明](定角闭环共用说明.md)。查表数据、道路几何、固定任务顺序和横移预补偿没有改变。扫码、机械作业、自动避障和中途续跑未纳入本次实现。

## 陀螺仪接口和待确认参数

操作者当前已开启 `src/car_config.h` 的 `CAR_IMU_UART_ENABLED=1`，提供的现场日志有持续的新角度。本轮保留此设置；实际接线和IMU精度尚未独立量测。

已准备的适配器沿用参考工程：USART2，PD5 TX、PD6 RX，115200 8N1。接收普通WIT角度帧 `55 53 ... checksum`，航向来自帧内Z轴角度。帧长、累加校验和有符号角度换算与项目现有 `wit_c_sdk.c` 一致。只被动接收，不调用旧 `imu_init()` 的自动扫描、定时器初始化或配置写入。

波特率、角度正负、误差范围、检查距离和时限集中在 `car_config.h`，修改后完整重编译。如引脚不同，修改 `vendor/stm32/imu/imu.c` 的 `Usart2Init()`；如串口号不同，还需更改对应初始化和中断入口，不能只改波特率。如协议不同，保留控制部分，替换字节适配，调用 `heading_sensor_publish()` 发布真实的新采样。

当前控制、轮询和停止阈值见 [连续闭环调参入口](连续转向与直行航向闭环.md)。速度模式轮询四轮位置、速度和状态，不等待位置模式到位位；下文关于四轮位置ACK和到位窗口的排查仍适用于旧 `run A/C`。

## 到场后的顺序

1. 确认模块、电平、接线、波特率与协议，开启匹配的接收适配并重新编译。该步骤不需要先让车辆运动。
2. 发送 `imu`，转动车身观察 `samples` 递增、`fresh=1`、`yaw_cdeg` 随车身变化，左转角度增加。静止时数值仍应持续更新采样序号。`yaw_cdeg` 单位0.01°，允许在±180°处跳变，航向跨界由控制器处理，单独左右180°命令保留所选方向。
3. 保留原 `turn` / `pulses 200` / `tl,tr` 小脉冲测试，核实 `CAR_TURN_CCW_DIR` 对应的真实旋转方向。传感器正负和电机方向是两个独立参数，都要验证。
4. 右上启停1摆车并朝扫码区，发送 `runimu A`；右下启停2摆车并朝扫码区，发送 `runimu C`。两侧初始方向分别是地图+Y和−Y；当前已修正地图转角与IMU左转角的方向关系。详见 [地图起点修正与后退行驶](地图起点修正与后退行驶.md)。不向模块发送清零指令，也不自动识别实际摆车位置。
5. 初次只观察少量动作，用 `!` 结束。先验证修正方向、角度收敛、四轮反馈、直行重复性，再进行完整路线。停止或故障后重新摆车，不从道路中途直接重发全程命令。

常用命令：

```text
imu
feedback
info
runimu A
!
```

普通命令末尾带换行。`feedback` 只显示当前一轮全程运行已收到的缓存，不主动查询、不使车辆运动。无需重复启动路线，故障发生时会自动打印逐轮反馈；故障后先保存输出，再切模式或重新启动，以免重置诊断。`imu` 和 `feedback` 也可在运行时查询，但调试串口输出会占用主循环时间，不应循环高速发送。

## 软件反馈排查结论（原位置模式）

本次确认并修改了以下问题或风险，但没有现场报文证明其中某一项就是此前4号未到位的根因：

1. 原CAN中断调用 `CAN_ClearITPendingBit(..., CAN_IT_FMP0)`，而本项目STM32库的合法清除列表不包含FMP0；实际释放接收FIFO由 `CAN_Receive()` 完成。现改为读取到FIFO为空，并检测/报告FIFO溢出。原错误调用在关闭完整参数断言时通常是无操作，不代表它必然造成4号故障。
2. 原 `can_SendCmd()` 忽略 `CAN_Transmit()` 无可用邮箱的返回值。现在识别这种情况，停止继续提交，保留发送失败标志；部分位置命令提交失败时不广播启动。不新增自动重试，不改变CAN速率或驱动器参数。
3. 原队列不记录接收时间，也不限制累计到位结果的年龄。现在记录时间，查询前已入队的回复不得满足新查询；超过ACK、查询或动作期限收到的回复不得放行。各轮到位结果也必须在有效期内。
4. 原动作时限检查先于接收队列处理。现在先消费已经收到且在期限内的反馈，再判断超时，避免及时到达的反馈仅因主循环稍晚处理而丢失；晚到的反馈仍不能放行。
5. 清下一动作的接收队列不再清除活动运行的丢帧标志。丢帧或发送失败必须先进入故障处理，不能被下一动作隐藏。
6. 补充逐轮诊断，避免把“驱动器报告未到位”和“没有收到有效状态回复”混成同一种说法。

旧位置模式的状态位仍采用厂家定义：0x3A回复中bit0使能、bit1到位、bit2堵转、bit3堵转保护。参见[厂家Emm V5说明书的状态标志及到位窗口说明](https://blog.csdn.net/zhangdatou666/article/details/132644047)。未改变这些位的意义，没有改成只等3个轮子，也没有用估时替代到位。

## 如何看4号的日志

`ack=15` 表示四个位置ACK已收到；`ready=7` 表示当前1、2、3号满足条件，4号未满足。仅凭这两个数字不能断定电机故障，必须结合以下字段：

| 字段 | 如何解读 |
|---|---|
| `addr=4 status_replies=0` | 这一轮尚未收到4号合法格式的0x3A回复；供电、通信、报文形状或驱动协议均可能，不能写成“电机没有转完” |
| `flags_valid=0` | 状态位没有有效观测；后面的数值不能作为使能/到位事实 |
| `action_status_replies=0` | 当前动作还没有完成该轮的有效查询；不能拿自检或上一动作的状态当作当前到位反馈 |
| `action_status_replies>0 flags_valid=1 arrived=0` | 当前动作确实收到状态，但最近状态未置到位位；再核对现场动作、位置误差和到位窗口 |
| `status_age_ms` | 距离最近0x3A回复的时间；`age_ms`则是距离任意合法回复的时间，不能拿新ACK刷新旧状态的年龄 |
| `command_dec=58` | 十进制58，即0x3A状态回复 |
| `command_dec=253 value_dec=2` | 0xFD位置命令ACK |
| `arrival_notices>0` | 收到0xFD/0x9F主动到位通知；诊断会记录，但不代替当前策略要求的位置ACK和主动状态查询 |
| `invalid>0` | 入队短回复的校验字节不匹配 |
| `rejected_shape>0` | 收到的帧在ID、帧型、包号或长度上不匹配当前允许的状态/诊断回复格式；没有保留完整原始总线抓包 |
| `can_rx_fault=1` | 检测到硬件接收FIFO溢出，不能信任这一轮反馈完整性 |
| `can_rx_fault=2` | CAN发送时没有可用邮箱，命令未完整提交；可与其他故障按位组合 |

驱动器控制应答配置可能只返回ACK、只返回到位或返回两者，需核对实物设置。旧位置模式仍要求位置ACK，连续模式要求速度ACK，故“队友可以跑完整圈”不能单独证明其程序也完成了相同的反馈检查。没有队友当前源码，尚无法比较这一点。

Emm短回复不带本程序的动作序号。接收时间检查能排除已排队的旧消息，不能辨认“上一动作的回复恰好在新请求后才从总线到达”。新鲜度与四轮顺序查询降低混用范围，但不构成硬件事务编号；现场仍需核对真实返回时序。

## 故障和验证边界

IMU样本过期/无效、UART接收错误、旋转方向与角度响应矛盾、修正不收敛、直行偏航超限、CAN丢帧/发送失败或四轮反馈不完整都会请求停车，不自动重试或续跑。请求停车不等于已测得车轮停稳；总线故障时也不能保证停车命令成功送达。

电脑验证脚本：

```powershell
& '.\tools\verify-heading.ps1' -Gcc 'C:\msys64\ucrt64\bin\gcc.exe'
```

它运行原有入口回归及新增测试，覆盖两种UART适配开关、校验/串口帧重同步、角度跨±180°、样本时效/时间溢出、4号已回复但未到位、旧/迟到回复、发送邮箱失败、CAN FIFO突发帧/溢出、方向不符、无法收敛、急停、偏航超限，以及带模型误差和直行偏航的A/C整圈模拟。模拟反馈不是车辆实测。

当前结果和源码哈希见[连续闭环验证](../evidence/chassis-history/连续航向闭环验证.json)；此前记录保留在[共用核心验证](../evidence/chassis-history/定角闭环共用验证.json)和[原验证记录](../evidence/chassis-history/航向闭环与反馈验证.json)。旧验证记录只对应各自版本，不代表当前源文件已经上车验收。IMU精度、安装方向、四轮驱动兼容性、真实停车距离、节点误差和整场耗时均待现场验证。
