# 串口屏接入（r32）

本次在r31上接入既有robot-status只读状态屏，不修改HMI界面、运动路线、抓放参数或视觉对准判据。屏幕不发车辆命令，显示发送不等待屏幕应答，掉线或发不出去不会取消车辆任务。

## 文件与接线

配套屏幕为480×272横屏TJC4827T143_011N_P20；工程中screen/robot-status.tft是既有serial-screen-ui导出文件的逐字节副本，1002304字节，SHA256为cd9b536a1402383a5edbe8375ab877ee70ceab51eeac1d0e0dc05f44873c6c0c。不是本轮重新编辑或重新编译的屏幕工程。原始HMI和TFT均未修改。

| 连接 | 设置 |
| --- | --- |
| MCU PC6 / USART6_TX → 屏幕RX | 9600，8N1，普通指令模式 |
| MCU GND → 屏幕GND | 共地，供电沿用已确认的屏幕电源接线 |
| 屏幕TX / MCU PC7 | 本版不需要连接；USART6接收及RXNE中断均未启用 |

USART3调试、USART1扫码、USART2 IMU、UART5视觉保持原通道。Keil原本编入但未调用的阻塞uart6_ckp.c替换为src/hmi_status.c，编译单元仍为70；旧文件保留。新模块独占USART6，不能再调用旧HMISends/HMISendb或将printf输出到屏幕串口。

MCU复位后应显示version=20261020-merge2-r32。若屏上尚未下载这份TFT，需要用户自行下载配套屏幕文件；本次没有对实屏或单片机执行下载。

## 显示内容

主界面显示四组任务码、阶段、主控计时；从runimu接受启动时开始计时，完成、故障或主动停止后冻结，下轮重新开始。taska=134123、taskb=314231对应134+123+314+231。任务是否有效及整轮结束后的清空跟随当前车辆状态，不由屏幕决定。

阶段为0待启动，1扫码，2第一批抓取，3第一批粗加工，4第一批暂存，5第二批抓取，6第二批粗加工，7第二批码垛，8返回，9完成，10故障。没有独立的“主动停止”阶段，主动停止回0；细节看调试串口日志。

机构页显示升降/平推指令目标、夹爪/云台指令角和已确认的载物台杯位。没有夹持传感器或舵机到位传感器，因此pick/place正确次数始终-1（屏幕--）；机构不忙也不冒充“全部已到位”，使能后空闲状态使用未知值。电压尚无可靠数据，保持未知。

感知页显示新鲜IMU角度、目标角度、最近有效视觉坐标的偏差和数据年龄。超过250ms的IMU角度显示未知，超过1000ms的视觉颜色隐藏；缺坐标的旧PICK仍按原控制规则接受，但不虚构屏幕坐标。D/E只有环中心、没有颜色，既有屏幕在color=0时隐藏dx/dy，因此环偏差仍以串口station correction日志为准。comm是四轮CAN反馈汇总，不是屏幕应答或屏幕在线证明。

旧底盘代码只给出1～4地址和运动符号，没有左前/右前/左后/右后标签；gcs-gold-medal-main/gcs-gold-medal-main/docs/hardware_reverse_analysis.md的轮位分析也记为无法确认。本版HMI_LF/RF/LR/RR_ADDRESS默认0，四轮8格显示--，没有把猜测的轮位当事实。确认物理位置后，只需在src/hmi_status.h填写对应1～4地址，不改底盘控制映射。专项测试中1/2/3/4的轮位定义仅为测试覆盖，不是实车标定。

## 串口调试命令

下面命令发到既有USART3调试串口，不是直接发到屏幕。运行中也可切换显示，不会触发车辆动作。

| 命令 | 作用 |
| --- | --- |
| screen / screen status | 显示发送状态；不宣称屏幕已收到 |
| screen main | 比赛页 |
| screen chassis | 底盘调试页 |
| screen arm | 机构调试页 |
| screen sensors | 感知调试页 |
| screen refresh | 请求完整状态重发 |

每条屏幕ASCII指令都带FF FF FF原始结束字节；先提交完整任务码，再提交有效标志，最后刷新。上电1秒后开始发送，常规最多每500ms组织一批变化字段，每5秒完整重发，以覆盖屏幕晚启动或重启。USART6 TXE中断逐字节发送；缓冲尚未发完时保留完整旧批次，下一轮再取最新状态，不交错半条命令。屏幕回包不进入车辆控制入口。
