## 2. 接线和串口格式

| 接口 | 接线 / 用途 | 通信设置 |
|---|---|---|
| 电脑调试 USART3 | MCU PB10 TX→USB串口RX，PB11 RX←USB串口TX，GND共地；3.3V逻辑 | 115200、8N1、无流控、文本发送 |
| 机构CAN | 四轮地址1～4，升降5，平推7 | 共用非阻塞CAN发送队列；按地址分流反馈 |
| 夹爪PWM | PA1，TIM2 | 当前逻辑张爪45°、合爪15° |
| 载物台PWM | PA2，TIM2 | 1/2/3号杯对应20/139/256° |
| 云台PWM | PA3，TIM2 | 普通逻辑角范围−94.5～265.5° |
| IMU USART2 | PD5 TX / PD6 RX，WT101 | STM32与模块230400；模块保持50 Hz输出 |
| 扫码 USART1 | PB6 TX / PB7 RX，XM1601，PC0低有效触发 | 默认9600；可切STM32端为115200 |
| 视觉 UART5 | PD2 RX←视觉TX，PC12 TX→视觉RX，共地 | 115200、8N1，AA55二进制帧 |
| 状态屏 USART6 | PC6 TX→屏幕RX，共地；只读状态显示 | 9600，界面操作见[串口屏接入](串口屏接入.md) |

关闭串口助手循环发送。普通命令以LF或CRLF结束；`!` 不需要换行。`s/z/S/Z` 停止命令需要换行，避免输入 `station` 时误触发停止。固件提示为英文ASCII，接收端可用ASCII或UTF-8。

命令区分大小写；节点使用大写A～I。平推、升降参数为整数毫米；机构角度允许一位小数。目标坐标是绝对值，`arm lift 130` 不是相对上升130mm。

## 3. 机构会话与真实姿态声明

### 3.1 建立会话

先确认底盘已停止、没有活动路线或人工导航动作，再逐条发送：

```text
arm on
arm status
```

等待 `[arm interlock acquired: chassis commands locked until parked arm off]`。此时 `[arm interlock] state=2`。

`arm on` 会发停车并查询四轮新状态/速度反馈，反馈有效并保持200ms后启用升降5和平推7。首次启用不会直接摆动三路舵机。当前轮速幅值和非零持续时间只记录，不以其判定停稳；日志中的“stop confirmation”不能证明车轮实际零速，操作者须检查实物。会话细节见第8节。

### 3.2 声明当前实际位置

格式：

```text
arm pose P Z Y C
arm platform pose DEG
```

| 参数 | 含义 / 允许范围 |
|---|---|
| P | 平推实际绝对位置，0～187mm；0收回，187为理论上限 |
| Z | 升降实际绝对高度，0～135mm；135最高 |
| Y | 云台当前逻辑角，−94.5～265.5° |
| C | 夹爪当前逻辑角，0～270° |
| DEG | 载物台当前角度，0～270° |

这两条是人工声明，不会自动寻找原点，也不清两轴编码器；**会直接输出云台/夹爪及平台对应PWM**。必须先核对实际姿态，不能用声明替代尚未完成的运动。

仅当实际位置确为平推0、升降135、云台0、夹爪45、平台1号20°时，使用：

```text
arm pose 0 135 0 45
arm platform pose 20
arm status
```

### 3.3 单轴检查及退出

在已经正确声明姿态、现场无干涉时，可从小步开始，例如平推0→1→0mm、升降135→130→135mm。每条指令单独发送，等 `[arm done: ...]` 并检查实物后再发下一条。具体命令见[速查表](串口命令速查.md)。

普通机构动作会查询5/7号轴反馈。升降/平推按新鲜实际位置和驱动器到位条件完成；没有夹持或舵机角度传感器。

退出手动机构会话时，先完成 `arm home` 并检查实际收拢，再 `arm off`。后者关闭三路PWM，夹爪可能失去保持力；5/7步进保持使能。`arm home` 保持夹爪状态，且不会自动把平台切回1号杯。

## 4. 三类操作流程

### 4.1 单块抓放与手动装车

- `arm pick` 要求平推0、升降135、云台0。按固定原料姿态开爪→转131°→平推55mm→降105mm→合爪15°，最后保持夹住。
- `arm place` 将手中物块放入当前杯位：升135→收平推0→转256°→伸35→降110→张爪45°。须已声明平台角度，不自动换杯。
- `arm cycle` 执行收拢→抓取→放平台，途中会开爪，不能当作保持现有夹持的搬运命令。
- `arm load1` 装一块到当前杯位，再切下一杯、回131°预备角；`arm load1 last` 末尾回0°。当前杯位须能由平台声明识别为1/2/3。
- `arm load3`（别名 `arm load 3`、`arm cycle3`、`@`）从1号杯开始装三块，最后收拢并回1号杯。它保留独立顺序配方，不自动等待视觉。
- 手动 `arm pick/place/cycle/load3` 的顺序配方与自动直接搬运不是同一条路径；不能把自动110mm起转规则套到所有手动动作。
- `arm pick red/green/blue` 只是同一固定抓取姿态的兼容别名，不执行颜色选择。

手动切换平台 `arm platform 1/2/3` 要求平台已声明，机构平推0、升降135、云台0。杯位角度20/139/256°；这是车载杯号，不是地面环位号。

### 4.2 自动两批整圈

1. 将车放在原启停区A/C起点，车头预先朝D/E/F一侧（地图−X）；不用向场内挪60mm。检查IMU新鲜度、CAN和机构现场状态。
2. 按第3节建立 `arm on` 会话，声明真实机构及平台姿态。需要机构已收拢、平台1号位。
3. 闲置时确认 `station auto on`。上电默认开启，运行中不允许更改。
4. 可提前输入完整任务，也可在首个B点等扫码；任务格式见第5节。
5. 选择实际起点发送 `runimu A` 或 `runimu C`，自动作业期间保留机构会话，不发送 `arm off`。

当前自动流程：

| 阶段 | 行为 |
|---|---|
| 发车至首次扫码位置 | 发车时自动初始化扫码一次，A左移/C右移并接收任务；保持手工摆好的−X，车尾扫码器朝+X。首弯入口前（路径进度880mm）已有任务则连续切向B→E；否则走足1030mm到原扫码位置，无码才停等；不在B再次初始化或原地转向 |
| 原料区F点，两批各一次 | 高位收回、云台131°后先发H对齐物料盘；DISC及全部修正位移完成后，再依次发三条C，收到对应PICK后装入杯1/2/3；第三块结束收拢并回杯1 |
| 粗加工D点，两批各一次 | 进站一次D对准2号基准，按任务环位放下，再按同序抓回原杯 |
| 暂存H点，第一批 | 一次E对准2号基准，按第一批映射放单层 |
| 暂存H点，第二批 | 跳过入站E，在各同色目标位发一次F识别已有物块，完成已收纠偏动作后叠放 |
| 完成两批及回程 | H→E→B直通，车头保持+Y；A沿原末段小弯回原终点；C在B→C前中段同步侧移60mm，末段只直行停车；整轮完成时清空任务，下一轮需新输入 |

起步仍放在原A/C，不向场内移动60mm，手工朝−X。逻辑路线沿用r76：横移1030mm至B′(2250,1200)，再沿−X行驶1050mm到E(1200,1200)；人工导航地图与离线路表不变。r77正常连续通过时切掉B′和E的尖角，实际经过各圆弧及切线出口，**不再经过这些顶点的精确坐标**。有码时B′弧出口约(2100,1200)，E弧出口约(1200,1050)，继续到原料区F；不是在E停车后才开始横移。

扫码初始化仍只在发车时一次，首个有效任务锁定，重复码不覆盖。首弯入口前无码就保持原直线去B′，到点后无码等待；若随后收到码，完成该直线后再连续通过B′→E→F。返程经过B不重初始化或接下一轮码。只跑底盘时不要求扫码，也启用连续过弯。

完整逻辑路程仍记13960mm，圆角的实际规划长度更短，二者不能混同。所有连续路径使用二维编码器＋IMU位置跟踪，不叠加分段横移的经验前移补偿；原左20mm/m、右8mm/m配置保留给分段执行器。模拟独立积分实际轮速，报告绝对累计误差；80mm历史模型预算及分段模式单独登记的经验偏置均不是实车精度标准。工位相对视觉修正和不可观测打滑仍会影响真实场地位置。

原料校正的 `H` 是视觉命令字，与地图上的暂存区H节点不同。MaixCAM当前 `task_plate` 识别物料盘下弧最低点，按 `PLATE_TARGET_X/Y` 计算偏差；当前仓库目标为(311,267)像素，容差各6像素。这是视觉配置，不代表实车毫米精度。

STM32复用现有FIFO执行 `MOVE/MOVEY/MOVEXY`：当前正dx后退、正dy左移，假定1px=1mm，均按车身坐标执行；原料机位的方向和比例需要实车核验。视觉默认单次修正后立即回 `DISC`，终包坐标只记录，不生成第二次补偿；必须等已收位移、原编码器/IMU完成判据及新鲜轮反馈交接完成后才请求C。三块之间不重复H，不自动反向撤销原料修正。

日志依次出现 `[station raw align] ... request H once` → 修正日志（可能没有位移）→ `[station raw aligned] ... start C/PICK`。若返回 `NONE,H` 或缺少终包，沿用原工位等待策略，告警并保留任务，不跳过校正、不自动重发H；急停及真实驱动器故障沿用既有处理。当前 `vision debug` 仍只支持D/E/F。

地面前1、中2、后3，相邻150mm，1↔3直接300mm索引。第二次暂存保留视觉纠偏后的车位，不自动反向撤销纠偏；后续相对索引及离站以该位置继续，逻辑回2号不代表回到原导航停车坐标。

道路行驶中 `obstacle` 会停车并按记录退回上一已记录节点后停等；本工程没有自动检测输入或障碍重规划。工位作业、环位移车、离站重叠期间的 `obstacle` 是故障停车，不自动倒退。

PC9高电平按下消抖后等效启动 `runimu C`，仍检查同一准备条件；长按只触发一次，上电已按住不会发车。见[PC9启动与扫码初始化](PC9启动与扫码初始化.md)。

### 4.3 只跑底盘、单段测试和人工导航

只跑整圈底盘：先按第3节收拢并退出机构会话，闲置时发送 `station auto off`，再 `runimu A/C`。恢复自动作业需闲置时 `station auto on`，重新按真实状态建立机构会话及准备姿态。

单段平移：`test` → `dist N`（50～2000mm）→ `rpm N`（20～250RPM）→ `f/b/l/r` 中的一条。左右横移还受1200mm分界的250/200档位限制，较低请求仍保留。前后是位置模式，估时不代表真实到达；横移采用IMU与编码器闭环。

定角转向：`turn` → 可选 `rpm N` → `left90/right90/left180/right180` 中的一条。需要新鲜IMU。

人工导航：`nav` 后按实物声明 `pose A` 和 `heading 0`，再 `go H`。完整确认、道路阻断和进度指令见[速查表](串口命令速查.md)。`rpm` 根据当前模式设置速度，不是修改runimu的全局配置；人工导航另允许 `rpm 0` 使用道路表速度。

## 5. 任务码与生命周期

完整格式：`task G1+G2+G3+G4`，每组3位。也接受12位连写，或省略 `task ` 前缀。

| 组 | 含义 |
|---|---|
| G1 | 第一批杯1/2/3对应的颜色顺序 |
| G2 | 第一批这三块对应的粗加工目标环号 |
| G3 | 第二批杯1/2/3对应的颜色顺序 |
| G4 | 第二批这三块对应的粗加工目标环号 |

颜色1红、2黄、3蓝、4绿；每批颜色不重复，两批颜色集合相同。G2/G4各为123的排列，非法输入不会局部覆盖现有任务。

例如 `task 134+123+314+231`：第一批颜色1/3/4放环1/2/3；第二批颜色3/1/4在粗加工放环2/3/1。第二批暂存按颜色回查第一批的暂存位置叠放，而不是直接照搬G4。

`task 123` 仅供第一批调试，第二批颜色为空。使用 `station` 查看两批解析结果及 `task_ready`。

任务对一整轮有效，覆盖两批及返程；首个B点后不重复要求扫码。整轮完成、全局停止或故障取消本轮时清空；`task_ready=0`、两批颜色/环位归零表示失效。闲置时扫码只显示结果，不缓存成下一轮任务。自动运行中仅首次横移扫码窗口及首个B点等待阶段允许接收本轮任务。

## 7. 视觉链路与独立纠偏

### 7.1 电脑调试命令和UART5协议的区别

电脑调试口使用 `vision ...` 文本命令。视觉板使用UART5，帧格式为：

```text
AA 55 LEN payload CRC8 0D
```

LEN为payload长度，最大48字节。CRC8多项式0x07、初值0x00，覆盖LEN及payload。UART5只有一个协议接收所有者，不与旧9字节协议共用。

| 方向 / payload | 行为 |
|---|---|
| MCU→视觉 `C,N` | 请求颜色N到固定原料取料口，N为1～4 |
| 视觉→MCU `PICK,N` / `PICK,N,x,y` | 当前等待颜色确认；x/y用于诊断，不动态改变机械臂坐标 |
| MCU→视觉 `D` / `E` / `F,N` | 粗加工对准 / 暂存对准 / 同色叠放识别 |
| 视觉→MCU `MOVE,dx` | 有符号前后位移像素，正后退、负前进 |
| 视觉→MCU `MOVEY,dy` | 有符号横移像素，正左、负右 |
| 视觉→MCU `MOVEXY,dx,dy` | 同一元素双轴并行；兼容 `movexy dx dy` |
| 视觉→MCU `DISC,cx,cy,dx,ok` | D/E成功终包要求ok=1；坐标与残差仅记录，不另加一致性/幅值门槛 |
| 视觉→MCU `STACK,x,y,dx,ok` | F成功终包要求ok=1；兼容旧 `STACK,x,y`，本身不生成移车 |
| MCU→视觉 `R` | 仅显式 `vision range` 诊断会发送，自动D/E/F不发R |

当前按完整有符号像素幅值换算毫米，比例暂假定1px=1mm，不重复乘视觉端增益。离散MOVE/MOVEY/MOVEXY按FIFO执行，终包到来后排空已收队列和当前动作，再继续抓放或结束调试。0位移不会覆盖此前已排队动作。仅在对应视觉等待会话接收移车payload；直接给电脑调试口发送这些payload不是运动命令。

超时、BUSY、目标不可用及非法/未成功终包主要告警并保留当前请求；不会伪造视觉成功、自动跳过物块或按旧稿“重发两次后停车”。无请求序号，跨任务迟到回包无法完全区分，需核对视觉板任务生命周期。详见[视觉上位机指令执行](视觉上位机指令执行.md)及[MOVEXY双轴并行纠偏](MOVEXY双轴并行纠偏.md)。

### 7.2 独立视觉纠偏

人工把车放在对应区域，按第3节声明机构/平台，保证平推0、升降135、IMU新鲜，然后选择：

| 指令 | 任务 |
|---|---|
| `vision debug` / `vision debug D` | 粗加工对准 |
| `vision debug E` | 暂存圆盘对准 |
| `vision debug F N` | 颜色N的叠放识别，N为1～4 |
| `vision debug status` | 查看是否运行及链路状态 |
| `vision debug off` | 运行中按全局停止取消，未运行时仅提示inactive |

调试将云台转到126.5°观察角，执行上位机移车指令；不要求二维码/任务，不夹取、不放料、不索引、不自动离站。成功后保持车位和观察角，预存任务及自动开关保留；中途off按全局停止规则使本轮任务和姿态失效。再次跑整圈前应收拢回正、恢复平台1号位，并将车放回实际起点。

`vision ping` 只发D，不启动纠偏；`vision pick N` 只做请求，不自动夹取。自动路线/工位占用视觉时拒绝这些手动请求，查询仍可用。完整命令见[速查表](串口命令速查.md)。

## 8. 互锁、完成依据和故障恢复

### 8.1 等待告警与硬故障

| 范围 | 当前行为 |
|---|---|
| 四轮互锁 | 下发停车，查询四轮新状态/速度；样本须在500ms内，有效反馈保持200ms才获取会话。2秒未获取及后续反馈过期是告警并继续查询 |
| 四轮速度 | 幅值、持续非零只记录；旧±5/±15RPM及300/3000ms停机规则不适用 |
| 四轮驱动 / 总线 | 四轮失能、堵转、保护或CAN发送/总线硬故障仍停止并锁定 |
| 5/7号机构状态 | 失能、堵转、保护记录 `[arm axis warning]`，不据此直接停止；不自动清保护、重新使能或虚构完成 |
| 5/7号机构完成 | 两轴新鲜状态、速度样本、实际位置及到位标志满足判据；速度幅值不作为完成门槛，ACK缺失可告警后由实际位置/到位确认 |
| 机构超时 / 接收溢出 | 查询/动作超时告警并继续等反馈；接收溢出恢复接收，不把时间到了当作完成 |
| 机构硬错误 | 位置命令被拒绝、配方超行程、CAN发送/总线硬故障仍失败停止 |
| 底盘运行 | IMU、编码器、驱动器和CAN各有自己的检查；不能把“机构超时只告警”解释为取消所有底盘保护 |
| 视觉等待 | 延迟/无目标告警并保留请求；格式、CRC和当前等待状态仍约束接收；队列满会告警，不能当作已执行 |

因此，日志出现warning不等于已取消任务，也不等于已经安全到位。保留从启动到停住的完整日志，结合 `info/feedback/imu/arm status/station/vision status` 确认停在哪个阶段。

### 8.2 状态与完成反馈

`[arm interlock] state=`：0无会话，1等四轮反馈，2机构独占，3故障锁定。

`[arm] state=`：0空闲，1轴预检，2提交命令，3运动，4停止/故障，5云台诊断。`referenced` 表示人工姿态基准是否有效，不是传感器测得的绝对姿态。

`[arm step complete: ...]` 只是一步；整套等待 `[arm done: ...]`。该完成只说明轴反馈及PWM指令时序满足条件，没有夹持、舵机实际角度或物块到位传感器。`[accepted]` 和位置模式估时都不代表真实完成。

### 8.3 停止及恢复

- `!` 或带换行的 `s/z/S/Z`：全系统停止，取消路线、工位和视觉待执行动作，本轮任务清空，不自动恢复。
- `arm stop`：手动会话仅停机构、继续锁住底盘；启用自动工位的路线/工位中取消整个作业并停车。机构基准失效。
- 停止保持最后舵机PWM和步进使能，不等于实体断电；舵机仍可能继续趋向最后目标。

恢复顺序：

1. 保存完整日志，检查真实车体/机构、供电和CAN状态。
2. 全局停止或互锁故障后，显式 `arm on` 重新获取四轮互锁；手动仅停机构时先用 `arm status` 确认会话是否仍有效。
3. 按真实位置重新 `arm pose ...`，并重新核对/声明平台角度；不能照抄停止前的账面目标。
4. 先验证小步，再恢复抓放；重新跑整圈需回到实际起点，并输入本轮任务或在首个B点重新扫码。

故障提示与查询方法见[速查表](串口命令速查.md)。

## 9. 云台PWM全行程诊断

要求机构互锁已建立；诊断不依赖5/7反馈，保持夹爪和平台PWM。

1. `arm yawtest init N`：N为已确认的起始脉宽500～2500μs，立即输出。
2. `arm yawtest N`：N为0～360测试刻度，8秒插值，不是普通逻辑角。

| 测试刻度 | PWM | 对应普通云台逻辑角 |
|---:|---:|---:|
| 0 | 2500μs | −94.5° |
| 94.5 | 1975μs | 0° |
| 360 | 500μs | 265.5° |

`arm yawtest 0` 不是回初始0°；全行程扫描可能大范围转动。完成只表示PWM插值结束，位置基准仍失效，恢复普通动作前须按实物重新声明。普通取放使用 `arm yaw` 和现有配方。

## 互锁和停止

`arm on`先要求底盘没有活动路线、待确认位置动作或导航流程，再下发四轮停车，轮询四轮的新使能/故障状态及速度反馈，连续保持200ms后启用5/7号机构电机。2秒获取期限改为告警，单项反馈仍要求500ms内的实际样本；缺少任一轮时继续轮询等待，不取消任务。此后每10ms查询一项轮状态/速度；手动与自动轮速幅值及持续时间均只记录，不再使用15RPM/3000ms停机条件。接收溢出丢弃不完整数据后继续轮询。驱动器禁用/堵转/保护、CAN发送失败或bus-off仍停止并要求检查。

手动机构会话期间，`go`、模式切换、平移和转向等底盘命令均拒绝；自动 `runimu` 仅在机构已声明、收拢且平台为1号位时允许启动，行驶和工位独占地使用四轮CAN反馈。`info`、`imu`、`feedback`、扫码查询/配置及按钮更新继续运行。机械动作每步检查5/7号的新状态、速度样本和编码器基线，速度幅值只记录；发出指令后以新鲜实际位置、驱动器到位及有符号编码器位移确认完成，ACK迟到仅告警；不以延时或一份旧到位标志推进。机构位置命令不使用广播同步，CAN回包按1～4和5/7分流。

`!`无需换行，提出底盘及机构停止请求；`s/z/S/Z`现在需要换行，避免 `station` 命令首字母触发停止；`!` 仍无需换行。`arm stop`在自动行驶/工位期间取消整个作业并停车；手动会话中仅停止机构。停止时保留最后PWM和步进使能，取消插值和序列，位置基准失效。舵机仍可能走向最后目标；软件命令不能代替实体断电。

全系统急停或底盘监测故障后，`arm status`显示互锁state=3。检查现场，显式 `arm on`重新验证四轮，随后按真实姿态重新 `arm pose`；载物台曾参与动作则重报 `arm platform pose`。不得根据旧账面位置盲目重跑。退出需要已完成的收拢姿态，`arm home`完成并检查后才可 `arm off`，再进入底盘。

## 命令

所有文本命令加换行；平推/升降用整数毫米，角度可带一位小数。保留 `!` 即时停止。

| 命令 | 作用和前置条件 |
|---|---|
| `arm on` | 申请独占，等待四轮反馈停稳；三路PWM仍关闭 |
| `arm status` / `arm` | 查看会话、位置基准、状态、步骤、命令坐标、PWM与互锁状态 |
| `arm pose P Z Y C` | 声明实际平推、升降、云台、夹爪位置；不移动两轴或清编码器，但会直接输出Y/C对应PWM |
| `arm slide N` | 平推到0～187mm；0为收回，187为继承的理论上限，未实测全行程 |
| `arm lift N` | 升降到0～135mm；135为最高处 |
| `arm yaw N` | 云台到−94.5～265.5度；超范围拒绝，不隐式取模跨端点 |
| `arm move P Z Y` | 同一步提交两轴及云台目标；一般调试优先单轴 |
| `arm open` / `claw open` | 开爪45度 |
| `arm close` / `claw close` | 合爪15度 |
| `claw angle N` | 夹爪角度0～270度，沿用1度安装偏移 |
| `arm pick` | 从0/135/0姿态五步夹取：开爪→云台131→高位伸55→降105→合爪15°；结束保持夹住 |
| `arm place` | 保持夹持，升135→收0→云台256→伸35→降110→开爪45°；要求已声明载物台角度 |
| `arm cycle` | 回收拢位→夹取→放载物台；过程会开爪，手里已有物块时用单独 `arm place` |
| `arm home` | 先升135→收0→云台0；保持夹爪状态，不自动松爪 |
| `arm platform pose DEG` | 声明载物台当前实际角度0～270；立即写PA2 PWM，不自动寻找原点 |
| `arm platform 1/2/3` | 切换20/139/256度档位；必须已声明平台角度且机构在0/135/0收拢位 |
| `arm stop` | 停止机构，保持PWM与步进使能，位置基准失效 |
| `arm off` | 收拢后退出独占并关闭全部舵机PWM；5/7保留使能；可能失去夹爪保持力 |

`arm pick red/green/blue`保留为同一个夹取姿态的兼容别名，不会选择不同物块。平台档位来自随包 `PWM.c`，不是本轮新测量。`arm place`只往当前平台位置放，不自动轮换档位。

首次只在实际处于收回0、最高135、云台0、夹爪45时使用：

```text
arm on
arm status
arm pose 0 135 0 45
arm slide 1
arm slide 0
arm lift 130
arm lift 135
```

逐条等待 `arm done`、观察实物后再发下一条。确认小步方向和反馈后，才能试 `arm pick`。云台0/131/256度输出约1975/1247/553us，夹爪开45°/合15°约826/604us。重新声明云台0的PWM1975us与旧独立工程的1586us不同，不混用标尺。

放平台前，只有平台实际在20度初始档时才声明 `arm platform pose 20`，然后 `arm place`。机构恢复 `arm home`后可旋转平台，再进行下一次操作。所有步骤需现场确认无干涉，`arm done`只证明两轴反馈条件和PWM插值完成，没有舵机位置或夹持传感器。

## 保留的云台全行程诊断

`arm yawtest init 实际脉宽`（500～2500us）直接声明并输出云台PWM；`arm yawtest 0..360`用8秒插值扫描，其中0→2500us、360→500us。测试刻度94.5约对应当前云台初始0度/1975us。该功能保持夹爪和平台PWM，不依赖5/7反馈，仍要求底盘四轮互锁和会话有效。诊断完成不恢复两轴位置基准。不要把 `arm yawtest 0` 当作云台初始位。

## 怎么读完成反馈

| 输出 | 应如何处理 |
|---|---|
| `[accepted]` | 命令已接受，不等于运动完成 |
| `DONE_BY_IMU` | 闭环转向的软件完成判据通过，检查车身真实朝向 |
| `DONE_BY_IMU_ENCODER` | 闭环横移的软件完成判据通过，检查地面真实位置 |
| `estimate elapsed` / `NOT arrival` | 只是位置模式估时，不能认定车已到位 |
| `[arm step complete: ...]` | 一步结束，序列可能继续，等待整套 `arm done` |
| `[arm done: ...]` | 两轴反馈条件和PWM插值完成，检查实物、夹持和间隙后再发下一条 |
| `[arm yawtest done: ...]` | 仅云台PWM插值结束，未检查5/7或真实舵机角度 |

`arm status`里有两种state，别混在一起：

| 所在行 | 数值含义 |
|---|---|
| `[arm interlock] state=` | 0无会话；1等四轮停稳；2机构独占有效；3故障锁定 |
| `[arm] state=` | 0空闲；1等两轴新反馈；2提交位置命令；3执行中；4停止/故障；5云台诊断 |
| `[arm] referenced=` | 1表示已声明位置且基准仍有效；0表示需要重新确认真实姿态 |
| `[platform] referenced=` | 平台角度是否已声明；不是传感器测得的位置 |

## 常见拒绝与故障

| 提示/现象 | 原因与处理 |
|---|---|
| 串口无回复 | 核对PB10/PB11交叉接线、共地、115200、换行及芯片复位运行；不要只看发送回显 |
| `arm session owns motion` | 底盘被机构会话锁住；机构 `arm home`完成并检查后 `arm off`，再跑底盘 |
| `chassis active` | 底盘路线/位置动作/导航未结束；先停住并检查，再 `arm on` |
| `four-wheel stop confirmation timeout` | 四轮状态/速度不齐、未停稳或反馈不符；检查1～4地址、CAN供电/接线和实际转速，不连续重试绕过 |
| `four-wheel feedback stale` / `wheel moving/disabled/stalled` | 四轮反馈过期、超过5RPM、失能或堵转，机构已停止并保留锁；检查后 `arm on`重新验证 |
| `wheel low-speed feedback persisted` | 会话内±5RPM非零读数持续300ms；机构停止，检查底盘实际是否微动 |
| `arm on and four-wheel stop confirmation required` | 未建立机构独占或已故障锁定；先检查，再 `arm on`并等待成功 |
| `actual pose unknown` | 上电尚未声明姿态，或停止/诊断已使基准失效；按真实姿态重新 `arm pose ...` |
| `busy; use ! or arm stop` | 上一动作未结束；等完成，异常时停止，不连发运动命令 |
| `feedback timeout` / `position ACK timeout` | 5/7号回复缺失；检查地址、电源、CAN和驱动协议 |
| `axis disabled/stalled/protected` | 机构电机失能、堵转或保护；先排查机构和供电，停止后重建位置基准 |
| `action timeout` | 位移/方向/到位等条件未全部满足；保存日志，检查编码器极性、脉冲比例、行程和真实动作 |
| `declare actual platform angle` | 放平台前未声明平台当前位置；只有实际角度明确时发送 `arm platform pose DEG` |
| `platform requires declared angle and arm home pose` | 先声明平台角度，再让机构 `arm home`完成，随后切档 |
| `park with arm home` | 机构未确认收拢，不能释放底盘；`arm home`完成并检查后再 `arm off` |

故障后的恢复顺序：保存日志→检查真实机构/车体状态→显式重新申请机构独占（全系统急停/四轮故障时）→重新声明实际机构和平台姿态→先小步验证。不得仅靠重写账本把未到位“改成到位”。软件停止保留最后PWM，机构仍可能继续趋向最后舵机目标；需要切断动力时由现场操作者使用实体开关。

## 云台诊断刻度

纯云台诊断：`arm yawtest init 实际微秒值`（500～2500），再 `arm yawtest N`（0～360测试刻度，8秒插值）。它要求底盘互锁已建立，保留夹爪和平台PWM，不要求5/7在线；测试后机构位置基准失效。

| 测试命令 | 目标PWM | 对应当前云台坐标 |
|---|---:|---:|
| `arm yawtest 0` | 2500us | −94.5°端点 |
| `arm yawtest 94.5` | 1975us | 当前初始0° |
| `arm yawtest 360` | 500us | 265.5°端点 |

刻度不是实测角度。两端之间是大范围扫动，不把 `yawtest 0`当回初始；普通取放用 `arm yaw`及已标定的姿态。

### r13短时速度读数
