# 粗加工环位作业与视觉对准（20261019-merge2-r11）

r10的环间索引来源仍是 `codex/merged2-station-rings` 固定提交 `7fed0f62821a3c2680dbd1c3ce16e88f9009d5b5`。r11只补当前粗加工流程及底盘工位接口，未导入远程底盘，也未改原料、暂存、任务码生命周期或原机械参数。

## 本次动作顺序

以到D完成工位转向后的车头为准：前1、中2、后3。首先在升降135mm、平推0mm时转云台到125°，视觉确认中间2号基准。向前索引150mm到1附近，视觉精调并停稳后，回云台0°选择杯位，从平台取物，再以55mm / 105mm / 125°放下。收臂后依次向后到2、3，均先视觉对准再取物放下。

三块全部放完，再回到1，按1→2→3逐环视觉对准、抓回对应原杯。最后回到2号环并视觉确认，升降135、平推0、云台0、平台1号位，交还原路线去H。1与3间仍拆为两段150mm，路线节点和道路里程不被工位移动覆盖。

G2/G4仍表示各杯位物块的目标环号，必须各是1/2/3的排列。访问顺序固定1/2/3；按任务码反查对应杯位，抓回也放回该原杯。例：G2=312，1号环使用第2杯，2号环使用第3杯，3号环使用第1杯。不能把访问顺序变化当成忽略任务码。

## 与实际视觉代码对接

核对来源：[vision-maixcam/maixcam_app_v2](https://github.com/linbing-wolf/gcs-test/tree/16949b0a6fa4af86323a55e0659c8d74779f5d4c/vision-maixcam/maixcam_app_v2)，固定提交 `16949b0a6fa4af86323a55e0659c8d74779f5d4c`。以 `tasks.py` 的实际 `pack_move` / `pack_disc` 行为为准；该目录部分README仍保留旧版短DISC格式。

串口沿用UART5 115200，帧为 `AA 55 LEN payload CRC8 0D`，CRC覆盖LEN及payload。

| 方向 | payload | 作用 |
|---|---|---|
| MCU→CAM | `R` | 中断旧任务，等待 `READY`，握手围栏 |
| MCU→CAM | `D` | 粗加工当前可见圆心检测 |
| CAM→MCU | `MOVE,dx` | 水平像素偏差；正号按配置前进，负号后退 |
| CAM→MCU | `DISC,x,y,dx,1` | 640×480口径，`dx=x-320`，绝对偏差≤5px才可接受 |
| CAM→MCU | `NONE,D` / `ERR,...` | 拒绝当前动作并停车 |

收到MOVE后先发R并等READY，确保相机不再继续旧300ms循环；然后车辆只移动3mm，使用当前编码器/IMU闭环停车、重新取得四轮严格零速互锁，再以R/READY→D获取新测量。不把像素当毫米，也不缓存运动期间的MOVE/DISC。每环须3次独立DISC确认后才允许抓放。

握手/取消等待上限2秒，单次D等待25秒（大于视觉端20秒），每环总对准上限60秒，累计修正路程上限75mm。旧短格式DISC、ok=0、坐标不一致、超范围MOVE、CRC错误或失联均不能放行。CRC错误等待至超时；明确失败立即停止。

现有视觉D回复不含环号，只识别当前视野圆心。软件以起始2号环及150mm索引维护1/2/3位置；它不能从DISC证明看到的是数字1/2/3。初始必须在2号环附近，相机ROI须能稳定锁定当前目标而非相邻环。这一边界不能由电脑测试代替现场确认。

## 本次参数与仍保留的保护

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `STN_ROUGH_PLACE_READY` | 1 | 操作者已指定粗加工姿态 |
| `STN_ROUGH_PLATFORM_TAKE_READY` | 1 | 粗加工专用，取料复用ARM_PLACE_* |
| `STN_ROUGH_SLIDE_MM` / `LIFT_MM` / `YAW_DEG` | 55 / 105 / 125 | 粗加工抓放 |
| 平台取料 `ARM_PLACE_*` | 35 / 110 / 256 | 沿用当前车载放置几何 |
| `STN_ROUGH_INDEX_MM` / `SIGN` / `RPM` | 150 / -1 / 60 | 前1、中2、后3，段间移动 |
| `STN_ROUGH_ALIGN_STEP_MM` / `MOVE_SIGN` | 3 / 1 | 有界视觉微调；MOVE正号向前 |
| `STN_STORAGE_PLACE_READY` / `STN_PLATFORM_TAKE_READY` | 0 / 0 | 暂存及其旧取料表未标定，仍拒绝 |

夹爪闭15°、开45°；两轴300RPM、夹爪500ms、云台/平台2000ms沿用当前配置。以上是操作者指定值和软件策略，不是本次实车验证结果。首次必须确认MOVE正负与实际画面变化方向、画面中心是否对应夹爪55/105/125落点、杯中可靠取出及机械间隙。

机构移动互锁仍要求四轮全部健康、新鲜且严格零速。仅工位子移动允许在平推0、升降135、云台125°观察位移动；普通道路仍要求云台0°收拢。1RPM反馈仍会中止机构。视觉缺失、未对准、急停、`arm stop`、`obstacle`、IMU/CAN/轮反馈异常都取消整轮并使任务码失效，不自动重试或反向退回旧道路。

## 现场查看

每条命令单独发送：`station`、`vision status`、`arm status`。`vision status` 的rough state：0闲置、1等待、2结果就绪、3超时、4故障；phase：1等待READY、2等待MOVE/DISC、3等待取消旧任务的READY。正常日志依次出现 `[rough align] ring=2 start`、可选 `[rough correction] ...`、`[rough aligned] ring=2 DISC confirmed`，随后才到1号环并开始取放。

故障后先检查实物，重新 `arm on` 获取互锁，按真实机构位置声明 `arm pose ...` 和平台角度。不要在D直接重发整圈runimu；整圈需摆回原启停区并输入新任务。源码改变后重新编译；本次不执行烧录或车辆动作。
