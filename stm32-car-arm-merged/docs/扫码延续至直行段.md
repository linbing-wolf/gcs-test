# r99 扫码延续至直行段

首次发车初始化扫码器后，接码窗口覆盖发车横移、B→E直行、E→F以及首次F到站。B点未扫到时继续按原路线行驶，连续路径不再因缺码截短圆角、回到B停车。地图、名义路段长度、速度与原有圆角几何不变。

第一条完整合法任务码沿用原格式校验并锁定两批任务；收到重复码或其他合法码也不会覆盖。扫码配置READY/FAULT与文本接收仍独立：配置ACK缺失时，原CR/CRLF文本解析继续工作，不靠配置超时生成任务。

## 到F仍没有任务码

原料取料颜色需要任务码，因此首次F到位后若仍无码，就保持停车并继续接码，打印：

```text
[scan station] first F reached; waiting for task before raw work; scanner remains active
```

此时没有编排取料动作，也不会因为缺码进入 `station action refused`。收到扫码或手输 `task 134+123+314+231` 后，使用已有四轮互锁和原料工位流程继续。车在途中缺码时只行驶、扫码；收到任务后才允许原有进站机械臂准备。已有预置任务时仍可提前准备，不增加等待。

发车横移已扫到、直行中扫到、E→F扫到、F停车后才扫到均支持。B→E和E→F段仍使用原IMU/编码器路线；缺码不会触发额外转向或返回B。

## 生命周期和保持项

- 每次首次发车只初始化一次，波特率保持当前值；发车时丢弃旧半包。
- 首码跨两批保留，返程B不再初始化、重新接任务或覆盖任务。
- `!`取消流程并清任务；停车取消后、整轮结束后和闲置时的晚到码不会重新生成任务。
- 无新增自动故障停机、自动重试、清CAN队列或占位任务。扫码器串口配置命令、CR/CRLF和二进制ACK隔离保持。
- 机械臂、视觉、地图、运动配置、r98末端平滑控制及r97 CAN自动恢复保持。

## 验证

旧源码在“缺码不得于B进入扫码停站”的新断言上失败。`tools/verify-scan-straight.ps1`覆盖普通分段和连续圆角，各24个首码时机场景：A/C×6种输入时机×9600/115200两种波特率。另覆盖无配置ACK、完整合法码/半包/无效码/重复码、F手输任务、直行中急停，以及连续模式的A/C两批完整路线。

两模式分别1044872、1270962条断言通过。两条“直行才收到任务”的整轮模型均完成8项、13760mm，并验证一次初始化、两批任务不覆盖及结束后任务过期。原有预置任务A/C完整路线、108个过弯局部模型、r98停车专项和当前无自动停机策略测试也通过。

项目要求的heading/arm两套旧脚本仍分别失败在第602/159行自动故障停机断言，与操作者明确保留的现行策略不兼容；不宣称全部历史回归通过。旧B点停等测试描述已不代表当前扫码行为，本轮使用新的行驶接码专项覆盖这一契约。

固件版本 `20261026-merge2-r99`。完整Keil构建、AXF/HEX一致性、源码哈希和具体报告见 `evidence/current-validation.json`。没有烧录或实车测试，模型不保证移动中二维码的实际可见性、解码率或扫码器硬件状态。
