# 双超声波底盘避障测试

本工程复用比赛的 `runimu`：沿同一比赛路网，按 `B → F → D → H → F → D → H → 起点` 到点，使用 IMU 和四轮 CAN 反馈闭环。E 等途经点仍由路网决定；道路封闭后，可以更换途经点，作业点顺序不变。保留 B 点车尾朝二维码板和 F/D/H 的到站朝向。只运行底盘，不启用扫码、视觉、屏幕、舵机或机械臂作业。

测试版轮速上限 60 rpm，暂时关闭弯道连走和站内对位小动作，以便把回波和当前路段对应起来。前进看车头探头，左移看左侧探头。首次走某条道路时，如果原朝向会导致倒车或右移，先转 90°；已经通过的路允许倒车或右移，减少不必要的转向。倒车、右移、原地转向及退回时，没有对应方向的超声波保护。

| 设备 | 接口 | 接线 |
|---|---|---|
| 车头超声波 | U5 | 1：5V1→VCC；2：PC11→Trig；3：PC10←Echo；4：GND |
| 左侧超声波 | U4 | 1：5V1→VCC；2：PB11→Trig；3：PB10←Echo；4：GND |
| 无线调试器 | U6 | 1：3.3V；2：GND；5：PB0→模块 RX；6：PB1←模块 TX；3、4 不用 |

U4 的 PB10/PB11 与旧 USART3 有线调试口共用，测试时拔掉旧串口线。无线端设 `115200 8N1`，普通命令加回车或换行，`!` 不用换行。四轮电机地址 1–4，IMU 沿用 PD6 接收。

| 起点 | 放车朝向 | 启动方式 |
|---|---|---|
| C | 车头朝 B，由车头探头看 C–B | 短按 PC9 后松开，或发 `runimu C` |
| A | 车头朝场地图左侧（−X），左探头朝 B | 长按 PC9 后松开，或发 `runimu A` |

## 场地测试

1. 烧录本工程生成的 `ultrasonic_chassis.hex`，复位后发 `imu` 确认 `fresh=1`。发 `loop`，分别在车头和左侧放置、移开圆柱，核对 `FRONT`、`LEFT` 是否对应，随后发 `quiet` 关闭连续打印。
2. C 起点先空场跑一遍。发 `feedback` 查看四轮反馈；路线启动后会先等四轮位置等反馈。CAN 仍不通时，先排查通信，不能用这次测试判断避障成败。
3. 把车放回原起点，将圆柱放在 C–B 的行驶线上，建议先让圆柱表面距车头探头约 400–450 mm，观察起步前或驶近时能否拦住；再将圆柱移远一些，测试运动中发现障碍、停车和退回。切换到 A 按同样方式检验左侧探头。空场跑通不能替代两组带障碍测试。
4. 观察 `[obstacle confirmed]` 是否给出正确道路和探头，随后应有 `[obstacle stopping]`。若已经驶出，应有 `[obstacle returning]`；能够改道时会输出 `[obstacle detour]`，否则 `[obstacle return stopped]` 并等待。需要人工中止时发 `!`；重跑前把车摆回所选启停区。`status` 可随时查看两路距离、当前监听方向和封路状态。

当前只判断车辆正在准备进入或正在行驶的路段。两次符合条件的有效回波都在 550 mm 内且未明显越过当前直线段终点，才封闭该道路的双向通行。超时为 `UNKNOWN`，不证明路能走；测试版仍会按限速尝试行驶。退回位置由编码器估算。首次实跑应留出人工断电条件；实际停车距离、遮挡、串扰和绕行净空须在场地验证。

## 构建

Keil 工程入口：`Ultrasonic_Chassis.uvprojx`。命令行在本目录运行 `python build.py`，会在 `build/` 下创建带时间戳的产物目录，包含 HEX、AXF 和 `result.json`。脚本使用主机模型验证 A/C 全程和避障改道，使用 ARMCC 构建并核对 HEX 与 AXF 的加载字节、关键中断向量以及测试版排除的初始化入口。
