# AI 交接文档 · 视觉端 ↔ STM32 串口协议（给负责 STM32 侧固件的 AI）

> 目标读者：实现/修改 STM32 侧 UART 驱动与流程状态机的 AI。
> 视觉端版本：**3.8.1**（MaixCAM2，2026-10-20）｜ 本文所有行为都来自实际代码，可直接照此实现。
> 对应源码：`maixcam_app_v2/protocol.py`、`tasks.py`、`main.py`、`config.py`

---

## 0. 你必须先知道的 8 件事

1. **一问一答**：视觉端是单线程阻塞的。**收到结果帧再发下一条**。
2. **任务执行中再发命令** → 视觉端回 `BUSY`（不是失败，表示"还在算"）。
3. **`R` 可以打断任何任务**，立即回 `READY`。
4. **超时必须 > 20000ms**（`TASK_TIMEOUT_MS`）；`G` 的视觉超时是 3000ms。
5. **`STACK` 只回中心 `x,y`**，**不含高度** —— 高度由 STM32 自己按物料/层数算。
6. 所有 `x,y,w,h` 都是 **640×480 口径、已去畸变**。
7. **D/E 现在同时校水平和垂直**：视觉端会发 `MOVE,<dx>` 和 `MOVEY,<dy>`；
   STM32 必须两条都解析，否则对应轴永远对不中。
8. **`DISC` 的 `ok` 当前固定为 1**（即使 `|dx|` 超差）；是否需要继续微调，以串口里
   实际收到的 `MOVE/MOVEY` 和历史帧为准，不要只看 `ok`。

## 1. 物理层

| 项 | 值 |
|---|---|
| 视觉端 | MaixCAM2，`/dev/ttyS4`（UART4） |
| 引脚 | A21 = TX，A22 = RX |
| 参数 | **115200 8N1，无流控** |
| 前提 | 板子上「Maix 通信协议」必须先关掉（否则 UART4 被占用） |
| 吞吐 | ≈11.5 KB/s；最长帧（OBST）≈25 B ≈ 2.2ms |

## 2. 帧格式（双向一致）

```text
┌──────┬──────┬─────┬─────────────────┬──────┬──────┐
│ 0xAA │ 0x55 │ LEN │ payload[LEN]    │ CRC8 │ 0x0D │
└──────┴──────┴─────┴─────────────────┴──────┴──────┘
 2B     1B     LEN B                    1B     1B
```

- `LEN` = payload 字节数（0~255），**不含**帧头/CRC/帧尾
- `CRC8` = 对 **`LEN` + `payload`** 计算；**不含** `0xAA 0x55`，**不含** `0x0D`
- CRC 参数：**poly=0x07, init=0x00, 不反射, 无最终异或**
- payload 是 **ASCII**（不要用中文）

### 2.1 单元测试向量（视觉端实测的字节）

| payload | LEN | CRC | 整帧（hex） |
|---|---|---|---|
| `D` | 0x01 | 0xCE | `AA 55 01 44 CE 0D` |
| `R` | 0x01 | 0xAC | `AA 55 01 52 AC 0D` |
| `Z` | 0x01 | 0x94 | `AA 55 01 5A 94 0D` |
| `C,1` | 0x03 | 0xC4 | `AA 55 03 43 2C 31 C4 0D` |
| `T,134+123+314+231` | 0x11 | 0xB1 | `AA 55 11 54 2C 31 33 34 2B 31 32 33 2B 33 31 34 2B 32 33 31 B1 0D` |

**先用 `D` 和 `C,1` 两条把自己的 CRC 实现对一遍。**

### 2.2 拆帧要求

- 允许前面有噪声字节：搜索 `AA 55` 再对齐
- 支持粘连（一包多帧）与分片（一帧多包）
- CRC/帧尾不符 → **丢弃该帧**，不要回任何东西
- **半帧超时**：视觉端 200ms 没收到新字节会丢弃残留；STM32 建议同策略，避免断线后吞帧

## 3. 命令表（STM32 → 视觉端）

| 命令 | payload | 说明 |
|---|---|---|
| `A` | `A` | 启停区 |
| `T` | `T,<15字符>` | 任务码，例 `T,134+123+314+231` |
| `C` | `C,<颜色码>` | 颜色码只能是 `1/2/3/4` |
| `D` | `D` | 粗加工区圆盘 |
| `E` | `E` | 暂存区圆盘 |
| `F` | `F,<颜色码>` | 码垛：按颜色找底座（也可只发 `F`，退回旧行为）|
| `G` | `G` | 前方障碍物 |
| `R` | `R` | 复位/握手（可打断任务）|
| `Z` | `Z` | 结束 |

解析规则（视觉端实际实现）：payload 先 `strip`；有逗号则按**第一个逗号**切成 `命令,参数`，否则取第一个字符为命令、其余为参数。

**未知命令：视觉端静默忽略（不回帧）。** 所以 STM32 不要依赖"发错会收到 ERR"。

## 4. 回复表（视觉端 → STM32）

| 场景 | 回复 | 字段含义 |
|---|---|---|
| 启停区 | `START,<区号>,x,y,w,h` | 区号 1=右侧有灰色道路，2=没有；`x,y,w,h` 是蓝色启停区，**看不到时全 0，区号仍有效** |
| 任务码 | `TASK,<G1>,<G3>` | 只回颜色组（偶数位是放置位置，不回显） |
| 原料区 | `PICK,<颜色码>,x,y` | 命中物料的中心 |
| 圆盘 | `DISC,x,y,dx,ok` | `dx = x - 320 + ALIGN_DX_OFFSET`；当前 `ok` 固定为 1；`dy` 不在回复里，视觉端通过 `MOVEY` 自行闭环 |
| 码垛 | `STACK,x,y` | 只给中心；**视觉不测高度**。视觉按颜色选底座，找不到同色就回空环中心 |
| 障碍物 | `OBST,x,y,w,h,mm` | `mm` 是估算距离（0=无法估算）|
| 无障碍 | `CLEAR` | |
| 握手 | `READY` | |
| 结束 | `OK` | |
| 忙 | `BUSY` | 任务中又收到命令 |
| 失败 | `NONE` / `NONE,<tag>` | tag ∈ `A/T/C/D/E/F`（G 不会回 NONE）|
| 异常 | `ERR,camera` | 相机不可用（随后进程退出）|

### 4.1 视觉端 → STM32 的主动指令（**D/E 对齐时必须实现**）

| 指令 | 含义 |
|---|---|
| `MOVE,<dx>` | 水平微调：`dx` = 目标在画面上的水平偏差像素。**执行后不要回帧**；具体映射成左右平移/前后移动由你决定 |
| `MOVEY,<dy>` | 垂直微调：`dy` = 目标在画面上的垂直偏差像素。**执行后不要回帧**；映射到你们的垂直/前后机构 |

- 仅在 `D/E` 对齐阶段发送；视觉端每轮重新测量，等待 `ALIGN_SETTLE_MS(1200ms)`。
- 两轴都超差时，视觉端会**先发 `MOVE`，紧接着发 `MOVEY`**（两帧连续）。
- 方向反了（越调越远）→ 不要改 STM32 符号，改视觉端配置：
  - 水平：`ALIGN_INVERT_D/E`
  - 垂直：`ALIGN_INVERT_DY_D/E`
- 视觉端最多发 `ALIGN_MAX_ITER(3)` **轮**；每轮每轴最多一条指令。
- 当前数值系数：`MOVE_SCALE=1.0`、`MOVEY_SCALE=1.0`；
  `ALIGN_STEP_MAX=0`（不限幅），`ALIGN_GAIN=0.8`。
- **忽略 `MOVEY` 的后果**：`dy` 不会收敛，视觉端会把 3 轮用完并回 `DISC,...,1`
  （`ok` 仍为 1），但垂直方向实际没对准。

## 5. 状态机

```text
[上电]
  视觉端：自检 → 开 UART → 发一次 READY（仅提示，可能丢）
  STM32 ：上电后主动发 R，收到 READY 才算握手成功   ← 约定

IDLE
  视觉端：每 5ms 收一次
  STM32 ：一次只发一条命令，等回复

RUNNING（视觉端执行任务，A/C/D/E/F 最长 20s，G 最长 3s）
  STM32 若又发命令 → 收到 BUSY（继续等，别当失败）
  STM32 若发 R     → 视觉端立刻中断并回 READY

回复到达 → 回到 IDLE
```

## 6. 每条命令的完整语义与边界

### 6.1 `A` 启停区

- 判据：画面右侧 `ROI_ROAD=[384,120,256,300]` 内**灰色像素占比 ≥30%**，并且 AI 判为 `other`（双确认）；连续 5 帧一致。
- `START_ZONE_HAS_ROAD=1`，`START_ZONE_NO_ROAD=2`。
- 蓝色启停区位置：全画面最大蓝块（≥5000px）；看不到就回 `0,0,0,0`。
- 超时 20s → `NONE,A`（道路结论未稳定）。

### 6.2 `T` 任务码

- 格式：**4 段、每段 3 位数字、用 `+` 连接**，共 15 字符。
- **G1/G3 每一位必须是 1~4**（颜色的语义校验）；G2/G4 只校验是数字。
- 非法 → `NONE,T`（立即，不耗时）。
- 合法 → `TASK,G1,G3`。

```
134+123+314+231 → TASK,134,314
999+000+999+000 → NONE,T        （颜色位非法）
134+123+314     → NONE,T        （段数不对）
```

### 6.3 `C,<颜色码>`

- 颜色码不是 1~4 → **立即** `NONE,C`。
- 原料区 ROI `[140,100,360,300]`；LAB 阈值找候选（≥300px），AI 判色优先。
- AI 置信度 <0.60 → 退回阈值；AI 判成 `background/other` → 该候选**丢弃**。
- 通过判定：连续 15 帧颜色投票 ≥70% + 连续 15 帧中心不动 **+ 物料已停稳**
  （原料区是电动转盘，6~10 秒/圈且间歇停；判据是用 `PICK_STOP_HOLD_MS=300ms` 内的
   位移 ≤ `PICK_STOP_SPEED_PX_S=8px/s` 折算的容差，转慢也算"没停"）。
  转盘一直不停 → 20s 超时回 `NONE,C`。
- 超时 20s → `NONE,C`。

### 6.4 `D` / `E` 圆盘（**重点**）

- 目标：让「环 2」的靶心落在画面中心，水平容差 `|dx| ≤ ALIGN_TOL=5px`，
  垂直容差 `|dy| ≤ ALIGN_DY_TOL=5px`。
- 视觉端识别顺序：
  1. 最内圈白块（靶心）优先；
  2. 黑色同心环质心；
  3. 霍夫圆 + 径向边缘最小二乘细化；
  4. 最后用同心圆环兜底。
- **内容校验**：候选圆心附近必须匹配 `assets/target2.png` 数字“2”模板，
  否则丢弃并回 `NONE`（不会画绿圆）。当前阈值 `0.55`，尺度 `[0.9, 1.0]`。
- 收到 `D/E` 后先等 `DISC_START_DELAY_MS=800ms`，让车/机构停稳，再读第一帧。
- 偏差计算：
  ```text
  dx = x - W/2 + ALIGN_DX_OFFSET   （默认 +5px）
  dy = y - H/2 + ALIGN_DY_OFFSET   （默认 0）
  ```
- 闭环：
  1. 两轴都在容差内且连续 `ALIGN_STABLE_FRAMES=3` 帧稳定 → 回 `DISC,x,y,dx,1`；
  2. 否则每轮对超差轴发指令：
     - 水平：`MOVE,<step>`，`step = dx × 0.8 × MOVE_SCALE`；
     - 垂直：`MOVEY,<step>`，`step = dy × 0.8 × MOVEY_SCALE`；
  3. 等 `ALIGN_SETTLE_MS=1200ms` 后重新测量；
  4. 最多 `ALIGN_MAX_ITER=3` 轮，仍未对齐 → 回 `DISC,...,1`（带最后一次偏差）。
- 完全看不到圆 → 连续 `DISC_LOST_FRAMES=2` 帧立即回 `NONE,D|E`。
- 收到 `MOVE/MOVEY` 后**不要再发新的 D/E**，视觉端会自己继续；等最终的 `DISC`。
- 当前实车实测（2026-10-20）：
  ```text
  [D] dx=+14 dy=-109 → MOVE,11   MOVEY,-87
  [D] dx=+31 dy=-124 → MOVE,25   MOVEY,-99
  [D] dx=+14 dy=-109 → MOVE,11   MOVEY,-87
  ```
  STM32 尚未执行 `MOVEY` 时，`dy` 完全不收敛，可作为联调判据。

### 6.5 `F` 码垛

- 暂存区 ROI `[160,120,320,240]`。
- `F,<颜色码>`：只找**同色**物料作为底座；同色多个取**离 ROI 中心最近**的一个
  （前提：云台已对准目标工位/环，否则“最近”可能是错的环）。
- 找不到同色底座 → 用霍夫圆找**空环中心**并回该坐标；
  连环都找不到 → 退回 ROI 中心（`STACK_RING_FALLBACK=False` 时回 `NONE,F`）。
- `F` 不带参数：退回旧行为，取 ROI 内最靠上的色块。
- **不做颜色投票**（只判中心稳定，连续 15 帧）。
- 回复 `STACK,x,y`（**不带高度**）；超时 20s → `NONE,F`。
- 颜色码非法（不是 1~4）→ 立即 `NONE,F`。

### 6.6 `G` 障碍物

- 全画面找最大黑色块（≥400px），连续 **5 帧**中心稳定 → `OBST,x,y,w,h,mm`。
- 连续 **3 帧**看不到 → 立刻 `CLEAR`（≈50ms）。
- 3s 内没结论 → `CLEAR`（按无障碍处理，**不会回 NONE**）。
- `mm = fx * 50 / w`（障碍物按 φ50mm 计），未标定时为 0。

### 6.7 `R` / `Z`

- `R`：任意状态下回 `READY`；任务中会**立即中断**当前任务。
- `Z`：回 `OK`，**视觉端不退出**，之后仍可继续响应。

## 8. STM32 侧必须实现的容错

1. **超时**：普通命令 >20s、`G` >3.5s 才判失败；收到 `BUSY` 要重置计时继续等。
2. **重发**：视觉端不重传。CAN 式重发由你决定：建议同一命令最多重发 2 次，且只在超时后。
3. **未知帧**：忽略（视觉端不会回 ERR）。
4. **半帧**：200ms 无新字节丢弃缓冲。
5. **握手**：上电发 `R`，等 `READY`；超时 1s 重发，最多 3 次。

## 9. 常见实现错误（会造成"通信正常但行为不对"）

| 错误 | 后果 |
|---|---|
| CRC 把 `0xAA 0x55` 或 `0x0D` 也算进去 | 全部帧被丢弃 |
| `LEN` 算成"整帧长度" | 拆帧错位 |
| 把 `BUSY` 当失败直接重发 | 多个任务排队，拿到过期坐标 |
| 把 `STACK` 当成带高度 | 现在只有 `x,y`，多解析一个字段会错位 |
| `F` 不带颜色码 | 视觉会取最靠上的物料，可能选错底座（颜色不一致）|
| 忽略 `MOVE` | 圆盘水平方向永远对不中 |
| 忽略 `MOVEY` | 圆盘垂直方向永远对不中，`dy` 不收敛 |
| 把 `DISC` 的 `ok=1` 当成两轴都对准 | 当前 `ok` 固定为 1，超差也会回 1；必须结合 `MOVE/MOVEY` 和最终坐标判断 |
| 用 640×480 以外的坐标系解释 `x,y` | 全场景偏移 |
| 任务中并发发命令 | 排队执行，最后收到的是旧任务结果 |

## 10. 视觉端不可配置项（写死的约定）

- 对外坐标口径：**640×480**
- 颜色码：**红1 黄2 蓝3 绿4**
- 任务码 G1/G3 颜色位：**必须是 1~4**
- 圆盘对齐容差：**水平 ±5px，垂直 ±5px**（`ALIGN_TOL` / `ALIGN_DY_TOL`）
- 圆盘对齐轮数：**3 轮**（`ALIGN_MAX_ITER`），每次等待 **1200ms**（`ALIGN_SETTLE_MS`）
- D/E 启动延时：**800ms**（`DISC_START_DELAY_MS`）
- 主动指令：`MOVE,<dx>`（水平）/ `MOVEY,<dy>`（垂直），执行后都不回帧
- 帧头/帧尾/CRC 参数：见 §2
