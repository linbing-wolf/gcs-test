# STM32 接入交接：H 后无论 arrival 均固定三轮 J

更新日期：2026 年 11 月 26 日

本文替代 `HANDOVER_STM32_HDISC2_20261126.md` 中按 `arrival` 分支抓取的流程。

## 结论

视觉端工作区配置 `H_MATERIAL_EXTENDED_PACKET_ENABLED = True`，目标 H 终包为 `HDISC2`。

收到有效 `HDISC2` 终包后，STM32 不使用其中的坐标直接抓取第一件物料，也不按 `arrival=0/1` 分叉。后续统一执行三轮 J：

```text
发送 H
  -> 接收 HCOLORS（可能收到）
  -> 接收 MOVEXY（可能收到）
  -> 等待有效 HDISC2
  -> 发送 J（第 1 轮）
  -> 等待 MSTATE,1
  -> 抓取第 1 件
  -> 发送 J（第 2 轮）
  -> 等待 MSTATE,1
  -> 抓取第 2 件
  -> 发送 J（第 3 轮）
  -> 等待 MSTATE,1
  -> 抓取第 3 件
```

`HDISC2` 中的 `arrival` 只用于日志和故障诊断，禁止用于决定“立即抓”或“少执行一轮 J”。

即使 `HDISC2` 中 `n=0`，只要前缀、字段、CRC 和数值校验全部通过，它仍是有效 H 终包，也仍按固定三轮 J 继续。

## HDISC2 格式

视觉端回包格式保持不变：

```text
HDISC2,arrival,n,color,x,y[,color,x,y,...]
```

| 字段 | 含义 |
| --- | --- |
| `arrival` | 0=到达时观察到运动，1=到达时已停稳；仅诊断，不决定后续流程 |
| `n` | 校准后完整视野内的有效颜色数，允许 0–4 |
| `color` | 红 1、黄 2、蓝 3、绿 4 |
| `x,y` | MaixCAM 对外 640×480 坐标 |

颜色组按 `x` 从小到大排列。同色多目标只发送面积最大的一个。

示例：

```text
HDISC2,1,3,1,100,230,2,300,250,3,500,240
HDISC2,0,2,2,180,240,3,460,235
```

两条示例都必须在收到后执行固定三轮 J，行为完全相同。

STM32 接收时至少检查：

- 前缀必须为 `HDISC2`。
- `arrival` 只能为 `0` 或 `1`。
- `n` 只能为 `0`、`1`、`2`、`3`、`4`。
- 字段总数必须为 `3 + 3*n`。
- 每个颜色只能为 `1`、`2`、`3`、`4`，且同包内不能重复。
- `x/y` 必须能完整解析为整数。

满足以上条件即进入固定的三次 J 流程。`arrival` 值只写入日志或诊断状态。

## STM32 状态机

```text
H_SESSION
  -> 发送 H
  -> 等待 HDISC2
  -> 保存 arrival 和 H 坐标用于日志
  -> J_ROUND = 1

J_1 + 抓取1
  -> 发送 J
  -> 等待 MSTATE,1
  -> 解析本轮最新坐标
  -> 执行第 1 件抓取
  -> 等待机构动作完成
  -> J_ROUND = 2

J_2 + 抓取2
  -> 发送 J
  -> 等待 MSTATE,1
  -> 解析本轮最新坐标
  -> 执行第 2 件抓取
  -> 等待机构动作完成
  -> J_ROUND = 3

J_3 + 抓取3
  -> 发送 J
  -> 等待 MSTATE,1
  -> 解析本轮最新坐标
  -> 执行第 3 件抓取
  -> 等待机构动作完成
  -> H/J 工位结束
```

第一件必须使用第 1 轮 J 的 `MSTATE,1` 坐标。`HDISC2` 的坐标只用于校准结果记录和 H 诊断，不能代替第 1 轮 J。

## J 完成条件

每轮 J 只有收到完成位为 `1` 的终包才允许抓取：

```text
MSTATE,1,n,color,x,y,state[,color,x,y,state,...]
```

- 首字段 `1` 表示本次 J 已结束。
- `n` 是当前完整视野内的颜色数量。
- 每个颜色组必须重新解析坐标。
- 抓取动作必须使用本轮最新 `MSTATE,1` 返回的坐标。
- `MSTATE,0` 不是完成包，不得触发抓取。
- `BUSY` 不是完成包，STM32 不得开始机械臂动作。

收到 `BUSY` 时保持当前视觉会话。STM32 侧继续执行自己的工位超时和机械动作完成检查。

J 只负责识别当前完整视野内的停稳物料，不会自动发送移动指令。STM32 仍需在每轮抓取后等自己的机构动作完成，再发送下一轮 J。

## 异常处理

- 收到 `NONE,H`：本轮 H 未得到有效终包，不进入固定三轮 J；按整机流程重试 H 或报 H 工位故障。
- 收到 `ERR,...`：终止当前 H/J 会话并报故障。
- 需要取消时发送 `R`，等待 `READY` 后清理 H/J 会话。
- J 超时期间不得复用上一轮坐标进行抓取。
- 同一轮 J 重复收到终包时只处理一次，避免重复抓取。
- 三轮中的任意一轮失败都必须停止后续抓取，不能跳过失败轮次。

## 时序约束

视觉端最近已将 H/J 的停稳窗口缩短，并允许 J 复用 H 或上一轮 J 已确认的稳定坐标。因此 STM32 不应再额外休眠固定秒数。

推荐直接按事件推进：

1. 收到有效 `HDISC2` 后立即发送第 1 轮 J。
2. 收到 `MSTATE,1` 后立即执行对应抓取。
3. 抓取机构确认完成后发送下一轮 J。
4. 三轮完成后进入后续工位。

如果现场仍需机械臂安全等待，等待时间应属于 STM32 的机构动作约束，不应通过跳过 J 或延迟解析 `MSTATE,1` 来实现。

## 通信与 CRC

- GPIO I²C 保持 A1=SCL、A0=SDA、从机地址 `0x42`、10 kHz。
- 外层帧保持 `AA 55 LEN payload CRC8 0D`。
- CRC8 多项式保持 `0x07`。
- 视觉端可以跨多个 I²C 分片发送一条消息，STM32 必须按 `LEN` 收齐后再校验 CRC。
- `HDISC2` 三色消息通常跨两个 32 字节分片，不能把单个分片直接交给协议解析器。

## STM32 接入验收

1. 构造 `arrival=0` 和 `arrival=1` 两种 `HDISC2`，确认都会进入固定三轮 J。
2. 构造 `n=0` 与 `n=4` 的合法 `HDISC2`，确认都不会跳过 J 或改变 J 轮数。
3. 每轮仅收到 `MSTATE,0` 时确认不会抓取。
4. 每轮收到 `MSTATE,1` 后确认只抓取一次。
5. 模拟 J 超时、`BUSY`、`R/READY` 和 CRC 错误。
6. 验证 `HDISC2` 跨两个 I²C 分片的组帧。
7. 验证第 1、2、3 件均使用各自最新 J 坐标。
8. 确认旧文档中的 `arrival` 分支逻辑已从 STM32 代码中删除。
