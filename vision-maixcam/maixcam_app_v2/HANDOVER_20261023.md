## 3. 串口协议

帧格式不变：

```text
AA 55 LEN payload CRC8 0D
```

视觉端回复格式不变：

```text
DISC,x,y,dx,ok
STACK,x,y,dx,ok
```

当前 `ok` 固定为 `1`。

### 3.1 新增 MOVEXY

当前默认：

```python
ALIGN_MODE = "movexy"
```

视觉端双轴微调发送：

```text
MOVEXY,<dx>,<dy>
```

例如：

```text
MOVEXY,-38,-9
```

含义：

- 一条指令同时下发两轴；
- 某一轴为 `0` 表示该轴不动；
- `dx/dy` 是像素步长，已经过增益、方向反转和 scale 处理。

**重要：下位机必须能解析 `MOVEXY,dx,dy`。**  
如果下位机只支持旧的 `MOVE` / `MOVEY`，把配置改为：

```python
ALIGN_MODE = "split"
```

即可退回旧协议。

### 3.2 one-shot 行为

```python
ALIGN_ONE_SHOT = True
```

流程：

```text
收到 D/E/F
→ 识别一次
→ 超差则发一条 MOVEXY
→ 等待动作后回读
→ 回传调整后的 x/y/dx
```

one-shot 期间**不会再补发** MOVEXY。

回读参数：

```python
ONE_SHOT_VERIFY_MS     = 600
ONE_SHOT_VERIFY_MAX_MS = 2500
ONE_SHOT_STOP_TOL      = 3
ONE_SHOT_STOP_FRAMES   = 3
```

并且已经增加运动确认：

```text
发了 MOVEXY 的轴，必须先检测到该轴真的移动
再连续 3 帧稳定，才允许返回
```

避免动作还没开始就被误判为停稳。

## 4. 当前 D/E/F 参数

### 4.1 目标与偏置

| 项目 | D | E | F |
|---|---:|---:|---:|
| 目标 x | 318 | 318 | 315 |
| 目标 y | 200 | 200 | 195 |
| X 偏置 | `ALIGN_DX_OFFSET_D=2` | `ALIGN_DX_OFFSET=2` | `STACK_ALIGN_DX_OFFSET=5` |
| Y 偏置 | `ALIGN_DY_OFFSET_D=40` | `ALIGN_DY_OFFSET=40` | `STACK_ALIGN_DY_OFFSET=45` |
| 水平容差 | 5px | 5px | 5px |
| 垂直容差 | 5px | 5px | 5px |
| X 反向 | False | False | False |
| Y 反向 | False | False | False |

计算关系：

```text
D/E：目标 x = 320 - X偏置
     目标 y = 240 - Y偏置

F：  目标 x = 320 - STACK_ALIGN_DX_OFFSET
     目标 y = 240 - STACK_ALIGN_DY_OFFSET
```

### 4.4 H 命令（物料盘下弧对齐）

物料盘太大，画面只能拍到它的下弧、圆心落在画面外。做法：粗圆心先验
（`PLATE_INIT_CX/CY/R`）→ 沿下半弧射线找边缘点 → 最小二乘拟合圆 →
取最低点 `(cx, cy+r)` 为基准，与目标最低点相减得 dx/dy，像 D/E 一样发
`MOVEXY,dx,dy` 微调。回复复用 `DISC,x,y,dx,ok`（dy 只随 MOVEXY 下发，
STM32 侧解析无需改动）；一次/闭环跟随 `ALIGN_ONE_SHOT`。

```python
PLATE_TARGET_X = 311.0   # 目标最低点 x（现场标定：盘摆到位，读日志 low=(x,y)）
PLATE_TARGET_Y = 267.0   # 目标最低点 y
PLATE_DX_OFFSET = 2      # 固定偏差修正（同 D/E 口径）
PLATE_DY_OFFSET = 40
PLATE_TOL_X = 6
PLATE_TOL_Y = 6
```

### 4.5 运行时切换对齐回复模式（诊断用，免重编包）

`ALIGN_REPLY_MODE` 默认 `"direct"`（去回读：发完 MOVEXY 立即回**动作前**偏差，最快）；
`"verify"` 会回读一次、回**调整后**偏差（准但慢，多等 `ONE_SHOT_VERIFY_MS~MAX_MS`）。

现场不想重编包也能临时切（优先级：触发文件 > config）：

```bash
touch /tmp/align_verify   # D/E/F/H 临时改 verify（拿「移动后偏差」）
rm    /tmp/align_verify   # 恢复 config 默认
touch /tmp/align_direct   # 反向强制 direct
```

扫描结果按 `ALIGN_MODE_CACHE_MS`（默认 500ms）缓存；切换时会打印
`[ALIGN] 触发文件 ... 强制 ...`，日志里能确认当次到底走没走回读。

## 6. 已知问题

### 6.1 F 会误识别画面边缘的同色物体

实测出现过：

```text
初始 AI 中心 (512,216)
颜色质心 (553,224)
→ 发 MOVEXY,150,57
→ 最终跑到 (68,11)
```

原因：

```text
ROI_STACK 覆盖 x=80..560
STACK_AI_MIN_TILES = 2
```

只要画面右侧有同色物体，2 个 AI 块就能通过。

建议后续增加：

```text
绝对目标门限：中心离目标 (315,195) 超过 80～100px 直接拒绝
```

或收紧 ROI / 提高 `STACK_AI_MIN_TILES`。

### 6.2 F 颜色质心与顶部圆心的透视偏差

颜色质心包含侧面，透视下会向画面下方偏移。  
目前尚未加入顶部圆心补偿。

可选方案：

1. 固定偏移补偿；
2. 在 F 区做 3×3 标定，拟合位置相关 `dx/dy`；
3. 顶面轮廓椭圆拟合；
4. 相机几何模型。

### 6.3 F 的 X 残差

近期实测 F 的 X 残差约：

```text
-6 ～ +9px
```

部分轮次会因 X 偏差触发 MOVE，导致车体前后移动。  
当前 F 目标 x 已改为 315，仍需要多轮测试确认。

### 6.4 D/E 的 X 残差

近期 D/E 多次出现：

```text
D: dx=+8～+9
E: dx=-7～+8
```

Y 基本正常。  
说明 D/E 的 X 目标还需要分别标定，不能长期共用。

### 6.5 图像延迟

主要开销：

```text
F AI 分块扫描约 81 次分类
每 100ms 保存 JPEG
60fps 相机缓冲积压
```

建议按场景降低：

```python
STACK_AI_STRIDE = 96
STACK_DEBUG_MAX_FRAMES = 8
STACK_DEBUG_MIN_INTERVAL_MS = 500
STACK_DEBUG_QUALITY = 60
```

比赛时可以直接：

```python
STACK_DEBUG_SAVE = False
```
