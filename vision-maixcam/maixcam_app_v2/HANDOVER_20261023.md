## 3. 串口协议

帧格式不变：

```text
AA 55 LEN payload CRC8 0D
```

视觉端回复格式不变：

```text
DISC,x,y,dx,ok
STACK,x,y,dx,ok
```

当前 `ok` 固定为 `1`。

### 3.1 新增 MOVEXY

当前默认：

```python
ALIGN_MODE = "movexy"
```

视觉端双轴微调发送：

```text
MOVEXY,<dx>,<dy>
```

例如：

```text
MOVEXY,-38,-9
```

含义：

- 一条指令同时下发两轴；
- 某一轴为 `0` 表示该轴不动；
- `dx/dy` 是像素步长，已经过增益、方向反转和 scale 处理。

**重要：下位机必须能解析 `MOVEXY,dx,dy`。**  
如果下位机只支持旧的 `MOVE` / `MOVEY`，把配置改为：

```python
ALIGN_MODE = "split"
```

即可退回旧协议。

### 3.2 one-shot 行为

```python
ALIGN_ONE_SHOT = True
```

流程：

```text
收到 D/E/F
→ 识别一次
→ 超差则发一条 MOVEXY
→ 等待动作后回读
→ 回传调整后的 x/y/dx
```

one-shot 期间**不会再补发** MOVEXY。

回读参数：

```python
ONE_SHOT_VERIFY_MS     = 600
ONE_SHOT_VERIFY_MAX_MS = 2500
ONE_SHOT_STOP_TOL      = 3
ONE_SHOT_STOP_FRAMES   = 3
```

并且已经增加运动确认：

```text
发了 MOVEXY 的轴，必须先检测到该轴真的移动
再连续 3 帧稳定，才允许返回
```

避免动作还没开始就被误判为停稳。

### 4.4 H 命令（物料盘下弧对齐）

物料盘太大，画面只能拍到它的下弧、圆心落在画面外。做法：粗圆心先验
（`PLATE_INIT_CX/CY/R`）→ 沿下半弧射线找边缘点 → 拟合盘缘 → 取最低点为
基准，与目标最低点相减得 dx/dy，像 D/E 一样发 `MOVEXY,dx,dy` 微调。
回复复用 `DISC,x,y,dx,ok`（dy 只随 MOVEXY 下发，STM32 侧解析无需改动）；
一次/闭环跟随 `ALIGN_ONE_SHOT`。

**弧模型：不是圆，是「轴对齐椭圆」**（盘是平面圆、镜头斜视 → 投影为椭圆）。
实测 12 张真实下弧图：边缘半径随角度极差约 12px（底部最小、±45° 最大），
用圆去套会有 ~3~8px 系统偏差——绿圆两侧翘离盘缘、最低点偏低 ~4px。
故默认 `PLATE_ARC_MODEL="ellipse"`：在 `(x, y/k)` 拉伸空间拟合圆（k 自动估计，
范围 `PLATE_ELLIPSE_K_*`），最低点 = `(cx, cy + b)`；`"circle"` 可退回旧行为。

```python
PLATE_ARC_MODEL      = "ellipse"
PLATE_ARC_ROBUST     = True    # 剔除离群边缘点（中间黑条/夹具/阴影）
PLATE_ELLIPSE_K_MIN  = 0.86    # 竖直/水平半轴比搜索范围
PLATE_ELLIPSE_K_MAX  = 1.05
PLATE_INIT_CY        = -32.0   # 粗圆心先验（决定第一轮搜索带扫哪儿）
PLATE_TARGET_X       = 311.0   # 目标最低点（现场标定）
PLATE_TARGET_Y       = 313.0   # 落点基准；有效目标 y = 此值 − PLATE_DY_OFFSET
PLATE_DX_OFFSET = 2            # 固定偏差修正；有效目标 x = 311 − 2 = 309
PLATE_DY_OFFSET = 0            # 0 → 有效目标 y = 313
PLATE_TOL_X = 6
PLATE_TOL_Y = 6
```

### 4.4b 运行时可调落点（现场调，免重编包）

```bash
# 只写要改的项；文件不在/行不合法 → 该项仍用 config
ssh root@<板子> "printf 'PLATE_DY_OFFSET=5\n' > /tmp/plate_bias"
ssh root@<板子> "printf 'PLATE_TARGET_Y=303\n' > /tmp/plate_bias"
ssh root@<板子> "rm -f /tmp/plate_bias"          # 恢复 config 默认
```

可覆盖的键：`PLATE_TARGET_X / PLATE_TARGET_Y / PLATE_DX_OFFSET / PLATE_DY_OFFSET`
（见 `config.PLATE_BIAS_KEYS`）。支持 `#` 注释、空行、`=` 两侧空格；`H` 启动日志
会打印「目标 → 有效 | 落点来源」，能一眼看出当前用的是 config 还是覆盖文件。
⚠️ 方向：**有效目标 y 越大 = 落点越低 = 车越靠前**；`PLATE_DY_OFFSET` 变大 = 落点抬高。

> ⚠️ **有效目标** = `(PLATE_TARGET_X − PLATE_DX_OFFSET, PLATE_TARGET_Y − PLATE_DY_OFFSET)`，
> 即 dy=0 时最低点落下的位置；`[H]` 启动日志里会打印「目标 → 有效」两行数值。
> `PLATE_DY_OFFSET` 每 +1 就把落点抬高 1px（40 = 抬 40px）。现场要求落点更靠下，
> 故 40→0（净下移 40px）；想只下移 35px 就填 5。

> ⚠️ `PLATE_TARGET_Y` 的 267→263 是「平均修正」（真实图实测 圆−椭 平均 4.2px，
> 随位姿在 0.3~7.4px 间变化），现场必须用新抓图复核后再定稿。
> 若把 `PLATE_ARC_MODEL` 改回 `"circle"`，要同步改回 267。

### 4.4a 假圆防护（粗定位 + 质量闸门）★ 重要

**现场问题**：盘相对车**横向偏移很大**时（用户拍的 `other_0422~0444`），配置先验
偏出搜索带（±`PLATE_SEARCH_BANDS[0]`=60），算法会沿旧弧扫到**桌面/夹具/线缆**，
拟出**假圆**（rms 6~11 却照样回 `DISC`），并驱动错误的 `MOVEXY`。

**修法（两道防线）**：

```python
PLATE_COARSE_LOCATE      = True   # ① 先验无关的全图粗定位
PLATE_COARSE_X_STEP      = 16     #    逐列扫「亮→暗」最强下降沿（盘缘暗线）
PLATE_COARSE_ITERS       = 120    #    RANSAC 圆拟合（抗离群：黑条/夹具/线缆/桌边）
PLATE_COARSE_MIN_INLIERS = 12
PLATE_COARSE_R_RATIO_MIN = 0.55   #    粗圆半径还要在「配置先验半径 × 0.55~1.60」内
PLATE_COARSE_R_RATIO_MAX = 1.60
PLATE_QUALITY_GATE = True         # ② 质量闸门：不可信宁回 NONE，不回假圆
PLATE_MAX_RMS      = 4.0          #    残差上限(px)（主判据）
PLATE_MIN_PTS      = 30           #    有效边缘点下限（只防退化）
```

流程：粗定位先验与配置先验**各试一轮** → 取「可信且 rms 最小」的 → 都不可信就回
`NONE,H`（上位机重摆）。`meta` 里有 `coarse/prior_used/tries` 便于排查。

贴合的实测（35 张真实图，离线回归）：

| 配置 | 可信拟合 | 假圆 | NONE |
|---|---:|---:|---:|
| 旧（无粗定位/无闸门） | 11 | 24 | 0 |
| **粗定位 + 闸门（现在）** | **17** | **0** | 18 |

判据分得很干净：可信拟合 rms ≤ 3.0 / npts ≥ 44；假圆 rms ≥ 5.96，故闸门取 4.0。

抓图：`PLATE_DEBUG_SAVE=True` 时每次 H 在 `PLATE_DEBUG_DIR`
（默认 `/root/yyb_mover_data/plate_debug/`）下建任务目录，存关键帧 + `meta.jsonl`
（含 `model/a/b/k/rms/low_x/low_y/dx/dy`）+ `summary.json`，只保留最近
`PLATE_DEBUG_KEEP_TASKS` 次。

### 4.5 运行时切换对齐回复模式（诊断用，免重编包）

`ALIGN_REPLY_MODE` 默认 `"direct"`（去回读：发完 MOVEXY 立即回**动作前**偏差，最快）；
`"verify"` 会回读一次、回**调整后**偏差（准但慢，多等 `ONE_SHOT_VERIFY_MS~MAX_MS`）。

现场不想重编包也能临时切（优先级：触发文件 > config）：

```bash
touch /tmp/align_verify   # D/E/F/H 临时改 verify（拿「移动后偏差」）
rm    /tmp/align_verify   # 恢复 config 默认
touch /tmp/align_direct   # 反向强制 direct
```

扫描结果按 `ALIGN_MODE_CACHE_MS`（默认 500ms）缓存；切换时会打印
`[ALIGN] 触发文件 ... 强制 ...`，日志里能确认当次到底走没走回读。

## 6. 已知问题

### 6.1 F 会误识别画面边缘的同色物体

实测出现过：

```text
初始 AI 中心 (512,216)
颜色质心 (553,224)
→ 发 MOVEXY,150,57
→ 最终跑到 (68,11)
```

原因：

```text
ROI_STACK 覆盖 x=80..560
STACK_AI_MIN_TILES = 2
```

只要画面右侧有同色物体，2 个 AI 块就能通过。

建议后续增加：

```text
绝对目标门限：中心离目标 (315,195) 超过 80～100px 直接拒绝
```

或收紧 ROI / 提高 `STACK_AI_MIN_TILES`。

### 6.2 F 颜色质心与顶部圆心的透视偏差

颜色质心包含侧面，透视下会向画面下方偏移。  
目前尚未加入顶部圆心补偿。

可选方案：

1. 固定偏移补偿；
2. 在 F 区做 3×3 标定，拟合位置相关 `dx/dy`；
3. 顶面轮廓椭圆拟合；
4. 相机几何模型。

### 6.3 F 的 X 残差

近期实测 F 的 X 残差约：

```text
-6 ～ +9px
```

部分轮次会因 X 偏差触发 MOVE，导致车体前后移动。  
当前 F 目标 x 已改为 315，仍需要多轮测试确认。

### 6.4 D/E 的 X 残差

近期 D/E 多次出现：

```text
D: dx=+8～+9
E: dx=-7～+8
```

Y 基本正常。  
说明 D/E 的 X 目标还需要分别标定，不能长期共用。

### 6.5 图像延迟

主要开销：

```text
F AI 分块扫描约 81 次分类
每 100ms 保存 JPEG
60fps 相机缓冲积压
```

建议按场景降低：

```python
STACK_AI_STRIDE = 96
STACK_DEBUG_MAX_FRAMES = 8
STACK_DEBUG_MIN_INTERVAL_MS = 500
STACK_DEBUG_QUALITY = 60
```

比赛时可以直接：

```python
STACK_DEBUG_SAVE = False
```
