# STM32 接入交接：H / HDISC2 / J

更新日期为 2026 年 11 月 26 日。

> **流程已更新：** `arrival=0/1` 不再决定抓取轮数。所有有效 `HDISC2` 后统一执行三轮 J。
> 请以 `HANDOVER_STM32_HDISC2_FIXED_3J_20261126.md` 为准，本文仅保留字段和协议说明。

## 当前状态

MaixCAM 已启用实验版 `HDISC2`。当前配置为 `H_MATERIAL_EXTENDED_PACKET_ENABLED = True`，H 终包使用本文格式。

## H 任务时序

STM32 发送 ASCII `H` 后，允许收到：

1. `HCOLORS,c1,c2,dir`
2. `MOVEXY,dx,dy`
3. `HDISC2,arrival,n,c1,x1,y1,c2,x2,y2,c3,x3,y3`

`BUSY` 表示视觉端仍在处理当前任务。`READY` 只用于主动发送 `R` 后的取消确认。H 没有结束时，STM32 不应把中间包当作工位结果。

## HDISC2 格式

```text
HDISC2,arrival,n,color,x,y[,color,x,y,...]
```

字段：

| 字段 | 含义 |
| --- | --- |
| `HDISC2` | 新 H 终包前缀 |
| `arrival` | 车到达并开始 H 观察时，`1`=物料已停稳；`0`=观察到物料运动后才停稳 |
| `n` | 校准后完整视野内的有效颜色数量，允许 `0–4` |
| `color,x,y` | 每个颜色一组；颜色码为红 `1`、黄 `2`、蓝 `3`、绿 `4` |

坐标使用 MaixCAM 对外 `640×480` 口径。相同颜色有多个目标时，只发送面积最大的一个。颜色组按 `x` 从小到大排列。

`HDISC2` 不再重复旧 `HDISC` 的基准 `x,y,dx`、先到色、后到色和方向字段。STM32 必须按独立前缀处理，不能复用旧的七字段 `HDISC` 解析器。

示例：

```text
HDISC2,1,3,1,100,230,2,300,250,3,500,240
```

表示到达时已停稳，校准后看到红 `(100,230)`、黄 `(300,250)`、蓝 `(500,240)`。

## arrival=1 抓取流程

`arrival=1` 表示开始 H 时物料已停稳：

```text
HDISC2
  -> 发送 J
  -> 等待 MSTATE,1
  -> 抓取第 1 件
  -> 发送 J
  -> 等待 MSTATE,1
  -> 抓取第 2 件
  -> 发送 J
  -> 等待 MSTATE,1
  -> 抓取第 3 件
```

即通过 **3 轮 J** 获取每次抓取前的最新坐标。每轮必须收到完成位为 `1` 的 `MSTATE` 后再抓取。J 返回的物料选择仍由 STM32 的抓取任务颜色顺序决定。

## arrival=0 抓取流程

`arrival=0` 表示到达时仍在运动，校准时才停稳：

```text
HDISC2
  -> 立即抓取第 1 件
  -> 发送 J
  -> 等待 MSTATE,1
  -> 抓取第 2 件
  -> 发送 J
  -> 等待 MSTATE,1
  -> 抓取第 3 件
```

第 1 件直接使用刚收到的 `HDISC2` 三色坐标。之后只做 **2 轮 J**，为第 2、3 次抓取更新坐标。

## 校验与异常

- 严格检查前缀、字段数量、颜色码、坐标整数和颜色互异。
- `arrival` 只能为 `0` 或 `1`。
- `n` 必须为 `0–4`，后续字段数必须等于 `3+3*n`。
- J 的 `MSTATE,1,n,...` 需要对所有记录校验状态均为 `1`。
- 收到 `BUSY` 时保持当前视觉会话，不得开始对应抓取。
- 主动取消时发送 `R`，收到 `READY` 后清理当前 H/J 会话。
- STM32 侧仍需有自己的工位超时和底盘动作完成检查，视觉端 H/J 不提供统一任务截止。

## I2C 和帧长度

- GPIO I²C 仍为 A1=SCL、A0=SDA、从机地址 `0x42`，每片 32 字节。
- 外层仍为 `AA 55 LEN payload CRC8 0D`，CRC8 多项式为 `0x07`。
- 三个颜色时，最长 `HDISC2` 示例的 payload 约为 `40` 字节，外层帧约 `45` 字节，需要跨两个 I²C 分片。
- 四个颜色时，payload 最大约 `50` 字节，外层帧约 `55` 字节，也仍在单字节 LEN 范围内。
- STM32 必须跨分片组帧，校验 CRC 后再解析，不能按单个 32 字节 I²C 片直接当完整消息。
