# J 物料停稳检测指令交接

日期为 2026 年 11 月 22 日。本功能已随 3.9.97-i2c-gpio 上传板端。2026 年 11 月 23 日 17:20 已将 J 更新为静默等待版本，启动握手验证通过。

## 指令与任务生命周期

发送 `J` 开始全图物料检测，使用现有颜色定位和 AI 判色能力。每种颜色跟踪一个候选，检测范围为当前整个画面。

任务没有观察总时长上限。等待期间只在本地写调试日志和刷新画面，不向上位机发送 `MSTATE,0` 过程包。画面没有有效物料、有物料运动或证据不足时继续等待。当前可见物料的跟踪状态全部为 `1`，并且颜色集合连续稳定 100 ms 后才发送一次 `MSTATE,1` 终包并退出。

收到 `R` 立即中断任务并回复 `READY`，任务期间收到其他指令按现有 TaskCtl 回复 `BUSY`。应用退出时返回 `NONE,J`。J 不接受参数，`J,1` 等带参数请求回复 `ERR,j_arg`。

J 只执行图像采样、显示、日志和状态回包。该任务内没有车辆移动指令。

## 数据帧

外层继续使用现有 `AA 55 LEN payload CRC8 0D`，CRC8 对 LEN 和 payload 计算，poly 为 0x07。GPIO I²C 的 32 字节传输单元由现有传输层分片，接收方需完整组帧后解析 ASCII payload。

payload 结构如下。

```text
MSTATE,done,n,color1,x1,y1,state1,color2,x2,y2,state2,...
```

| 字段 | 取值和含义 |
| --- | --- |
| done | J 只发送 1 终包。0 过程包结构保留用于协议兼容，当前 J 不再发送 |
| n | 该帧报告的颜色数量，0～4 |
| color | 1 红、2 黄、3 蓝、4 绿，按颜色码递增排列 |
| x、y | 物料中心，对外图像坐标口径，正常配置为 640×480 |
| state | 0 运动中、1 已停稳、2 证据不足 |

总字段数为 `3 + 4*n`。done 为 1 时 n 必须大于 0 且每个 state 都为 1。同一包每种颜色最多出现一次。最多报告四种颜色，n 表示颜色数量。

以下过程包结构继续由打包函数支持，J 任务等待期间不会发送这些包。

```text
MSTATE,0,0
```

红色物料正在运动、蓝色物料已经停稳时，本地日志可能出现如下状态。

```text
MSTATE,0,2,1,320,240,0,3,450,210,1
```

新出现的红色物料还没有足够连续观察记录。

```text
MSTATE,0,1,1,320,240,2
```

两种物料全部停稳并连续确认后，J 只发送下面这一种终包。发送后本次 J 退出。

```text
MSTATE,1,2,1,320,240,1,3,450,210,1
```

## 停稳判定

使用最近至少 300 ms 的连续采样，至少需要 3 帧。将中心坐标换算成现有对外坐标后，计算最近窗口的 X、Y 极差所形成的对角线长度，长度不超过 3 px 则暂判为停稳，超过则判为运动中。单色暂判停稳后，所有当前可见颜色还必须保持相同颜色集合并连续为 `1` 满 100 ms，才会形成终包。期间任一种颜色变为 `0` 或 `2`、颜色集合变化、重新出现颜色或采样断档，都会重新计时。

采用窗口内的运动范围，物料运动一圈后回到原点仍会被识别为运动。允许未完整入镜的物料参与判断，依据其可见部分中心的连续变化确认运动或停稳。局部中心稳定反映的是画面内可见部分的位置稳定，遮挡和分割变化仍可能影响测量。判定针对物料相对图像的位置变化，测量时摄像头应保持固定。

以下情况报告证据不足，并清除或重新积累对应颜色的运动窗口。

- 首次出现，连续观察时长或帧数不足。
- 相邻有效帧间隔超过 150 ms。
- 同一帧出现多个相同颜色候选，无法确定是否一直在跟踪同一个物料。包中展示面积最大者的中心，state 为 2。

某颜色从当前帧消失时，清除该颜色的跟踪记录。终包代表结束当帧可见的全部有效颜色都已停稳。已经离开画面的物料不计入该帧的数量。

识别的颜色采用现有 ColorClassifier 的最终结果，包括现有 AI 阈值和 CV 回退策略。没有被现有分类器认可的对象不会计入颜色数量。

## 配置

```python
MATERIAL_STATE_REPORT_MS = 500
MATERIAL_STATE_HOLD_MS = 300
MATERIAL_STATE_TOL_PX = 3.0
MATERIAL_STATE_MIN_FRAMES = 3
MATERIAL_STATE_MAX_GAP_MS = 150
MATERIAL_STATE_CONFIRM_MS = 100
```

REPORT_MS 是本地调试日志间隔，HOLD_MS 是单色运动窗口，CONFIRM_MS 是全部可见颜色连续保持停稳的最终确认时间。这些配置均不设置任务总超时。如果有效识别帧率低于约 7 fps，需要结合现场测量调整 MAX_GAP_MS。

## 现场测试修正

2026 年 11 月 22 日实景测试确认，原有贴边即报 2 的规则会使画面边缘静止物料始终无法确认。现已允许截断物料按相同连续窗口判定，继续保留全部可见物料均需确认的结束条件、无总超时和 R 中断。

2026 年 11 月 23 日日志复核发现，过程包每 500 ms 才输出一次，而终包判断逐帧执行，曾出现上一份过程包仍有 `0`、随后很快发送终包的情况。J 已改为等待期间静默，要求全部可见颜色连续稳定 1000 ms 后只发送一次终包。
