# STM32 物料区交接：H 定位一次，C 按任务码抓取三次

更新日期：2026 年 11 月 27 日

本文替换物料区当前的“H 后固定三轮 J”流程：

- `HANDOVER_STM32_HDISC2_FIXED_3J_20261126.md`
- `HANDOVER_STM32_HDISC2_20261126.md`
- `HANDOVER_STM32_H_J_20261124.md` 中的物料区抓取时序

新流程只使用一次 `H` 完成物料区定位和车体距离校正，随后根据任务码中的三种颜色依次发送三次 `C,<颜色码>`，每次使用对应的 `PICK` 坐标抓取一件。物料区抓取不再发送 `J`。

## 1. 新流程总览

```text
STM32 发送 H
  -> MaixCAM 发送 HCOLORS,<先到色>,<后到色>,<方向>
  -> MaixCAM 发送 MOVEXY,<dx>,<dy>
  -> STM32 执行 MOVEXY 并等待车体动作完成
  -> MaixCAM 发送 HDISC2,<arrival>,<n>,<color>,<x>,<y>,...
  -> STM32 保存本轮 H 定位结果
  -> 根据当前三色任务码生成抓取顺序

第 1 件
  -> STM32 发送 C,<颜色1>
  -> MaixCAM 返回 PICK,<颜色1>,<x1>,<y1>
  -> STM32 抓取并等待机构动作完成

第 2 件
  -> STM32 发送 C,<颜色2>
  -> MaixCAM 返回 PICK,<颜色2>,<x2>,<y2>
  -> STM32 抓取并等待机构动作完成

第 3 件
  -> STM32 发送 C,<颜色3>
  -> MaixCAM 返回 PICK,<颜色3>,<x3>,<y3>
  -> STM32 抓取并等待机构动作完成

物料区本轮完成
```

关键约束：

1. 每轮物料区只发送一次 `H`。
2. `H` 未收到有效终包前，STM32 不发送 `C`。
3. 三次 `C` 必须逐次执行。收到本次 `PICK` 并完成抓取后，才能发送下一次 `C`。
4. 每件物料都使用本次 `C` 返回的 `PICK` 坐标。
5. 不发送 `J`，不使用 `MSTATE`，不再执行三轮 `J`。
6. `HDISC2` 的坐标用于本轮 H 定位记录和诊断，不能代替三次 `C` 的最新抓取坐标。

## 2. 任务码与三色抓取顺序

任务码仍由 `T,<任务码>` 下发，格式为：

```text
G1+G2+G3+G4
```

- `G1`：第一批三件物料的颜色和顺序。
- `G2`：第一批放置位置。
- `G3`：第二批三件物料的颜色和顺序。
- `G4`：第二批放置位置。
- `G1`、`G3` 均必须为三位数字，每一位只能是颜色码 `1/2/3/4`。

MaixCAM 对合法任务码返回：

```text
TASK,<G1>,<G3>
```

例如：

```text
STM32 -> T,134+123+314+231
MaixCAM -> TASK,134,314
```

如果本次物料区使用第一批，则严格执行：

```text
C,1
C,3
C,4
```

如果本次物料区使用第二批，则严格执行：

```text
C,3
C,1
C,4
```

STM32 必须逐字符读取任务码，按任务码给出的顺序发送 `C`。MaixCAM 不保存“当前正在抓第几件”的全局状态，抓取顺序由 STM32 控制。

本文定义的一次物料区流程包含三件物料。若实际流程需要同时处理 `G1` 和 `G3` 两批，应为第二批重新开始一次“H 定位一次 + C 抓取三次”的流程。

## 3. H 指令和回包

### 3.1 发送 H

```text
STM32 -> H
```

H 任务期间，STM32 应按顺序接收以下消息：

```text
HCOLORS,<c1>,<c2>,<direction>
MOVEXY,<dx>,<dy>
HDISC2,<arrival>,<n>,<color>,<x>,<y>,...
```

`HCOLORS` 和 `MOVEXY` 是过程消息。STM32 可解析并记录，但不能把它们当作物料区任务完成。

当前版本的每轮 H 只应发送一次 `HCOLORS`。若收到重复 `HCOLORS`，应记录协议异常，不得重复启动抓取流程。

### 3.2 HCOLORS

```text
HCOLORS,c1,c2,direction
```

| 字段 | 含义 |
| --- | --- |
| `c1` | 当前 H 流程中的先到色 |
| `c2` | 当前停稳物料对应的后到色 |
| `direction` | `0`=顺时针，`1`=逆时针 |

颜色码为红 `1`、黄 `2`、蓝 `3`、绿 `4`。

### 3.3 MOVEXY

```text
MOVEXY,dx,dy
```

- STM32 执行车体双轴微调。
- 视觉端检测到实际位移后继续生成 `HDISC2`。
- `HDISC2` 是视觉定位终包，不保证 STM32 底盘运动已经完全结束。
- STM32 必须等待自身 `MOVEXY` 动作完成并且车体稳定后，再发送第 1 次 `C`。

### 3.4 HDISC2

```text
HDISC2,arrival,n,color,x,y[,color,x,y,...]
```

| 字段 | 含义 |
| --- | --- |
| `arrival` | `1`=到达 H 时未观察到运动，`0`=观察到运动后才定位 |
| `n` | 当前完整视野内的有效颜色数，范围 `0-4` |
| `color` | 红 `1`、黄 `2`、蓝 `3`、绿 `4` |
| `x,y` | MaixCAM 对外 `640×480` 坐标 |

颜色组按 `x` 从小到大排列。同色有多个目标时，只返回面积最大的一个。

示例：

```text
HDISC2,0,3,1,120,235,3,330,280,2,510,30
```

`arrival` 仅用于记录和故障诊断，不决定后续是否执行三次 `C`。

有效 `HDISC2` 校验条件：

- 前缀必须为 `HDISC2`。
- `arrival` 只能为 `0` 或 `1`。
- `n` 只能为 `0-4`。
- 字段总数必须为 `3 + 3*n`。
- 颜色码只能为 `1-4`，同一包内不能重复。
- 每组 `x/y` 必须为合法整数。

## 4. C 指令和回包

### 4.1 发送 C

```text
STM32 -> C,<color>
```

`color` 必须是任务码当前三件物料中的下一种颜色。

### 4.2 正常回复

```text
PICK,<color>,<x>,<y>
```

示例：

```text
C,3
PICK,3,286,274
```

C 任务会重新执行当前画面的物料定位，并等待目标颜色物料停稳后返回坐标。每次调用都会重新建立定位状态，不使用上一件物料的坐标作为本次结果。

STM32 必须检查：

- 前缀为 `PICK`。
- 返回颜色与本次请求的 `C` 参数完全一致。
- `x/y` 能解析为整数。
- 本轮只能执行一次抓取。

### 4.3 失败回复

```text
NONE,C
```

当前视觉端单次 C 任务上限约为 `20000 ms`。STM32 应等待正常 `PICK`、`NONE,C`、`BUSY` 或 `R/READY`，不能把一次通信超时直接解释为已抓取成功。

## 5. STM32 推荐状态机

```text
MATERIAL_SESSION_START
  -> 取得当前三色任务顺序
  -> 发送 H
  -> 保存 HCOLORS
  -> 执行 MOVEXY
  -> 等待底盘动作完成
  -> 等待 HDISC2
  -> 校验 HDISC2
  -> PICK_INDEX = 0

PICK_STEP
  -> 从任务顺序取 PICK_INDEX 对应颜色
  -> 发送 C,<color>
  -> 等待 PICK,<color>,x,y
  -> 使用本次 x,y 执行抓取
  -> 等待机械臂动作完成
  -> PICK_INDEX += 1
  -> PICK_INDEX < 3 时回到 PICK_STEP
  -> PICK_INDEX == 3 时进入 MATERIAL_SESSION_DONE
```

同一时间只允许存在一个视觉任务。上一任务没有终止包时，不发送下一命令。

## 6. BUSY、R 与异常处理

### 6.1 BUSY

视觉端为阻塞单线程。H 或 C 尚未结束时收到新命令，会返回：

```text
BUSY
```

STM32 收到 `BUSY` 后保持当前视觉任务状态，不重发 `H` 或 `C`，也不启动抓取。

### 6.2 R 中断

需要取消当前 H/C 会话时：

```text
STM32 -> R
MaixCAM -> READY
```

收到 `READY` 后清理 H 会话、当前抓取序号和临时坐标。

### 6.3 必须终止本轮的情况

- H 返回 `NONE,H`。
- H 返回 `ERR,...`。
- `HDISC2` 字段数量、颜色或整数格式非法。
- C 返回 `NONE,C`。
- `PICK` 返回颜色与请求颜色不一致。
- 任一 CRC 校验失败且重收后仍无效。
- 进程重启、READY 重新出现或通信链路中断。

以上任一情况都不得继续执行后续抓取。

`HDISC2` 中 `n=0` 表示 H 终包没有可用颜色坐标。默认应视为本轮 H 定位失败，不进入三次 C 抓取。若整机流程存在专门的旋转重试策略，应由 STM32 状态机显式处理并重新执行 H。

## 7. 通信帧与 I2C 分片

当前 MaixCAM 使用 GPIO I²C：

- SCL：`A1`
- SDA：`A0`
- 从机地址：`0x42`
- 最大时钟：`10 kHz`
- 每片数据：`32 Byte`

外层帧保持不变：

```text
AA 55 LEN payload CRC8 0D
```

CRC8 多项式为 `0x07`。

一条 `HDISC2`、`PICK` 或 `MSTATE` 可能跨多个 32 字节 I²C 分片。STM32 必须按 `LEN` 收齐整帧后再校验 CRC 和解析，不能把单个 32 字节分片直接交给文本解析器。

## 8. STM32 修改清单

1. 删除物料区“收到 HDISC2 后固定三轮 J”的状态。
2. 保留 HDISC2 解析，用于本轮 H 定位记录和诊断。
3. 从 `TASK` 的 `G1` 或 `G3` 中读取当前三色抓取顺序。
4. 三轮 J 改为三次串行 `C,<颜色码>`。
5. 每轮只接受颜色匹配的 `PICK,<颜色码>,x,y`。
6. 每件抓取使用本次 PICK 坐标。
7. 抓取机构完成后才发送下一次 C。
8. 物料区流程不再发送 J，不等待 MSTATE。
9. 保留 BUSY、R/READY、CRC 失败和进程重启处理。

## 9. 联调验收

1. 发送合法任务码，确认三次 C 的颜色顺序与 `G1` 或 `G3` 完全一致。
2. 确认一轮物料区只发送一次 H。
3. 确认 H 只产生一次有效 HCOLORS、一条 MOVEXY 和一个 HDISC2。
4. 确认收到 HDISC2 后没有发送 J。
5. 确认每次 C 都收到颜色匹配的 PICK，并且只抓取一次。
6. 在三件抓取之间转动或更换物料，确认每次都使用最新 PICK 坐标。
7. 模拟 `NONE,C`，确认停止后续抓取。
8. 模拟 BUSY，确认没有重复发送 H 或 C。
9. 在 H 或 C 过程中发送 R，确认收到 READY 并清理会话。
10. 构造跨多个 32 字节分片的 PICK 和 HDISC2，确认收齐后 CRC 校验成功。
