# 载物台提前选杯

2026-11-25 现场反馈后更新：从车载杯夹出物料时，下一杯改为在云台完成本次放料角的 PWM 插值与保持、且通过原离杯净空条件后再开始转动。下文记录的是变更前方案及当时的验证。地面抓回前选目标杯和原料放下松爪后换杯沿用原流程。

用户确认的目标是前移选杯指令，让载物台利用机械臂搬运时间转到目标杯位，减少机械臂回杯后的等待。本轮不改舵机角度、PWM插值时间、升降/平推速度、抓放高度或净空参数；不改任务码、J位置匹配、路线、驻车保持、取消或异常处理策略。

## 当前动作

| 作业 | 提前时机 |
|---|---|
| 两批粗加工从杯取料、第一批暂存 | 夹紧取出后，收臂的实际升降达到原125mm净空时开始选下一杯，与继续抬升/收回及地面放料并行。外侧环位的云台仍先高位收回再转向，不改变横扫顺序 |
| 两批粗加工从地面抓回 | 高位收回后，在转向地面抓取角时同时预选本次要放回的杯；伸出、下降、夹紧之前已经发完目标PWM，带物返回期间杯位保持 |
| 第二批暂存及使用直接带物转移的选杯步骤 | 选杯独立检查实际125mm净空，不再等待升到135mm及升顶后的200ms下降延时结束。云台/平推原110mm放行、真正到顶后才计下降延时的条件保留 |
| 原料区装车 | 原有放好松爪、达到净空后随机械臂回转切下一杯的流程保持；三块杯位1→2→3、末块回1不变 |

保持先放到当前杯并松爪，再离杯换下一杯；不能在夹爪或物块仍处于杯内时提前转。此处125mm沿用`ARM_CLEARANCE_MM`，不是新增标定值，也不能仅凭主机模型证明当前实物净空足够。

实现位置：`src/station_job.c`的`push_fixed_ring_contact`和固定环位调用点；`src/arm_control.c`的`platform_wait_clearance`、`lift_height_reached`及MOVING阶段PWM更新。`ARM_STATION_PRESELECT_ENABLED=0`保留取消工位预选的分支；关闭直转或升降联动时仍沿用既有顺序收回入口，在该入口中提前选杯。

## 验证

`tools/verify-platform-preselect.ps1`覆盖默认、关闭直转、关闭升降联动、关闭工位预选四种配置：

- 124mm时杯位PWM不变；实际125mm后，在未到顶之前已发完下一杯PWM；升顶后的下降延时仍有效，显式停止仍取消。
- 两批粗加工和第一批暂存的取料杯顺序、提前选下一杯、粗加工地面抓回前选目标杯，以及固定车身均保持。预选开启时，带物回杯过程中目标PWM不再改变。
- 第二批暂存仍逐目标请求F并允许原底盘索引，地面搬运期间提前选下一杯。
- 原料单块装车共三杯，松爪后才能换杯，反馈高度未达净空时不能转，最后回1号杯。

新增专项在修改前分别复现“125mm后仍未换杯”和“固定环位未提前选下一杯”的失败，修改后通过。PWM和编码器替身检查证明指令时序，不代表真实舵机已经转到位；载物台没有位置反馈，当前40ms插值不能当作实物到位证明。

原料四配置自动流程、J坐标定位、H/J、软件I²C、驻车保持、视觉微调和无自动故障停机专项通过。完整heading、arm-integration、旧fixed-ring脚本仍失败，且将本轮修改前`arm_control.c/station_job.c`与当前其它文件重新构建运行也在相同位置失败：

- `verify_entry.c:602`要求自动故障进入RUN_FAULT，与当前保留任务策略冲突。
- `verify_arm_integration.c:29`的硬编码旧姿态与当前实测参数不一致。
- `verify_station_fixed_ring.c:93`要求杯位平推40/放回高度100，当前实测值为35/110。

未调整这些旧断言。新固定工位专项读取当前标定参数并验证真实任务入口的杯位和时序，不能据此声称整个历史测试套件全绿。
