# 主转向提速与4号到位诊断

历史版本记录：2026-10-14的分段主转向策略。当前源码已改为连续速度控制，不再使用3600主转向或500 mm停车测角。请使用 [连续转向与直行航向闭环](连续转向与直行航向闭环.md)；以下参数和步骤仅用于旧版本追溯。

## 现场日志的结论

操作者提供的 `runimu A` 日志在第22个动作超时，`ack=15 ready=7`。四轮在该动作中各有71次有效状态回复；4号 `flags_dec=1 enabled=1 arrived=0 stalled=0 protected=0`，最近状态年龄131 ms。IMU同时 `uart_enabled=1 fresh=1 samples=3656 checksum_errors=0`。

因此这次停止是4号驱动器未置到位位，不能归为4号没回复或IMU没启用。程序没有扫码作业等待。操作者补充：轮子已停稳、车已到扫码位置。尚不能据此确定到位窗口、残留误差或驱动状态的具体原因；本轮没有修改驱动器参数，也没有绕过4号到位检查。

## 当前运动参数

| 项目 | 当前实现 |
|---|---|
| 左右90°前馈 | 3600脉冲，依据操作者两侧60 RPM下约90°的测量 |
| `runimu A/C` 主转向 | 60 RPM；90°先一次提交约3600脉冲，等待四轮完成后测角 |
| 主转向范围 | 剩余角度至少45°时采用主转向，单次最多90°；180°分成两次不超过90°的主动作 |
| 细修正 | 单次最多按10°计算，70%脉冲增益，转速不超过30 RPM；过冲可反向修正 |
| 独立定角 | `left90/right90/left180/right180` 共用上述策略，主转向遵守 `turn` 模式的 `rpm`；细修正取请求RPM与30的较小值 |
| 全程直行 | 90 RPM，`run` 和 `runimu` 均使用 `CAR_RUN_RPM` |
| `runimu` 直行检查 | 每500 mm停车测角，剩余不足500 mm时按剩余长度提交 |
| 保留条件 | 四轮ACK及新到位状态、IMU时效、稳定时间、±1.5°容差、15°偏航停止、动作和航向总时限 |

3600仅是闭环前馈初值，不代表单次脉冲已经证明90°。旧 `ccw90/cw90` 默认仍为0，旧 `run A/C` 仍要求自行标定；闭环命令使用 `runimu`。原始 `tl/tr` 的200脉冲和默认30 RPM保留。距离比例来自此前60 RPM标定，90 RPM下的真实距离、打滑、停止距离及速度提升需要复测。

`CAR_IMU_UART_ENABLED=1` 沿用操作者当前配置，USART2 PD5/PD6、115200、WIT角度帧。现场日志已证明当次有新角度；本轮没有独立量测接线、IMU精度和正负方向。

## 新增只读诊断

进入等待到位阶段后，每500 ms交替读取当前第一个未到位轮的位置误差 `S_PERR/0x37` 和实时速度 `S_VEL/0x35`。常规四轮状态查询保持25 ms间隔。额外诊断不要求应答，不改变状态查询的 `pending`，不会充当ACK或到位证明。CAN发送失败仍停止任务。

`feedback` 和故障输出新增字段：

| 字段 | 意义 |
|---|---|
| `error_valid` / `speed_valid` | 当前动作是否收到该项合法诊断；0时不能用数值下结论 |
| `error_counts` | 带符号的位置误差计数，65536计数对应电机一圈；这是编码器计数，不是位置控制脉冲数 |
| `speed_rpm` | 带符号的电机实时转速 |
| `error_age_ms` / `speed_age_ms` | 对应诊断的年龄；两项交替采集，不是同一时刻快照 |

协议依据[厂家Emm V5说明书](https://blog.csdn.net/zhangdatou666/article/details/132644047)及本地 `Emm_V5_Read_Sys_Params()`。例如误差-8计数约为电机轴-0.044°。`speed_rpm=0` 只代表速度反馈为零，不能单独放行下一动作。若4号仍超时，保留完整故障输出；结合误差、速度、到位位和现场现象再确定具体改法。不要先把到位窗口调大来掩盖未知原因。

## 现场操作

重新编译、下载并复位运行当前工程后，普通命令逐条带换行发送：

```text
!
turn
imu
rpm 60
left90
```

`imu` 应有 `fresh=1`；等待 `DONE_BY_IMU` 后再测试 `right90`。主转向日志应有 `phase=coarse`、`pulses=3600 rpm=60`；需要回修时出现 `phase=fine`，RPM不超过30。

测试全程时把车重新摆回真实A起点、车头沿场地+Y，再发 `runimu A`。`!` 只取消当前任务，不会把车送回起点，不能在扫码点直接重发全程。若仍停在扫码位置，先保存日志，再用 `feedback` 查看新增字段。

## 验证范围

电脑回归覆盖主转向3600脉冲、60→30 RPM细修正、较低请求RPM、左右90°/180°、过冲反向修正、±180°跨界、整圈A/C、4号未到位、诊断缺失/畸形报文、诊断不得满足ACK或状态查询、急停/超时及原有导航回归。ARM构建和源码哈希见[本轮验证记录](../evidence/chassis-history/主转向提速与到位诊断验证.json)。

本轮没有连接、烧录或驱动车辆。模拟路线时间不是实车成绩；4号停止后不报到位的根因仍待新诊断确认。
