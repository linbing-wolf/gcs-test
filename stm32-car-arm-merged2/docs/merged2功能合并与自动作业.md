## 现在能运行到哪里

**粗加工、暂存和从平台取料的姿态仍未标定。** `src/station_config.h` 中三个 `READY` 均保留0。实际自动流程会在D点执行粗加工动作之前故障停车，不会用 `{0,0,0}` 占位姿态执行。代码合并完成不代表整套机械动作已实车验收。

需要现场确认的配置：

- `STN_ROUGH_SLIDE_MM/LIFT_MM/YAW_DEG`：粗加工共用侧向抓放姿态；`STN_ROUGH_INDEX_*`：2号环基准、步距和方向。
- `stn_storage_place[5]`：暂存1～5号环位姿态；当前暂存流程使用前3个环位。
- `STN_PLATFORM_TAKE_*`：暂存区从车上杯位取物的原姿态表。粗加工取杯姿态复用当前 `ARM_PLACE_*`，两者都仍要求平台取料READY确认。
- 操作者2026-10-18提供：原料抓取为平推55mm、升降105mm、云台131°；放车载台为平推35mm、升降110mm、云台256°；夹紧15°、张开45°。已写入共用参数，完整自动动作路径仍需实车复核。

完成实际标定并验证路径后，才由操作者启用对应READY。粗加工按任务码物块顺序放下、按同序抓回，最后回2号环基准；解锁前应核对索引方向、杯位取料和碰撞间隙，不把编译通过当作实物动作已确认。

## 自动路线的准备与启动

串口为115200、8N1、无流控、文本发送。普通命令加换行；每一行单独发送并检查回复。`!` 不需换行。

1. 把车摆在实际A/C启停区，车头朝扫码区；确认 `imu` 新鲜、四轮反馈和CAN正常。
2. 发送 `arm on`，等待 `[arm interlock acquired: ...]`。没有四轮新零速/状态反馈，不放行机构。
3. 按机构**真实位置**声明姿态。只有平推确实收拢、升降确实最高且对应舵机姿态已确认时，才能使用下面的示例；这不是自动回零。

```text
arm pose 0 135 0 45
arm platform pose 20
arm status
```

这两条声明会提交舵机PWM，必须由现场操作者先核对真实姿态。底盘发车要求机构已声明且收拢、平台处于1号位、互锁有效。

4. 可提前输入两批任务码，也可在B点等扫码器输入：

```text
task 134+123+314+231
station
```

5. 保持机构会话，默认自动作业已开启，选择实际启停区：

```text
runimu A
```

或 `runimu C`。上电不会自动发车，扫码本身也不会启动整圈。B点先把车头转到−X（`STN_SCAN_HEADING=1`），让车尾扫码模块朝+X二维码板；航向对齐且四轮停稳后，才进入扫码任务等待。任务码有效后重新采集四轮反馈，直接衔接下一道路B→E；这段车头同样为−X，不再恢复进站前的航向。行驶中机构保持收拢；到站重新验证四轮停稳后才开始作业。

## 扫码与原料装车的动作顺序

- 扫码模块在车尾，B点转向控制的是车头方向−X，车尾朝+X二维码板。上电连续扫码模式保持启用；只有本轮首次B点任务等待时的扫码结果才交给任务解析器，行驶、转向及闲置期间只显示扫码结果。本轮新手输的预置任务仍可使用；转向停稳后有该任务即可继续。两批作业共用任务码，返程经过B不重扫；整轮完成或被急停/故障取消后清除，下轮需要新扫码或新手输。
- 原料区F点先完成底盘工位转向并验证四轮停稳，然后升降回135mm、平推收回0mm，云台转到 `ARM_PICK_YAW_DEG=131°`，夹爪张开45°。首块预定位按已声明姿态省略无变化的升降、平推和张爪步骤，减少不必要的预检及动作等待；若位置不同仍按先升降、再平推、再云台、最后张爪的顺序执行。云台步骤保留双轴新反馈预检及完整2秒插值，完成后才发出第一块颜色的视觉请求。此优化只用于首块预定位，不根据起始姿态省略后续取放或离站收拢动作。
- 视觉确认当前颜色位于固定取料口后，调用 `load1` 抓取；云台转到 `ARM_PLACE_YAW_DEG=256°`，放入当前载物台杯位。随后抬升、收回，云台返回131°并同时切到下一杯位；全部完成后才请求下一块颜色。按任务码顺序依次装满1、2、3号杯位，两批原料使用相同顺序。
- 三块全部完成后，机械臂回到升降135mm、平推0mm、云台 `ARM_YAW_HOME_DEG=0°`，平台回1号位，再恢复底盘行驶。识别失败或机构故障时停止，不跳过当前物块。

上述角度统一来自 `src/arm_config.h`，没有另写一套数值。r7云台/载物台按 `ARM_SERVO_TIME_MS=2000`、夹爪按 `ARM_CLAW_TIME_MS=500` 判断插值完成，没有舵机实际到位反馈。升降/平推目标速度为300RPM，仍逐步预检并验证ACK、位置、零速及状态；纯两轴步骤不再额外等待2秒。动作顺序保持先抬升、再收回、再旋转，实物是否夹牢、三杯是否装满仍需现场检查。

## 机械臂新命令

| 命令 | 作用 |
|---|---|
| `arm load1` | 从固定取料口装一块到当前杯位；抬起、收回后切换下一杯位，末尾回抓取预备角131° |
| `arm load3` / `arm load 3` / `arm cycle3` / `@` | 连续三块装车；从1号杯位开始，最后回收拢位、平台回1号位 |
| `arm status` | 查看使能、姿态声明、步骤、PWM，以及 `slot=1/2/3` |
| `arm home` | 回最高、收平推、云台0°；保持夹爪状态 |

手动 `load1/load3` 不等待视觉。只有自动原料工位会逐块先等视觉PICK再调用load1。它们没有夹持传感器，软件完成不代表物块夹牢或杯位正确。自动行驶/作业期间拒绝手动机构运动命令，避免抢占。

## 任务码

格式为 `G1+G2+G3+G4`，每组3位；也可连写12位。G1/G3是两批颜色，1红、2黄、3蓝、4绿；G2/G4是对应三块的粗加工目标环号，自动粗加工要求各为1/2/3的排列。解析器保留旧1～5输入兼容性，但含4/5或重复环位的批次在D动作前拒绝。例如：

```text
task 134+312+314+231
```

非法任务不会局部覆盖已存任务。`task 123` 仅供第一批颜色调试，第二批颜色为空，不能用它完整跑两批。`station` 显示自动开关、`task_ready` 和两批任务。XM1601收到完整CRLF扫码文本后，仅在本轮首次B点等待时交给同一个任务解析器。任务有效期覆盖两批作业及返程；整轮完成或取消后，`task_ready=0` 且两批颜色/环号归零，下一轮需重新输入。

## UART5视觉协议

接线：MCU PD2 RX接视觉端TX，MCU PC12 TX接视觉端RX，信号共地。115200、8N1。帧格式：

```text
AA 55 LEN payload CRC8 0D
```

LEN是payload字节数，最大48；CRC8多项式0x07、初值0x00，计算范围为LEN及payload。

| 方向/命令 | payload与行为 |
|---|---|
| MCU请求目标颜色 | `C,1` 等，颜色1～4 |
| 视觉确认目标已到固定取料口 | `PICK,1,x,y`，也兼容省略坐标的 `PICK,1` |
| 视觉尚未就绪 | `BUSY`，继续等待当前颜色 |
| `vision ping` | 发 `D`，最近回复在 `vision status` 中查看 |
| `vision range` | 发 `R`，不据此自动改变底盘或机构坐标 |
| `vision pick 1` | 手动请求；自动整圈中不允许抢占工位请求 |
| `vision clear` | 手动取消；自动整圈中由工位控制 |

x/y仅记录诊断，**不会据此动态追踪机械臂坐标**，仍使用固定取料口的已设姿态。只接受当前等待颜色的校验正确PICK；旧缓存、错颜色、非法坐标和坏帧不能触发抓取。RX溢出/UART错误使该请求故障。普通20秒超时按来源逻辑最多重发同色请求两次，然后停车，不会直接跳过该块。

本协议没有请求序号。虽然软件清空请求前的接收缓存，延迟到达的同色旧回复仍无法在协议层与新回复完全区分，需要视觉端保证回复对应当前固定口请求。此次未改动视觉端软件。

发送按UART TXE分次推进，视觉端不响应不会让主循环无限等待发完。UART5中断仍只有一个，仅入队字节/错误；解析在主循环进行。

## 停止、故障与互锁

- `!` 无需换行，全系统停止并取消工位/视觉请求，不自动恢复。
- `s/z/S/Z` 现在需要换行；原先立即识别首字母s会把 `station` 当成停止，因此在本版按完整命令识别。紧急停止继续使用 `!`。
- `arm stop` 在手动会话只停机构；在自动行驶或工位期间取消整圈并停车。
- 行驶期间发送 `obstacle` 仍先停稳、按编码器退回上一已记录节点并停等。当前没有自动障碍检测信号。
- 工位期间发送 `obstacle` 停止整个作业，**不会在机构伸出时自动倒车**。
- 任一轮缺反馈、非零速、堵转，或机构/IMU/CAN故障，都不能推进当前工位。行驶闭环与机构互锁互斥消费四轮队列，避免互相吞位置回复。
- 工位完成必须机构收拢，之后重新采四轮位置/速度/状态并校验航向，才可发出下一段行驶命令。

故障后先保存日志、检查车体与机构实际状态，再显式 `arm on` 重新检查四轮、重新声明真实姿态和平台角度，先小步验证。需要只跑底盘时，确认收拢并 `arm off`，再 `station auto off`；重跑整圈前摆回对应启停区。
