# XM1601上电连续扫码

更新：2026-10-16。操作者选择上电连续扫码、识别后输出结果，并提供P1接线图和XM1601手册附录D照片。

## 接线和串口

| 信号 | STM32 | 当前处理 |
|---|---|---|
| 扫码串口发送 | USART1 PB6 TX | 接模块RX，发送配置 |
| 扫码串口接收 | USART1 PB7 RX | 接模块TX，接收应答和扫码内容 |
| 低有效硬件触发 | PC0 | 开漏释放并上拉，保持高，不发低触发脉冲 |
| PC4、PC5 | 功能未确认 | 本轮不配置、不驱动 |
| 调试输出 | USART3 PB10 TX/PB11 RX | 115200、8N1，沿用原调试连接 |

扫码USART1暂按9600、8N1通信。该值是沿用项目旧串口示例的调试初值，模块当前实际波特率尚未确认；手册照片中的“设置115200”不是当前波特率证明。使用UART1 PB6/PB7初始化，不调用旧Serial_Init中的PA9/PA10配置。

## 上电行为

主循环等待约1000 ms后，按照片原始HEX字节依次发送：

1. 设置CRLF结束符：`7E 00 08 01 00 60 21 4B F0`。
2. 收到完整正确应答后，切连续模式：`7E 00 08 01 00 00 D6 DF 22`。
3. 第二步也收到完整正确应答后才输出：

```text
[scanner] CRLF acknowledged
[scanner] READY continuous acknowledged
```

两次应答均按照片核对为 `02 00 00 01 00 33 31`。该二进制应答不会当作二维码内容。每个配置阶段限时1000 ms，未应答/错误应答不进入READY，也不自动反复重发。

模块实际输出一条CRLF终止的扫码文本后，调试串口示例为：

```text
[scan] 134+123+314+231
```

支持跨多次中断接收和多条连续结果，不要求旧FF/FE包头包尾。单条内容最长126字节；超长、包含不支持的控制字节、串口错误或接收队列溢出时，丢弃受影响的半条内容，到下一次换行恢复，防止残缺内容被当成完整结果。当前以文本码为目标，不解析二进制载荷，不把内容用作串口控制命令或自动启动路线。

串口中断只收字节，主循环每轮最多处理32字节、在TXE允许时发送一个配置字节，无等待扫码的阻塞循环。PC9仍只打印开始按钮提示，电机、IMU、导航和原料区靠站逻辑未改。

## 现场操作

烧录当前完整固件并重新上电，保持原USART3调试连接115200。先观察是否出现READY，再对准已知二维码检查是否有`[scan]`。本轮没有连接、烧录或驱动实际车辆。

调试命令需回车：

| 命令 | 作用 |
|---|---|
| `qr` | 查看状态、当前STM32波特率、接收字节数、结果数及错误计数 |
| `qr init` | 按当前STM32波特率重新执行两步初始化 |
| `qr baud 115200` | 仅把STM32 USART1切到115200，再初始化；不修改模块波特率 |
| `qr baud 9600` | 仅把STM32 USART1切回9600，再初始化 |

这些运行时设置仅在RAM中，重新上电恢复car_config.h的CAR_SCANNER_UART_BAUD。若确认模块长期使用115200，可把该参数改为115200并重新编译。不会自动扫描波特率，不发送模块改波特率、Flash保存或恢复出厂命令。

若配置超时，先看`qr`的rx_bytes和uart_errors；核对TX/RX是否交叉、共地、供电和实际波特率。若9600无应答而确认模块用115200，发`qr baud 115200`。若已READY却始终没有扫码结果，还需要核对模块实际输出接口是否为TTL串口、码制设置、二维码和识读距离；当前手册照片未涵盖这些配置，不能臆造相关命令。READY只证明两个配置得到应答，不证明实际识读成功。
