## 当前行为

- 转向：记录受理命令时的实测航向，相对目标为±90°/±180°；转动中每个新IMU样本都更新角差与角速度，用PD计算轮速，接近目标时减速，过冲后允许反向低速修正。不再向闭环转向提交3600脉冲位置命令。
- 直行：整条道路几何段连续行驶，用同一个目标航向实时叠加旋转修正；不会把当前歪着的方向重设为正方向，不再每500 mm停车。单次几何段完成、换向、工位和最终返回阶段仍停车确认，本固定路线有18个平移几何段（发车与返程各1段横移、其余16段直行）。
- 行程：读取四轮 `0x36` 实际编码器位置，以选定前进/后退方向的投影平均计算距离，旋转修正项相消。剩余距离越小，行驶速度越低。距离达到容差后给零行驶速度，必要时继续小幅对齐车头，确认停稳后才推进。
- 完成：误差在±0.8°内、角速度不超过1°/s、至少3个新样本且稳定300 ms；还必须收到零速命令之后四轮新的低速/零速反馈并稳定300 ms。软件容差不是实车精度承诺。

`run A/C`、原始 `turn/pulses/tl/tr`、人工 `nav/go` 保留原位置模式。旧 `run A/C` 仍要求 `ccw90/cw90` 标定；新连续闭环命令不要求这两个脉冲值。IMU接收保持当前 `CAR_IMU_UART_ENABLED=1`，UART/引脚/波特率未改；没有写入IMU或电机的持久化配置。

## 为什么不再等待4号的位置到位位

现场最新日志在暂存区H的第42步，主转向后 `ack=15 ready=7`，4号持续回复、速度采样为0、位置误差-233编码器计数，但 `arrived=0`，尚未进入那次主转向后的细修正。

连续闭环使用速度模式，结束判据改为“IMU目标满足＋四轮新速度已停稳＋四轮状态正常”。位置模式的 `0x3A bit1 arrived` 不用于速度模式完成判定。这不是只等三个轮子：缺4号速度、编码器位置、状态或速度命令ACK，都会停止；4号非零速度、禁用、堵转/保护也会阻止完成。旧位置模式仍要求四轮位置到位位。

这解决的是控制模式与完成判据的匹配，不代表已经确认或修复4号原来的残留误差原因。驱动协议依据[厂家Emm V5说明书](https://blog.csdn.net/zhangdatou666/article/details/132644047)以及本地 `Emm_V5.c`。

## 调参入口

参数集中在 `src/car_config.h`，修改后完整重编译、下载、复位。

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `CAR_VELOCITY_CONTROL_MS` | 25 ms | 轮速控制目标周期；不是IMU的输出频率或硬实时保证 |
| `CAR_TURN_CLOSED_LOOP_RPM` | 60 RPM | `runimu` 转向上限；独立定角用 `turn` 模式的 `rpm` 上限 |
| `CAR_RUN_RPM` | 90 RPM | 全程直行上限，接近终点自动降低 |
| `CAR_HEADING_KP_X100` | 120 | 角度误差增益1.20 RPM/度 |
| `CAR_HEADING_KD_X100` | 30 | 角速度阻尼0.30 RPM/(度/秒) |
| `CAR_HEADING_MIN_RPM` | 3 RPM | 小角度修正最低速度初值 |
| `CAR_HEADING_DRIVE_TRIM_RPM` | 20 RPM | 直行旋转修正上限，同时限制在行驶速度绝对值以下，保持四轮沿选定前/后方向行驶 |
| `CAR_HEADING_TOLERANCE_CDEG` | 80 | 允许航向误差0.8° |
| `CAR_DISTANCE_KP_X100` | 50 | 剩余距离每1 mm对应0.50 RPM的前进速度 |
| `CAR_DISTANCE_TOLERANCE_MM` | 1 mm | 编码器距离完成容差，不是车身实际位置精度 |
| `CAR_DISTANCE_OVERRUN_MM` | 15 mm | 编码器距离超出目标15 mm则停止报错 |
| `CAR_VELOCITY_STOP_RPM` | 1 RPM | 四轮停稳速度阈值 |
| `CAR_VELOCITY_FEEDBACK_MS` | 300 ms | 四轮位置/速度/状态各自的新鲜度上限 |
| `CAR_VELOCITY_REPLY_MS` / `CAR_VELOCITY_ACK_MS` | 150 ms | 查询回复/四轮速度命令ACK时限 |

四轮按5 ms请求间隔依次查询实际位置、速度和状态，理想轮询周期约60 ms；每次仅一个查询在等待。每批四轮速度同步启动，必须先收到该批四轮ACK才允许下一批。持续不变的目标不会反复发送。控制实际周期受串口日志、反馈及主循环耗时影响。

每个新角度样本累计相邻角差，支持跨±180°，并保留左右180°指定方向。没有新角度时不伪造采样；超过250 ms停止。测试包含10/20/100 Hz模拟采样，但实际模块频率与延迟仍需现场核对。

编码器换算沿用旧距离标定的10.36脉冲/mm，并使用3200位置脉冲/圈、65536编码器计数/圈。四轮沿选定前/后方向的初始行程超过64计数后分别建立编码器方向，后续保持该方向做有符号投影，避免猜测CPOS正负和安装dir位之间的关系。任一轮始终不产生位置变化时不会仅靠其他三轮平均放行；被命令转动而位置超过1.5秒不变会停止。若实物不是原16细分或传动比已改变，必须重新核对换算。

## 首轮操作和日志

使用当前 `keil/TableNavigation.uvprojx` 重新编译、下载并复位。普通命令逐条带换行发送，关闭循环发送：

```text
!
turn
imu
rpm 30
left90
```

首次用30 RPM上限观察方向、减速、实际角度和停稳。出现 `DONE_BY_IMU` 后再测试 `right90`；确认后可用 `rpm 60` 重测。`!` 随时请求停车。故障后不自动重试、不中途续跑。

应看到 `control=continuous_velocity`，以及定期 `[control]`：

| 字段 | 含义 |
|---|---|
| `phase` | 0转向；1等待直行编码器基准；2连续直行；3终点停止/对齐 |
| `target_yaw_cdeg` / `yaw_cdeg` | 目标绝对航向和当前实测航向，单位0.01°，允许±180°跳变 |
| `error_cdeg` / `rate_cdeg_s` | 剩余角差/测量角速度；判断精度应看误差，不直接相减跨界的两个角度 |
| `distance_mm` / `target_mm` | 四轮编码器推算距离和当前几何段目标；转向阶段距离不适用 |
| `ack` / `fresh_mask` | 最近速度批次ACK及四轮位置/速度/状态新鲜度掩码；15代表四轮齐全 |

真正对齐后输出 `[heading aligned; four wheels stopped]` 并打印当时目标、实测和误差。若此时车头仍明显歪，保留该行及紧随的 `[control]`，需要核对初始基准、传感器安装/反馈与实车角度。若只出现故障，不能当成完成转向。

完整路线测试前重新摆回真实起点：右上区1、朝扫码区发 `runimu A`；右下区2、朝扫码区发 `runimu C`。两侧初始朝向分别是地图+Y和−Y，程序自动建立地图航向基准，返回后恢复本轮初始朝向。不要在暂停位置直接重发全程，也不要用 `pose/heading` 人工导航命令改变本模式目标。

## 验证与限制

当前电脑回归还覆盖16种车头/位移组合、前后退纠偏、A/C不同起始朝向、图面坐标物理重放及六次右侧工位朝向。原位置模式和CAN中断回归同时保留。当前源码、ARM构建和AXF/HEX一致性见[右侧夹爪朝向验证](../evidence/chassis-history/右侧夹爪工位朝向验证.json)；[地图与后退验证](../evidence/chassis-history/地图起点与后退验证.json)和[连续闭环验证](../evidence/chassis-history/连续航向闭环验证.json)为此前版本记录。

本轮没有连接、烧录或驱动车辆。PD参数、实际停车距离、转角精度、90 RPM下的真实行程及整场时间尚未实车验收。编码器推算仍受打滑和轮径差影响，IMU也有漂移；本控制保持航向，不提供场地XY绝对定位或横向路线回归。
