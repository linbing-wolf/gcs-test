# 合并范围与串口操作

> 本版默认接入自动到站作业、任务码、UART5视觉和 `arm load1/load3/@`，准备步骤、未标定边界及协议见 [merged2功能合并与自动作业](merged2功能合并与自动作业.md)。

> 旧 `run A/C`、`tl/tr`、`pulses`、`ccw90/cw90` 已移除，详见 [runimu全程入口与旧代码清理](runimu全程入口与旧代码清理.md)。当前本地版本20261019-merge2-r10支持同向直行节点连续通过，以及 `runimu` 中串口 `obstacle` 触发后退回上一已记录节点并停等，见 [连续直行与障碍退回](连续直行与障碍退回.md)。当前没有自动障碍检测输入，保留 `yaw_win` 诊断和你确认的3000速度配置。

r10只增加粗加工D的逐环放下/同序抓回：每次调用当前底盘闭环索引150mm，1↔3经2号分两段，最后回2号基准。原料区、暂存区、机械参数、路线及r9任务码有效期保持。粗加工姿态仍未标定、READY=0；配置和边界见 [粗加工环位作业合并](粗加工环位作业合并.md)。

r9任务码只对一整轮 `runimu A/C` 有效：第一批和第二批作业共用该任务，工位间交接及返程经过B均不清除、不重复要求扫码。完成两批并返回启停区、整轮完成时清空任务码；急停或故障取消本轮时也清空。下一轮可重新手输任务，或在首个B点等待重新扫码。扫码模块只有在首个B点扫码等待时才向任务解析器提交，闲置及整轮结束后的连续扫码只显示结果，不重新缓存旧任务。`station` 的 `task_ready=0`、两批 `colors=000 rings=000` 表示已失效；不影响同一轮两批作业的任务复用。

r8修复起步微小反向位置反馈可能锁错编码器方向的问题：每轮净位移至少2mm、连续两份不同时间且同向增长的位置反馈才确认方向；四轮全部确认前平移限20RPM，1.5秒仍未确认则故障停车。正常后输出 `[encoder directions confirmed] signs=...`。通过E不停时保留同一组基线和方向；F→E→D仍为860+810=1670mm。已确认方向的某轮若累计明显反向超过2mm，会输出 `[encoder direction conflict] wheel=...` 并停车，避免四轮平均时相互抵消。这些门槛是软件初值，不能代替实车超程原因确认。

## 来源和适配

底盘基线：本地 `stm32-car-test`，Git提交 `9d11dcc1777234704418172646a93b20d696c9ab`。远程来源：[test-code](https://github.com/linbing-wolf/gcs-test/tree/96f65d8e2469f1caeff2129cfebf98aa4daa9fca/test-code)，克隆提交 `96f65d8e2469f1caeff2129cfebf98aa4daa9fca`；采用其中当前 `main_armclaw.c` 的升降5、平推7、方向反转、行程比例、取放姿态及最新云台标定。原文件留在 `evidence/upstream-main_armclaw.c`，便于逐项对照。

远程目录中的每个 `main_*.c` 都是独立测试，不能一起编入一个工程。机械机构控制复用了本地独立测试模块已有的CAN反馈、非阻塞状态机和PWM插值，再加入最新参数、放载物台、完整取放和载物台档位。未修改原独立工程。随包驱动与底盘地图、距离比例、路线、查表数据保持基线字节一致。

原程序 `!` 表示夹取，合并后统一为急停；原 `@/$/W/7/8/9` 改成明确文本命令。原程序阻塞延时、开机假定位置和立即摆位不移入合并工程。r7两轴目标速度为300RPM、加速度150；只动升降/平推时按新鲜到位反馈完成，不再附加2秒舵机等待。云台及载物台保持2秒S曲线插值，夹爪使用0.5秒插值。提速后的实物运动、夹持及间隙仍需现场复核。

## 互锁和停止

`arm on`先要求底盘没有活动路线、待确认位置动作或导航流程，再下发四轮停车，轮询四轮的新使能/故障状态及零速反馈，连续保持200ms后启用5/7号机构电机。等待上限2秒，单项反馈时效500ms；缺少任一轮不能放行。此后每10ms查询一项轮状态/速度，持续监测四轮。非零速、失联、堵转、CAN错误或收包溢出会停止机构并请求底盘停车，锁仍保留，不自动恢复。

手动机构会话期间，`go`、模式切换、平移和转向等底盘命令均拒绝；自动 `runimu` 仅在机构已声明、收拢且平台为1号位时允许启动，行驶和工位独占地使用四轮CAN反馈。`info`、`imu`、`feedback`、扫码查询/配置及按钮更新继续运行。机械动作每步检查5/7号的新状态、零速、编码器基线，发出指令后检查ACK、到位、零速及有符号编码器位移；不以延时或一份旧到位标志推进。机构位置命令不使用广播同步，CAN回包按1～4和5/7分流。

`!`无需换行，提出底盘及机构停止请求；`s/z/S/Z`现在需要换行，避免 `station` 命令首字母触发停止；`!` 仍无需换行。`arm stop`在自动行驶/工位期间取消整个作业并停车；手动会话中仅停止机构。停止时保留最后PWM和步进使能，取消插值和序列，位置基准失效。舵机仍可能走向最后目标；软件命令不能代替实体断电。

全系统急停或底盘监测故障后，`arm status`显示互锁state=3。检查现场，显式 `arm on`重新验证四轮，随后按真实姿态重新 `arm pose`；载物台曾参与动作则重报 `arm platform pose`。不得根据旧账面位置盲目重跑。退出需要已完成的收拢姿态，`arm home`完成并检查后才可 `arm off`，再进入底盘。

## 命令

所有文本命令加换行；平推/升降用整数毫米，角度可带一位小数。保留 `!` 即时停止。

| 命令 | 作用和前置条件 |
|---|---|
| `arm on` | 申请独占，等待四轮反馈停稳；三路PWM仍关闭 |
| `arm status` / `arm` | 查看会话、位置基准、状态、步骤、命令坐标、PWM与互锁状态 |
| `arm pose P Z Y C` | 声明实际平推、升降、云台、夹爪位置；不移动两轴或清编码器，但会直接输出Y/C对应PWM |
| `arm slide N` | 平推到0～187mm；0为收回，187为继承的理论上限，未实测全行程 |
| `arm lift N` | 升降到0～135mm；135为最高处 |
| `arm yaw N` | 云台到−94.5～265.5度；超范围拒绝，不隐式取模跨端点 |
| `arm move P Z Y` | 同一步提交两轴及云台目标；一般调试优先单轴 |
| `arm open` / `claw open` | 开爪45度 |
| `arm close` / `claw close` | 合爪15度 |
| `claw angle N` | 夹爪角度0～270度，沿用1度安装偏移 |
| `arm pick` | 从0/135/0姿态五步夹取：开爪→云台131→高位伸55→降105→合爪15°；结束保持夹住 |
| `arm place` | 保持夹持，升135→收0→云台256→伸35→降110→开爪45°；要求已声明载物台角度 |
| `arm cycle` | 回收拢位→夹取→放载物台；过程会开爪，手里已有物块时用单独 `arm place` |
| `arm home` | 先升135→收0→云台0；保持夹爪状态，不自动松爪 |
| `arm platform pose DEG` | 声明载物台当前实际角度0～270；立即写PA2 PWM，不自动寻找原点 |
| `arm platform 1/2/3` | 切换20/139/256度档位；必须已声明平台角度且机构在0/135/0收拢位 |
| `arm stop` | 停止机构，保持PWM与步进使能，位置基准失效 |
| `arm off` | 收拢后退出独占并关闭全部舵机PWM；5/7保留使能；可能失去夹爪保持力 |

`arm pick red/green/blue`保留为同一个夹取姿态的兼容别名，不会选择不同物块。平台档位来自随包 `PWM.c`，不是本轮新测量。`arm place`只往当前平台位置放，不自动轮换档位。

首次只在实际处于收回0、最高135、云台0、夹爪45时使用：

```text
arm on
arm status
arm pose 0 135 0 45
arm slide 1
arm slide 0
arm lift 130
arm lift 135
```

逐条等待 `arm done`、观察实物后再发下一条。确认小步方向和反馈后，才能试 `arm pick`。云台0/131/256度输出约1975/1247/553us，夹爪开45°/合15°约826/604us。重新声明云台0的PWM1975us与旧独立工程的1586us不同，不混用标尺。

放平台前，只有平台实际在20度初始档时才声明 `arm platform pose 20`，然后 `arm place`。机构恢复 `arm home`后可旋转平台，再进行下一次操作。所有步骤需现场确认无干涉，`arm done`只证明两轴反馈条件和PWM插值完成，没有舵机位置或夹持传感器。

## 保留的云台全行程诊断

`arm yawtest init 实际脉宽`（500～2500us）直接声明并输出云台PWM；`arm yawtest 0..360`用8秒插值扫描，其中0→2500us、360→500us。测试刻度94.5约对应当前云台初始0度/1975us。该功能保持夹爪和平台PWM，不依赖5/7反馈，仍要求底盘四轮互锁和会话有效。诊断完成不恢复两轴位置基准。不要把 `arm yawtest 0` 当作云台初始位。

## 验证边界

本次记录在 `evidence/current-validation.json`。电脑测试覆盖底盘原有行为、最新PWM换算、两轴运动、取放次序、三档平台、互锁、停止、时钟回绕、四轮和机械两轴故障；ARM构建及AXF/HEX核对仅证明可生成匹配固件。未连接、烧录或运行真实硬件，仍需验证反馈极性/协议、PWM波形、真实角度、夹持、行程、碰撞间隙、急停制动和带载表现。A/C路线仍不执行工位动作，归位偏差问题沿用原底盘待排查状态。
