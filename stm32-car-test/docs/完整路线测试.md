# 完整路线单条命令

本版仅测试完整作业的行车路线，不执行扫码、抓放或工位停留，不考虑障碍物。任务顺序为：启停区 → 扫码 B → 原料① F → 粗加工① D → 暂存① H → 原料② F → 粗加工② D → 暂存② H → 原启停区。

## 下载后直接启动

1. 下载本版 `keil/OBJ/table_navigation.axf`，复位并运行。
2. 放置到对应启停区模型起点，车头沿场地 +Y；整个路线不旋转车身。A=(2250,170)、C=(2250,2230)，单位 mm，坐标沿用 `road_map.c`。+Y 是 A 区朝扫码区的总体方向；C 区启动时仍朝 +Y，第一条道路先左移 60 mm，再后退 1030 mm。模型起点不是启停区任意停车位置。
3. VOFA 文本模式，115200、8N1，普通命令末尾附加换行，关闭循环发送。
4. 从启停区1 A 开始，单独发送：

```text
run A
```

从启停区2 C 开始则发送 `run C`。命令声明你已实际摆到指定起点并对齐朝向，固定使用 60 RPM、加速度档位 150。无需先发 pose、heading、rpm，也不需要途中发送 confirm 或 node。

发送 `info` 可查询进度；发送 `!` 请求停车。停止或故障后不会自动恢复，需要检查车辆并重新摆回对应起点后再次启动。`test`、`nav` 也会中止全程并切换模式；运行中其他运动或参数命令拒绝。

## 自动推进的依据

每段先提交四轮相对位置命令并同步启动，要求四个位置命令的接收确认。首次到位查询在估时经过后开始，但只有四轮返回的新到位状态才推进；没有回复或回复未到位时，不用等待时间替代实际反馈。查询间隔至少 25 ms，每次只等待一个电机；状态回复超时 1000 ms、位置 ACK 超时 1500 ms 或原运动超时会请求停车。这里的查询与电机启停过程不是作业区等待。

协议依据：[张大头 Emm_V5.0 官方说明书 Rev1.3](https://blog.csdn.net/zhangdatou666/article/details/132644047)。位置命令正常确认使用 FD/02，状态查询使用 3A；状态位分别表示使能、到位、堵转和堵转保护。CAN 短帧按当前驱动的地址扩展 ID 和功能码格式解析。需要四个驱动器均允许返回位置命令接收确认；本程序不修改其永久配置。

`[run] ack=15` 表示四个位置命令均收到 ACK，`ready=15` 表示本轮查询四轮均满足条件；PREFLIGHT 的 ready 只代表使能且无堵转，MOVING 的 ready 还要求到位。`pending=1..4` 是当前等待回复的电机地址。若出现 `missing motor position ACK` 或 `motor status reply timeout`，先检查对应电机与 CAN，不重复启动。

## 位置与实车限制

结束显示 `DONE_BY_MOTOR`，表示电机反馈支持完成全部指令，不等于真实车身准确停在启停区。全程不借用人工节点确认；`node_est` 是根据已执行命令推算的节点，真实位置始终为 `physical_pose=unconfirmed`。应现场检查返回位置、横移偏斜和累计误差。

左右距离比例和左20/右8 mm/m 的向前预补偿继续生效；其物理效果仍需要验证。没有摄像头、IMU 或整车定位反馈，不会主动检测本次被忽略的障碍物。当前构建和模拟 CAN 行为检查不代表整车全程已通过。
