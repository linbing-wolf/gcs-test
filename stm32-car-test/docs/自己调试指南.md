# 自己调试从哪里开始

先打开 `src/car_config.h`。Keil 工程树新增 **CarConfig** 分组，可以直接打开参数、道路结构表、完整路线三个头文件。当前默认参数与整理前一致。

## 调参入口

| 想改什么 | 配置项 | 当前值 |
|---|---|---:|
| 单段 f/b/l/r 默认速度 | `CAR_TEST_RPM` | 60 RPM |
| run/runimu 完整路线直行速度 | `CAR_RUN_RPM` | 90 RPM |
| 人工导航道路表默认速度 | `CAR_ROAD_DEFAULT_RPM` | 100 RPM |
| 默认运动加速度档位 | `CAR_MOTION_ACCELERATION` | 150 |
| 单段默认距离 | `CAR_TEST_DISTANCE_MM` | 1000 mm |
| 左右脉冲/mm | `CALIBRATED_PPM_X` | 11.052632 |
| 前后脉冲/mm | `CALIBRATED_PPM_Y` | 10.36 |
| 左移时向前预补偿 | `LEFT_FORWARD_MM_PER_M` | 20 mm/m |
| 右移时向前预补偿 | `RIGHT_FORWARD_MM_PER_M` | 8 mm/m |

三个速度入口分开管理：串口 `rpm` 可以改标定或人工导航速度，**不会改 run 全程速度**。全程会用 `CAR_RUN_RPM` 覆盖道路表速度。速度范围仍为20～300 RPM，标定距离范围仍为50～2000 mm；150是驱动器加速度档位，不是mm/s²。

例如要把全程速度改为80，只改 `CAR_RUN_RPM` 为80，保存、完整重编译、下载当前AXF、复位运行，再发送 `run A`。不用顺带修改其他速度。修改宏在编译后生效，串口参数只在本次运行中保存。

一次只改一个参数并记录结果。左移仍往后偏时，可只把左移预补偿20改为25；变成往前偏时就减小。设为0关闭对应方向预补偿。距离换算按 `新比例 = 旧比例 × 目标距离 / 实测平均距离` 调整；它不能自动消除车头旋转或随机抖动。

## 道路和路线

- `structure.h`：24条有向道路，每条先写起终点，再逐行列出动作。例如A→B先左移60 mm，再前进1030 mm。
- 一段参数顺序是 `{方向轴, 带符号的距离毫米, RPM, 加速度档位}`。`BODY_FORWARD`正为前进、负为后退；`BODY_LEFT`正为左移、负为右移。
- 某段需要独立速度时，可把该段的速度宏替换成数值。人工导航 `rpm 0` 才使用表内速度；当前完整路线仍覆盖为全程速度。
- `full_route.h`：A/C两条无障碍路线和八个任务点。修改道路几何会影响最优性与查表，不用改道路长度代替脉冲/mm标定。
- 方向以车头+Y为基准。人工导航可按heading换算，全程固定+Y且不旋转车身。

## 查流程和找断点

`main_table_nav.c` 已按编号分为状态、CAN接收、串口/计时、电机接口、全程、命令、主循环、硬件启动。搜索函数名即可定位：

| 函数 | 用途 |
|---|---|
| `main()` | 硬件初始化，上电不自动跑路线 |
| `firmware_step()` | 停车优先，处理一个串口字节，再推进当前模式 |
| `command()` | 解析 info/test/run/go 等完整命令 |
| `start_test()` | 把 f/b/l/r 转成单段参数 |
| `start_run()` | 启动全程，进入四轮状态检查 |
| `run_segment()` | 提交当前段，在这里覆盖全程速度 |
| `run_update()` | 收CAN → 查故障 → 等ACK → 查到位 → 下一段/道路 |
| `motion_start()`，在motion.c | 毫米换脉冲、叠加预补偿、算各轮RPM、同步启动 |
| `motion_update()`，在motion.c | 处理估时和超时，不单独证明到位 |
| `nav_update()`，在navigation.c | 人工查表导航和confirm/node分段推进 |

`motion.c` 中的q/t缩写已改成 `pulse_count`、`ramp_pulses`、`ramp_time_ms`、`estimated_time_ms`，公式不变。头文件和全程状态字段补充了中文含义与单位。

## Keil Watch 看什么

先发 `info` 看回传。断点调试前先发 `!` 并确认车辆实际停稳；暂停MCU不等同于给独立电机驱动器发送停车命令。用当前重编译的AXF，保证调试行号与源码对应。

| 变量 | 含义 |
|---|---|
| `clock_ms`、`stop_pending` | 系统计时、待处理停车请求 |
| `test_mode`、`test_distance`、`test_rpm` | 标定是否启用、距离、速度 |
| `drive.state`、`drive.parameters` | 当前段状态、实际提交参数；枚举解释在motion.h |
| `drive.pulses`、`drive.forward_trim_mm` | 基础脉冲、本段前移补偿；各轮脉冲可能不同 |
| `nav.state`、`nav.error` | 人工导航状态和错误；枚举解释在navigation.h |
| `run.state`、`run.steps` | 全程状态、已提交段数，正常全程18段 |
| `run.edge`、`run.segment` | 节点表位置、道路内部段下标，从0开始 |
| `run.acks` | 四轮位置命令ACK位图，15表示全收到，不表示到位 |
| `run.ready` | PREFLIGHT是使能且无堵转；MOVING还要求到位，15表示全满足 |
| `run.pending` | 正在等回复的电机地址1～4；0表示无等待 |
| `run.job`、`run.distance_mm` | 理论任务点计数、已提交理论距离，不是抓放成功数或实测行程 |

ACK不齐先查CAN和电机应答设置；pending卡在某地址先查该电机状态回复，不先一味加大超时。详细现象见 [命令与故障排查](命令与故障排查.md)。全程真实车身位置仍为unconfirmed，本轮整理不新增实车验收。
