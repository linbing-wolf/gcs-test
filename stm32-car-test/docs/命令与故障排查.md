# 串口命令与故障排查

普通命令每条末尾发送 `\n`，命令小写，节点 A～I 大写。标定版会去掉整条命令首尾的空格和制表符；命令内部格式仍需正确。逐条发送并检查回传。

## 命令

| 命令 | 作用和条件 |
|---|---|
| `info` | 输出当前导航状态；任何状态下可查询 |
| `help` | 打印命令帮助 |
| `run A` / `run C` | 完整路线测试：声明实际放在对应启停区且车头 +Y；固定 60 RPM、无障碍路线、无工位动作和等待。自动读取电机 ACK 和到位反馈，`!` 可中止；详见 `完整路线测试.md` |
| `test` | 请求停车并进入单段标定；默认 1000 mm、60 rpm、加速度档位 150；导航位置确认失效 |
| `nav` | 请求停车并回到导航；重新确认真实起点和朝向后才能 `go` |
| `dist 1000` | 标定模式设置 50～2000 mm 距离；移动中拒绝 |
| `f` / `b` / `l` / `r` | 标定模式的前进/后退/左移/右移；每次只执行一段，移动中重复会拒绝；下次按键是操作者主动开始新试验 |
| `!` | 请求停车，无需换行；随后处理并清空待处理输入 |
| `pose A` | 停止状态下确认当前位置，并清除导航错误；正式路线必须是真实节点 |
| `heading 0` | +Y；只声明实际车头朝向，不会自动旋转车身 |
| `heading 1/2/3` | 分别为 −X、−Y、+X；命令写成如 `heading 1` |
| `rpm 20..300` | 标定模式修改下一次试验速度，独立于导航速度；导航模式覆盖后续路线速度 |
| `rpm 0` | 仅导航模式：恢复按 `structure.h` 中各段速度执行；标定模式拒绝 |
| `go B` | 已确认起点后，查表并启动去 B 的运动 |
| `confirm` | 实际完成且处于等待确认时，确认当前段；有下一段就立即启动 |
| `node B` | 整条道路所有段确认后，实际确认已到 B；多道路任务可能立即启动下一条道路 |
| `obstacle` | 运动中停车、封禁当前道路，进入等待实际返回确认 |
| `return A` | 确认真实返回当前道路起点后重新规划；不是自动倒车命令 |
| `block 0..11`、`unblock 0..11` | 设置/解除指定道路封禁；如 `block 3` |
| `progress 100` | 报告人工/外部测得的当前段进度（mm）；不会驱动车辆，也不代替完成确认 |

道路位序：0 AB、1 BC、2 CD、3 DI、4 HI、5 GH、6 FG、7 AF、8 EF、9 DE、10 EH、11 BE。

## 现象 → 证据 → 下一步

| 现象 | 不能直接推出什么 | 检查顺序 |
|---|---|---|
| 只有发送内容，没有 `[nav]` 回复 | 不能认定电机或 CAN 有问题 | 端口、115200/8N1、实际交叉接线、共地、程序是否真正运行 |
| VOFA 红字“已中止 I/O 操作” | 不能仅凭这条消息断定是接线、复位或代码造成 | 关闭旧连接、刷新并重新选实际端口、打开连接、只发 `info` |
| `[rejected: command/state/confirmation]` | 不是 CAN 驱动器故障反馈 | 检查是否处于导航模式、节点大小写、先 `pose` 是否成功、当前状态是否允许命令 |
| `[rejected: test command/range/busy/heading unavailable]` | 不代表 CAN 已发送失败 | 标定模式只接受方向键、dist、rpm；检查范围，运行中不重复启动或改参数 |
| `[test timeout/failure: stop requested ...]` | 不确认已经到位或已实际停稳 | 检查实车；未自然完成的这一轮不用于距离标定。软件回到 READY，但不会自动再次启动 |
| `[accepted]`、`[segment]`，但车不动 | 这两行只表示软件接受并提交指令 | 实际电机电源、CAN 收发器 VCC/GND、PA12→TX 与 PA11←RX、H/L、波特率与驱动器状态 |
| `FAULT ... error=3` | 不是电机返回的错误码 | 当前映射为 `NAV_MOTION_FAILED`；可能是执行提交失败或等待超时。本轮曾因未人工确认而超时 |
| 停车后仍 `error=3` | `!` 不自动清除上一次导航错误 | 车摆到已知起点，重新 `pose`，再检查 `info` |
| 下载显示 Verify OK，却没有启动串口 | 下载成功不等于主程序已运行 | 下载后复位并 Run；本轮曾读到 CPU 在 RAM 的 `0x20000000` |
| `[run fault] missing motor position ACK` | 不能当作电机已经收到位置命令 | 核对四个电机、CAN 和驱动器 Response 设置是否允许回复位置命令接收确认；不自动修改驱动器设置 |
| `[run fault] motor status reply timeout` | 不能把估时经过当作已经到位 | 观察 `info` 的 pending 地址，核对该驱动器供电、CAN 和 0x3A 状态回复 |
| `[run] DONE_BY_MOTOR` | 电机到位不等于车身准确回到启停区 | 现场检查真实位置与方向，软件位置仍标为 unconfirmed |

## 本对话已遇到的问题

1. 板上旧固件的 USART3 中断入口与 PB10/PB11 版本不一致。后来用正确的 `table_navigation.axf` 下载并核对入口。
2. 下载后 CPU 曾留在 RAM 的烧录辅助代码中；软件复位后 VTOR 指向 Flash，USART3 启用、计时增长。
3. CAN 曾出现 Bus-Off、发送错误计数 248、最近错误为位显性错误。这证明通信失败，但不能仅凭寄存器确定是哪根线或哪个器件造成。
4. 确认收发器供电及重启后，本次记录 CAN 错误为零，并收到地址 4 的 `F3 02 6B` 回帧。
5. 2026-10-12 后续测试实际收到 ` pose A`，开头有空格，起点没有确认。修正输入后，操作者报告 `go B` 正常运动。

上述是旧版的历史观察。2026-10-13 标定入口已新增首尾空白处理、四方向单段命令和模式隔离，实车效果仍待下载新固件后验证。标定模式不接受 `confirm`，不把估时当作到位。

若需软件查看 CAN 寄存器，新电脑上的下载器连接方式和脚本应另行核对。本包不带此前未稳定通过的 pyOCD 批量烧录脚本，也不运行后台串口监听。
