# 上下通道内移90与50毫米

更新：2026-10-17。按操作者实测，上方AG沿线向中部移90 mm，下方CI沿线向中部移50 mm。移动的是车辆中心行驶/停靠点，实际工位没有移动。

## 当前坐标与距离

图面X向右、Y向下，单位mm。A/C实际启停点及B/E/H保持原位。

| 节点 | 原坐标 | 当前车辆中心坐标 |
|---|---|---|
| F 原料 | (1200,200) | (1200,290) |
| G 上方左侧 | (340,200) | (340,290) |
| D 粗加工 | (1200,2060) | (1200,2010) |
| I 下方左侧 | (340,2060) | (340,2010) |

双向道路使用同一参数，坐标、运动段及长度一并更新：

| 双向道路 | 原长度 | 当前长度 |
|---|---|---|
| E↔F、H↔G | 1000 | 910 |
| E↔D、H↔I | 860 | 810 |
| A↔F | 1080 | 1170 |
| C↔D | 1220 | 1270 |

A↔F的启停连接段由30变为120 mm，C↔D连接段由170变为220 mm，启停点不会随通道移动。其他6组双向道路不变。两条整圈的节点、任务顺序和18个直行段不变，总长由15040变为14480 mm。

F车头向左、D向右、H向下，右侧朝作业区并确认IMU及四轮停稳后才计工位进度。后退仍只允许本轮已完整走过且位于正后方的道路；当前固定路线仍22次转向、0段倒车。按钮、扫码、IMU及电机控制参数保留。

## 修改偏移量

两个参数在src/car_config.h：

```c
#define CAR_MAP_TOP_INSET_MM         90
#define CAR_MAP_BOTTOM_INSET_MM      50
```

修改后，在包根目录依次执行，再用Keil编译：

```powershell
.\tools\rebuild-route-table.ps1
.\tools\verify-heading.ps1 -Gcc C:/msys64/ucrt64/bin/gcc.exe
```

地图重生成工具需要Node和GCC，可用脚本参数指定路径；普通Keil编译已配套的源码不需要这些工具。工具从实际编译的road_map.c/structure.h导出9点12路，核对24个方向的端点、长度和逆向动作，复用原查表生成算法，不读取历史mcu-distance/map.h。

lookup/generation.json绑定参数、节点、道路、源文件和表哈希。check-package.ps1检查表是否匹配当前几何；查表编译单元也核对偏移常量，只改偏移量不重生成会报Map_inset_changed_rebuild_route_table_first。速度等无关参数调整不要求重生成地图。C查表API及板上只查常量表的方式不变，Dijkstra只用于电脑验证。

## 验证与现场范围

新表通过531441种状态、43046721次查询，与现有C基准算法精确一致，并通过独立Floyd距离/未走道路优先核对。A/C两条整圈均回到原启停点，满足两批六次右侧工位朝向，原位置模式、按钮、扫码、反馈及急停回归也通过。当前源码、ARM构建与固件哈希见 [上下通道内移验证](../evidence/上下通道内移验证.json)。

本轮没有烧录或驱动车辆。偏移量来自操作者实测，电脑测试验证路线一致性，不证明整车外廓、夹爪及转向扫过范围已避开所有禁区。现场从原A/C点重新摆车，沿用runimu A/C，核对直行、到站转向和夹爪伸出时的余量；F/D离工位更远，也需确认夹爪工作距离。
