## 2. 自己电脑需要什么

- Keil µVision 5，能够编译和链接本固件约 402.61 KiB 的 Flash 数据（412272 字节）。
- ARM Compiler 5。本机确认过 **5.06 update 5（build 528）**；不要直接把这个工程切到 Compiler 6。
- STM32F4 器件支持包：本机使用 **Keil.STM32F4xx_DFP 3.1.1**。
- 实际下载器及其驱动；目前工程预设 CMSIS-DAP，换成其他下载器时在当前工程中重新选择。
- VOFA 或其他可收发文本的串口工具。

普通编译、下载、测试不需要 Node、Python、GCC、pyOCD，也不依赖原电脑的 `D:/keil5` 路径。若提示缺少指定 Compiler 5 版本，在 Options for Target → Target 中选择自己实际安装的 Compiler 5，再重新编译。

## 3. 接线

### 调试串口：115200，8N1，无流控

| 串口端 | 核心板 |
|---|---|
| TX | PB11，USART3_RX |
| RX | PB10，USART3_TX |
| GND | GND |

使用适合 3.3V 逻辑信号的接口。下载器的 SWD 接线和串口接线是两条通信路径；COM 号以新电脑识别结果为准，不能固定认为是 COM12。

### CAN：CAN1，500 kbit/s，扩展帧

| 核心板 | CAN 收发器 |
|---|---|
| PA12，CAN_TX | TX / TXD |
| PA11，CAN_RX | RX / RXD |
| GND | GND |

收发器 H 接电机 CAN_H，L 接电机 CAN_L；电机地址沿用 1、2、3、4。收发器、核心板和电机电源负极应共地。电机电源按实际驱动器要求供给。

**队友资料中使用的 VP230 是 3.3V 模块，VCC 必须接 3.3V。** 不把这一要求推广到未知型号模块，也不能把这款 VP230 的 VCC 接到 5V。断电接线；若从板上 VCC3.3 取电，先测量它对 GND 实际约为 3.3V。仅有 PCB 网络标签不能证明插座已供电。

## 4. 编译、下载并真正启动

1. 将整个目录放在自己的电脑上，例如 `D:/STM32_Car/stm32-car-test/`。打开其中的 `keil/TableNavigation.uvprojx`，目标是 `TableNavigation`。
2. 在 Project → Rebuild all target files 执行完整重编译。检查完整输出和最终汇总：必须为 `0 Error(s)`。原驱动存在一些编译警告；本轮完整重编译的数量见 [验证状态](docs/验证状态.md)。
3. 编译结果在 `keil/OBJ/table_navigation.axf`、`table_navigation.hex`。目录中附带的固件只作当前版本参考；源码改过就下载自己刚编译的结果。
4. Options for Target → Debug 选择实际下载器；当前配置是 CMSIS-DAP、SWD。确认芯片为 STM32F407ZG，Flash 算法覆盖 `0x08000000` 开始的 1 MiB。
5. 在 Flash Download 设置中启用 Erase、Program、Verify。通过 Keil Download 下载；应看到 `Erase Done`、`Programming Done`、`Verify OK`。不要运行旧 `Template` 工程或历史计时工程。
6. **下载后必须让核心板复位并运行。** 下载完成不一定已经进入应用程序。本次曾出现 CPU 留在 RAM 烧录辅助代码中：解决后才启用了 USART3。可在下载设置中选择 Reset and Run；若进入调试后停在 main，点击 Run（F5）。确认正在运行后再操作串口。新版本启动标题应为 `table navigation + pulse turn calibration + turn/forward full route`。按不到实体复位按钮也可使用 Keil 软件复位；本包不带自动复位或烧录脚本。
7. 打开 VOFA，选择实际端口；115200、8 数据位、1 停止位、无校验、无流控。使用 RawData、文本发送，末尾选择 `\n`，关闭循环发送。
8. 发送一次 `info`，确认真正收到 `[nav] ...` 回复。软件自己的蓝色发送显示不算板子回传。开机不会自动执行路线，会提交停车和电机使能命令。

本工程关闭了“进入调试前自动更新 Flash”。将程序下载并启动是操作者的明确操作。

## 5. 标定模式：第一轮只检查左移 60 mm

完整路线连续闭环：右上启停区1发送 `runimu A`，右下启停区2发送 `runimu C`，均将车头朝扫码区摆好并确认新IMU角度。速度模式要求四轮速度命令ACK、位置/速度/状态和IMU停稳。旧 `run A/C` 仍需左右脉冲标定，保留原初始+Y约定，默认直行90 RPM、旧旋转30 RPM；详见 [完整路线单条命令](docs/完整路线测试.md)。本版不执行工位动作或作业等待。查表导航的人工 `confirm/node` 机制保持不变。

在空地标记起点和车头朝向。标定模式以车身自身的前后左右为准，不使用 A～I 节点、路线或 `heading`。正式场地导航仍须确认真实节点。

逐条发送，普通命令末尾保留换行。新版本会去掉整条命令首尾的空格和制表符：

```text
test
dist 60
rpm 30
l
```

`test`、`dist`、`rpm` 应分别回复 `[accepted]`；`l/r` 应进入 `[shift closed-loop]`，以IMU和编码器连续控制，完成报告 `DONE_BY_IMU_ENCODER`，不自动启动下一段。`f/b` 仍是单次相对位置运动，两种方式的完成条件不同。

`l/r` 等待闭环完成和四轮停稳，再测量、摆回起点并发送下一次命令；缺少新鲜IMU会拒绝启动。`f/b` 仍需操作者观察实际停稳，估时提示不代表到位。运动期间重复方向键会被拒绝。

随时可发送 `!` 请求停止，标定距离和速度保留。`f/b` 保留 `估时×3+5000ms` 的等待上限；`l/r` 使用连续控制的超时及反馈新鲜度保护，详见 [横移闭环与发车](docs/横移闭环与发车.md)。超时或手动打断不算完整距离的标定结果。

`confirm`、`go`、`pose` 等导航命令在标定模式中会被拒绝。发送 `nav` 切回查表导航会先请求停车，并要求重新确认实际起点和车头朝向。

如果车辆不动，先解决该问题，不开始误差标定。2026-10-12 已有操作者确认此短段正常运动，但没有记录实测毫米数。

## 6. 前进、后退、左移、右移误差测试

### 固定测试条件

- 保持相同地面、负载和车头朝向。地上标记起点和直线，选车身同一个固定点作为测量基准。
- 车头始终沿你选定的前方；标定模式不需要 `heading`，不必朝地理北方。
- 测后退和左右移时，**不转动车身**。每次测试后把车搬回标记起点，不用倒车返回来建立下一次起点。
- 当前建议速度 **60 rpm**，加速度沿用参数表的 150。若尚未完成短段动作检查，先按上一节使用 30 rpm。
- 标定模式默认 `dist=1000`、`rpm=60`、`acc=150`，距离范围 50～2000 mm，速度范围 20～300 rpm。配置只保存在本次运行中，重新启动恢复上述默认值。
- 标定速度和导航速度分开保存。在标定模式中 `rpm 0` 无效；切回导航后 `rpm 0` 使用表内速度，当前表内默认仍是 100 rpm。
- 每方向重复 3～5 次。同一组记录使用相同速度。

### 每次的操作

先配置一次：

```text
test
dist 1000
rpm 30
```

然后每次只发送下表中的一个方向命令，末尾仍发送换行：

| 测试方向 | 命令 | 配置 `dist 1000` 后的目标距离 |
|---|---|---:|
| 前进 | `f` | 1000 mm |
| 后退 | `b` | 1000 mm |
| 左移 | `l` | 1000 mm |
| 右移 | `r` | 1000 mm |

每次观察车自然停稳后测量，再摆回同一标记和朝向。再次发送方向键即可开始新试验；软件不会自行重试、自动返回或接着执行路线。移动期间修改 `dist`、`rpm` 会被拒绝。若状态或动作不符合预期，先发 `!`，再发 `info` 查询。

先在 30 rpm 下每方向测 3 次，再只修改速度并重复：

```text
rpm 60
```

60 rpm 的动作与重复性正常后，`f/b` 可再测试 `rpm 90`。`l/r` 当前基础速度封顶60 rpm，设置90不构成90 rpm横移测试。旧记录表中的左右90 rpm行应标为“不适用：当前限速60”，按实际限速填写。固定地面、负载和距离，不同时改 ppm；出现明显侧滑或无法完成时先排查。

如果需要继续原来的查表导航，发送 `nav`，再按原流程 `pose`、`heading`、`rpm`、`go`。道路参数仍保持原值，因此导航 E→H、H→E 当前为 780 mm；标定模式的 `dist` 不修改道路或查表数据。

### 测量与记录

优先使用新的 [records/分速度误差记录.csv](records/分速度误差记录.csv)，已预填 36 次测试的方向、速度和目标距离。原 [四方向误差记录.csv](records/四方向误差记录.csv) 保留，可能包含你已填写的数据，适用于原道路测试。

记录主方向实际距离、侧向偏移，以及车头偏转角；没有角度测量工具时在备注写“明显偏左/偏右/未见明显偏转”。

- 距离误差（mm）＝实测主方向距离 − 目标距离。
- 相对误差（%）＝距离误差 ÷ 目标距离 × 100。
- 例如目标 1000 mm，实测 980 mm，误差为 −20 mm、−2%。

侧向偏移约定：以前进基准 +Y 为前方，向右记正、向左记负；左右平移时，向前的偏移记正、向后记负。车头偏转以从上方看顺时针为正。

按方向和速度分别比较平均误差与结果波动。实际车速不同可能改变滑移、启停和重复性，不直接假定越慢越准。摄像头左侧视距短时，可将较慢左移作为候选，但最终速度还需结合真实识别距离、系统延迟与实测停车距离确定；此版本没有自动视觉限速。

当前全局比例为 `ppm_x=11.052632`、`ppm_y=10.36`，在 `car_config.h` 的 `CALIBRATED_PPM_X/Y` 修改；前后共用 Y 比例，左右共用 X 比例。此次根据操作者在 60 rpm 下左右目标 1000 mm、反复实测约 950 mm，将 X 比例按 `10.5 × 1000 / 950` 增加约 5.263%。旧位置模式中1000 mm横移对应脉冲由10500变为11053；当前 `l/r` 和 `runimu` 横移使用该比例把编码器计数换算为距离并连续调速，不再一次下发这组目标脉冲。前后位置模式1000 mm仍为10360脉冲，标定默认60 rpm。

距离比例修正同时作用于标定命令和导航中车身左右方向的路段，不修改路段目标距离、方向映射或路线查表。操作者原始测量见 [60 RPM 实测与距离补偿](records/60RPM实测与距离补偿.md)。后续可按 `新 ppm = 旧 ppm × 目标距离 / 实测平均距离` 调整，但单个全局比例不能消除侧向偏移或车头偏转。

横移向前预补偿为左移每米20 mm、右移每米8 mm。当前连续横移将其作为速度前馈，与IMU航向修正合成；旧位置模式保留四轮合成脉冲。初值来自 60 rpm 测量的保守估计，补偿后的实际距离、偏移和轨迹尚未实测；该配置也作用于其他速度，但其他速度的物理效果未验证。该前后方向补偿是开环前馈；IMU闭环只观测航向，不能直接观测前后漂移。调整和关闭方法见 [横移向前预补偿](docs/横移向前预补偿.md)。

改源码后完整重编译、下载、复位运行，再重新测量。道路长度、内移参数或拓扑改变后，在本目录运行 `tools/rebuild-route-table.ps1 -Node <node路径> -Gcc <gcc路径>` 重生成并校验查表，再编译。工具和依赖源码已随包提供；车上仍使用离线查表。

## 8. 常见问题和当前限制

完整命令与故障排查见 [docs/命令与故障排查.md](docs/命令与故障排查.md)。

- 新版本会忽略整条命令首尾的空格和制表符；命令内部格式仍须正确。导航 `go` 之前必须收到起点确认成功。
- `69 6E 66 6F 0A` 只是 `info` 加换行；不能仅凭发送回显判断串口已通。
- VOFA 报 I/O 中止时关闭旧连接、刷新端口并重连；不能据此断定 STM32 程序错误。
- `estimate elapsed` 只是估时。等待确认超过 `估时×3+5000ms` 会进入 `FAULT error=3`；这不是电机回传的故障码。
- 标定模式 `!` 后仍保留距离与速度，摆回标记起点可再次发方向键；导航模式则需确认真实节点位置。

目前全程模式解析电机ACK与到位状态，尚未完成实车兼容性验收；没有自动标定、自动记录实际距离、全自动视觉避障或整场比赛闭环。完整验证范围见 [验证状态](docs/验证状态.md)。

## 9. 检查传输完整性

可在解压后的目录运行以下 PowerShell 命令；它只检查文件与工程路径，不编译、不下载、不连接硬件：

```powershell
& '.\tools\check-package.ps1'
```

清单记录的是打包时状态。之后有意修改源码或重新编译，初始哈希不一致是正常的；将自己的测试数据保存在 `records/` 中。新增文件不要求匹配初始清单。

开发者可选的电脑入口行为检查使用已有原生 GCC，不要求普通测试用户安装：

```powershell
& '.\tools\verify-heading.ps1' -Gcc 'C:\msys64\ucrt64\bin\gcc.exe'
```

该入口覆盖连续转向、直行、横移、A/C整圈、返程、模式互斥、故障、按钮、扫码及CAN接收行为，并分别编译IMU串口开启/关闭两种配置。`verify-entry.ps1` 另保留旧位置模式入口测试。二者均使用电脑模拟，不连接核心板，不能代替实车测量。
