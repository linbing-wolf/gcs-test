## 0. 一句话结论

**车的"局部闭环"做得很完整（每段航向、每段里程都有反馈），但"全局是开环的"：没有横向位置观测量。
再叠加 0.8° 航向死区和未修正的前后距离比例，导致误差逐段累加——14m 一圈偏出 200~600mm。**

## 2. 误差来源分解

| # | 来源 | 机制 | 量级（14m 一圈）| 置信度 | 依据 |
|---|---|---|---|---|---|
| 1 | **航向死区 0.8°** | 每段最多允许偏 0.8°，控制器不修 | 0.8°→**196 mm**；1.5°→**366 mm** | 高 | `CAR_HEADING_TOLERANCE_CDEG=80` |
| 2 | **前后距离比例** | 10360 脉冲走 1020mm，真实应为 10.16 脉冲/mm，代码仍用 10.36 | **+240~310 mm**（沿路径）| 中 | 2 次实测 |
| 3 | **横向 crabbing**（仅靠 IMU 无法观测）| 四轮线速度不一致/滚子不对称，yaw 不变但整车横移 | 与 #1 重叠，需实验区分 | 中 | 实测 13~27mm/m |
| 4 | **原地旋转的平移** | 每圈 **16 次转向**（每段都会停车对航向，其中 16 次需要转 90°），旋转中心不在车心 | 3~5 mm × 16 ≈ **50~80 mm** | 中 | 代码路径 |
| 5 | **IMU 绝对漂移** | `yaw_zero_cdeg` 只在发车时取一次；每段目标按绝对 yaw 重算 | 1~2°/4min → 横向 240~480 mm | 中 | 器件特性 |
| 6 | **90 RPM 未标定** | 所有比例都是 60 RPM 测的 | 未知（可能 ±2~5%）| 高（事实）| CSV 空白 |
| 7 | 横移前后补偿 | 左 20 / 右 8 mm/m，未实车验证 | 影响回程闭合 | 高（事实）| `car_config.h:41-42` |
| 8 | 到站位置不校验 | 只校验航向，不校验 xy | 累积 | 高（事实）| 代码路径 |

### 2.1 为什么 #1 和 #3 的数值几乎一样

```
0.8°  × 1000mm = 13.96 mm/m   ← 死区下限
1.5°  × 1000mm = 26.2  mm/m   ← 最小转速 3 RPM 推不动时的实际稳态
实测：13 ~ 27 mm/m            ← 正好落在这个区间
```

**结论：实测的横向漂移，量级上就是"航向稳态误差 0.8~1.5°"，不需要用 crabbing 解释也能对上。**
要确认到底是哪一种，必须做 §5 的实验 A。

## 3. 现有的"保证结果正确"机制

### 3.1 航向闭环（行进中持续运行）

```c
// main_table_nav.c:1532
turn = heading_control_rpm(&run.heading_control, run.turn_rpm);
if (forward || left) {                       // 直行时限制修正权限
    limit = min(|primary|-1, CAR_HEADING_DRIVE_TRIM_RPM=20);
    turn = clamp(turn, -limit, limit);
}
run_velocity_send(forward, left, turn);      // 每 25ms
```

| 项 | 值 |
|---|---|
| 控制律 | P + D（D 用 IMU 实测角速度，不是误差差分）|
| 增益 | KP = 1.2 RPM/°，KD = 0.3 RPM/(°/s) |
| 死区 | **0.8°** |
| 最小修正 | 3 RPM |
| 直行修正上限 | 20 RPM，且不允许把轮子修成反转 |
| 更新条件 | 必须收到新的 IMU 样本 |
| 目标来源 | 每段开始时按 `yaw_zero_cdeg` 重算绝对目标；段内按增量保持 |

**保证**：车头角度在目标 ±0.8° 内。
**不保证**：车在路中间（横向不可观测）、地面实际走了多远（打滑）。

### 3.2 距离闭环

```c
progress_mm = sum(四轮编码器增量·符号) × 3200 / (4 × 65536 × PPM)
```

| 项 | 值 |
|---|---|
| 反馈源 | 四轮 CPOS（65536/圈）|
| 控制律 | P，Kp = 0.5 RPM/mm，最低 3 RPM |
| 容差 | 1 mm |
| 超程保护 | 超过目标 +15 mm 或反向 → 故障 |
| 符号锁定 | 起步时按首段位移方向锁定，之后固定 |

**保证**：轮子转了 N mm。**不保证**：地面走了 N mm。

### 3.3 每段停车对航向（每圈 18 次）

`run_segment()` 在 `imu_mode` 下**每一段**都调用 `run_begin_alignment()`：
停车 → 等 IMU 稳定（≤0.8°、角速度≤1°/s、3 样本、300ms）→ 再走。

好处：段间不累积航向误差。
代价：**每圈多 18 次原地微转**（§2 #4）。

### 3.4 到站姿态门控

每个工位有指定朝向（原料左 / 粗加工右 / 暂存下），航向没对好不推进 job。
**但只校验姿态，不校验位置。**

### 3.5 回归测试

`tests/verify_entry` + `tests/verify_heading`：**1,180,756 条断言全过**，`-Wall -Wextra -Werror` 零警告。
覆盖：几何、四方向、时间回绕、CAN 故障注入、IMU 冻结/反向、编码器卡死。

## 4. 为什么会存在死区，以及它的代价

### 4.1 死区本身是必要的

| 原因 | 没有死区的后果 |
|---|---|
| IMU 噪声（静止 ±0.1~0.3°）| 控制器追噪声，轮子持续微调、车抖、电流大 |
| 电机静摩擦死区 | 1 RPM 指令推不动，0/3 RPM 来回跳 |
| 控制延迟（25ms + CAN）| 纯 P 必然在 0 附近形成极限环 |
| 麦克纳姆的代价 | 每次差速修正都伴随横向搓地 |

### 4.2 这里的问题是"一个数干了两件事"

```c
CAR_HEADING_TOLERANCE_CDEG = 80     // 同一个常数
  → 控制死区：|error| ≤ 0.8° 不修
  → 到位判据：|error| ≤ 0.8° 算完成
```

于是：**车在 0.8° 内停下 → 判定"已对齐" → 整段斜着走 → 永远不会被纠正。**
而且是对称死区，停在哪一侧就在哪一侧。

### 4.3 代价量化

| 死区 | 每米横偏 | 14m 累计 |
|---|---|---|
| 0.8°（现在）| 14 mm | 196 mm |
| 0.4° | 7 mm | 98 mm |
| 0.2° | 3.5 mm | 49 mm |
| 0.1° | 1.7 mm | 25 mm |

## 5. 定位实验（按顺序做，每一步都能砍掉一半猜测）

### 实验 A：区分"斜着走"还是"横着搓"（最重要）

```text
test → dist 3000 → rpm 60 → 前进
```

记录：起点/终点 IMU yaw + 地面横向偏差。

| 结果 | 结论 | 对策 |
|---|---|---|
| yaw 停在 0.5~0.8°，横偏 40~80mm | **死区稳态误差** | 缩死区 + 加 I |
| yaw 一直在 ±0.1°，横偏 40~80mm | **crabbing（纯侧滑）** | 必须外部横向参考 |
| yaw 漂到 1.5° 且回不来 | 最小 3 RPM 推不动 | 提高 MIN_RPM |

### 实验 B：前进 vs 后退（确认 #2 是不是纯比例）

```text
test → dist 1000 → rpm 60 → f 连做 3 次
test → dist 1000 → rpm 60 → b 连做 3 次
```

- 前后都偏长 → 纯比例问题，改 `CALIBRATED_PPM_Y`
- 只有前进偏长 → 停止滞后/减速滑行，需按方向分系数或停点提前

### 实验 C：90 RPM 补测（填掉空白 CSV）

```text
rpm 90 → dist 1000 → f / b / l / r 各 3 次
```

把这 12 个数填进 `records/分速度误差记录.csv`，才能判断 90 RPM 是否需要独立 PPM。

### 实验 D：量化原地旋转的平移

```text
连续 left90 ×4（回到原朝向）→ 量车体位置漂移
```

每次 >5mm 就需要加"转向位移补偿"。

## 6. 修复优先级

| 优先级 | 改动 | 预期收益 | 风险 |
|---|---|---|---|
| **P0** | `CALIBRATED_PPM_Y: 10.36 → 10.16`（或按实验 B 分方向）| 消掉沿程 +2%（≈280mm）| 低 |
| **P0** | `CAR_HEADING_TOLERANCE_CDEG: 80 → 30~40`（**不要直接到 20**，见 11.8）| 横向 14→5~7 mm/m | 低，可能轻微抖动 |
| — | `CAR_HEADING_MIN_RPM` **保持 3~5，不要提高**（见 11.8）| — | 提高到 8 会让精细对齐来回摆 |
| P1 | 航向加积分 I（限幅、仅直行段积分）| 消残余稳态误差 | 中（需防 windup）|
| P1 | 转向后按角度查表补偿平移 | 16 次 × 3~5mm | 低（纯补偿）|
| P2 | 每段目标航向改用"新 IMU 零点"或每圈重零 | 抑制 IMU 漂移 | 低 |
| P2 | 到站位置校验（需视觉）| 消除累计误差 | 依赖视觉接入 |
| P3 | 连续横向参考（视觉循线 / 红外）| 唯一能真正闭环 | 工作量大 |

### 6.1 关于 PID 的结论

- **航向**：P+D 已有，**只缺 I**，不需要完整 PID。
- **距离**：被控对象本身是积分器，P 已无稳态误差，**不要加 I**。
- **横向**：不是控制问题，是**观测问题**，加什么 PID 都无效。

## 7. 与视觉端配合的两种闭环（下一步）

### 7.1 站点绝对校正（离散，先做）

每圈 8 个停点，视觉会回 `PICK/DISC/STACK` 坐标。给每个工位存"期望坐标"，到站后：

```
误差 = 实测 - 期望
位置修正 += 误差          // 把里程计累计误差清零
```

效果：14m 的累计误差被切成 8 段（≈1.5m 一段），最坏只剩单段误差。
前提：视觉协议接入（**当前完全没有**，`vision-maixcam/stm32_patch/vision_uart.c` 是旧的 0xFF/0xFE 9 字节帧，与视觉端 v3.1.0 的 `AA55 LEN payload CRC8 0D` 不兼容）。

### 7.2 连续循线（动态纠偏）

视觉端新增 `LINE,dx,dtheta,conf`（20~30Hz），STM32 把 `dx` 叠加进混控器的 `left` 分量：

```c
left += (int16_t)(CAR_LINE_KP * dx);
```

安全限制：
- `left` 限幅 ±15 RPM
- 300ms 收不到 `LINE` → trim 衰减到 0
- `|dx| > 120px` → 视为丢失，停车报警

前提：确认 MaixCAM2 行驶时相机能看到脚下路面（若云台抬起看工位，则改用 5 路红外循迹）。

## 11. 二次复核补充（写完本文后再查一遍发现的问题）

### 11.1 `records/*.csv` 是空模板
两张表 48 行全部没有数据。**"四方向误差""分速度误差"从未真正记录**，所谓"后退误差为零"也没有出处。→ 所有标定结论都只有 1~2 个样本。

### 11.2 每段都完全停车（18 次/圈），其中 16 次要原地转
`imu_mode` 下**每一段**开头都走 `run_begin_alignment()`：停车 → 等稳定 → 再走。
转向也在这里完成（不是另外的动作），所以"16 次转向"包含在 18 次对航向里。

代价有两块：
- **时间**：每次对齐至少 300ms（`CAR_HEADING_STABLE_MS`）+ 停稳判定 100ms，一圈 ≈ **6~8 秒**
- **位移**：每次原地旋转因四轮摩擦不均产生 3~5mm 平移，且**没有任何补偿**

> 修正：先前本文曾写"34 次旋转"，是重复计数；实际是 16 次旋转 + 18 次停等。

### 11.3 停止阶段的转向不受 20 RPM 限制（条件触发）
直行时 `turn` 被限到 20 RPM，但 `VELOCITY_STOP_FORWARD` 阶段 `forward/left` 都是 0，
`if (forward || left)` 不成立 → `turn` 直接吃 `run.turn_rpm`（runimu = **60 RPM**）。
若段末发现较大航向误差（如 IMU 漂移 3°），会**突然原地 60 RPM 转一下**，产生横向"踢"。
（正常情况段末误差在死区内，`turn` 为 0，不会触发；这条是异常路径的风险。）

### 11.4 航向误差 0.9° 时可能"命令 3 RPM 但推不动"
`heading_control_rpm` 在 0.9° 时算出 1.2 RPM → 抬到 3 RPM。
若 3 RPM 低于电机静摩擦死区，IMU 永远不变 → 对齐永远不满足 → **20s 超时故障**。
现场表现：车停着不动，日志刷 `continuous motion did not converge before deadline`。

### 11.5 `progress_mm` 是四轮求和，单轮打滑会偏 25%
`sum/4` 的写法假设四轮贡献相等。若一轮悬空/打滑（编码器转得更多），里程会**偏大**→ 提前停车；
若一轮被拖住不转，里程**偏小** → 冲过头。

### 11.6 每段目标航向都用"发车时的 IMU 零点"
`run_heading_error()` 用 `sample.yaw_cdeg - run.yaw_zero_cdeg`。
IMU 的零漂会**均匀旋转整条路线**，且不会自愈。跑 4 分钟漂 1° → 14m 后横向 ~240mm。

### 11.7 地图内移常量（90/50/50/80）与实际场地不符时是"整体平移"
这四项是经验值，误差会直接变成**所有工位的系统性偏移**（不是随机的）。
若"每个工位都往同一方向偏同样的量"，优先怀疑这四个数，而不是控制环。

### 11.8 复核修正：不要把 MIN_RPM 提到 8，死区别直接降到 0.2°

先算一下"3 RPM 差速"能产生多快的转向：

```
3 RPM 轮速 → 15.4 mm/s
直行时左右差 2×15.4 = 30.9 mm/s，轮距 216mm
→ 偏航角速度 ≈ 0.143 rad/s ≈ 8.2 °/s
→ 25ms 控制周期 = 0.2°/tick
```

也就是说 **3 RPM 并不"推不动"，它已经能产生 8°/s 的修正**。把 MIN_RPM 提到 8 RPM，
每 tick 就是 0.55°，配上 0.2° 死区会**在零附近来回摆**（画龙）。

同时，死区也不是越小越好：`heading_control_update` 要求
`|error| ≤ 死区` 且 `|rate| ≤ 1°/s` 连续 3 样本、持续 300ms 才判 DONE。
如果死区小于 IMU 静止噪声，**永远满足不了 → 每次对齐 20s 超时**。

所以正确做法：
1. 先跑 `imu` 看静止时 `yaw_cdeg` 的抖动幅度（峰值）
2. 死区 = max(2 × 抖动峰值, 0.3°)，一般落在 **0.3~0.5°**
3. `CAR_HEADING_MIN_RPM` 保持 3~5
4. 只有确认"命令 3 RPM 但 yaw 不动"时，才提高 MIN_RPM

> 这一条修正了本文 §6 早期的建议（原写"80→20、3→8"）。

---

### 11.9 每帧速度下发阻塞 4ms
`run_velocity_send()` 每轮对四个电机各 `delay_ms(1)`，共 **4ms**；控制周期 25ms，占用 16%。
这 4ms 内主循环不处理串口/CAN，是"接视觉后 RX 溢出"风险的来源之一（见视觉端交接文档的 §3）。

---

### 11.10 视觉补丁与视觉端协议不兼容
`vision-maixcam/stm32_patch/vision_uart.c`：`0xFF + 9 字节 + 0xFE`，无 CRC；
视觉端 v3.1.0：`AA55 LEN payload CRC8 0D`。
另外补丁里 `Vision_RxFlag/RxState/pRxPacket` **未加 volatile**（ISR 共享变量）。

### 11.11 接线文档自相矛盾

- 视觉端 `config.py`：**A21/A22（UART4）**

## 12. 给接手人的提醒

1. **先做实验 A/B/C，再改代码**。现在最大的风险是"凭感觉调参数"，而 CSV 是空的。
2. **改任何一个参数后，复测同一组实验**，否则无法判断是改好了还是环境变了。
3. **不要把"能跑完整圈"当成"路径正确"**。现在能跑完是因为每段都闭环，但终点位置没人测量。
4. 如果后续接入视觉，优先做**站点校正**（改动小、收益确定），再考虑连续循线。

### 11.12 反馈过期时不会先减速，会"盲跑"最多 300ms

```c
// main_table_nav.c:1457
if (!run_velocity_feedback_fresh()) {
    if (run.state != RUN_PREFLIGHT || ... > CAR_VELOCITY_FEEDBACK_MS) {
        run_fault("four-wheel velocity/position/status stale"); return;
    }
    run_velocity_query(); return;      // ← 直接 return，不发送新的速度指令
}
```

四轮反馈任一超过 **300ms** 没更新时，代码只是 `return` 等下一轮，
**不会先减速或停车**——电机仍按上一条速度指令继续跑。

按 90 RPM（≈0.43 m/s）算：300ms ≈ **130mm 的盲跑距离**，然后才报故障停车。
如果 CAN 偶发拥塞（查询轮转 12 项 × 25ms ≈ 60ms 一轮，正常不会触发），
这一段就会变成"无监督前进"。

> 建议：反馈过期 >150ms 时先降速到 30 RPM，>300ms 再故障停车。
> 属于 P2，改动小、收益明确。

### 11.13 复核结论

- 本文 §2 的排序（死区 > 距离比例 > 转向平移 > IMU 漂移）**不变**；
- §6 早期"死区 80→20、MIN_RPM 3→8"的建议**已修正**为"死区 80→30~40、MIN_RPM 保持"（见 11.8）；
- 之前把"16 次转向"重复计成"34 次旋转"，**已修正**（见 11.2）；
- 新增 §11.9（每轮阻塞 4ms）与 §11.12（反馈过期盲跑）两条风险。
