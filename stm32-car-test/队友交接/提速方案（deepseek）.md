# 提速方案 · AI 交接（deepseek）

> 配套文档：`队友交接/路径诊断ai交接（deepseek）.md`（误差来源与验证方法）
> 日期：2026-10-18
> 适用：`stm32-car-test/`，commit `c273bd8` 之后
> 目标：在**不显著恶化终点位置误差**的前提下，把单圈时间从 ~64s 压到 ~50s

---

## 0. 一句话结论

**时间一半花在直线、一半花在 16 次原地转向 + 18 次停等。
优先动 `CAR_RUN_RPM` 和 `CAR_TURN_CLOSED_LOOP_RPM`，但必须同步放大航向修正权限、重标 PPM。
提速会让已有 200~600mm 的偏移更大，所以必须"一档一测"。**

## 1. 现状时间账（估算，非实测）

| 环节 | 计算 | 时间 |
|---|---|---|
| 直线 13960 mm @ 90 RPM | 90 RPM ≈ 463 mm/s | **30.2 s** |
| 16 次原地 90° @ 60 RPM | 每次 ≈0.73s 转 + 0.4s 稳定 + 加减速 | **24 s** |
| 18 次分段停等 | 300ms 稳定判据 + 100ms 停稳 + 启停 | **10 s** |
| **合计** | | **≈ 64 s** |

> 90 RPM 的线速度换算：1 圈 = 3200 脉冲 = 308.9 mm（由 `CALIBRATED_PPM_Y=10.36` 反推）
> → 90 RPM = 1.5 rev/s × 308.9 = **463 mm/s**；每 1 RPM ≈ 5.14 mm/s。

## 2. 四个可调旋钮

| # | 参数 | 现值 | 建议值 | 预计省时 | 风险 |
|---|---|---|---|---|---|
| 1 | `CAR_RUN_RPM` | 90 | **110（保守）/ 120（激进）** | **-5 ~ -7.6 s** | 打滑↑、PPM 失效、停车距离↑ |
| 2 | `CAR_TURN_CLOSED_LOOP_RPM` | 60 | **80** | **-4 ~ -6 s** | 原地转打滑↑ → 每次转向平移变大 |
| 3 | `CAR_MOTION_ACCELERATION` | 150 | **200** | -1 ~ -2 s | 起步打滑、超调 |
| 4 | `CAR_HEADING_STABLE_MS` / `CAR_HEADING_SETTLE_MS` | 300 / 100 | **150 / 50** | -3 s | IMU 噪声大时会误判"稳定" |

四个全上：**≈64s → 48~50s（快 22%）**。

## 3. 提速必须同步改的三处（否则会出新故障）

### 3.1 航向修正权限

```c
// car_config.h:85
#define CAR_HEADING_DRIVE_TRIM_RPM    20
```

直行时的最大差速。90 RPM 时占 22%，120 RPM 只占 17%。
同样的扰动需要更大的修正量。

→ 提到 **25~30**。否则高速下"车头修不回来"，表现为 `error_cdeg` 长期贴上限。

### 3.2 距离超程保护

```c
// car_config.h:98
#define CAR_DISTANCE_OVERRUN_MM       15
```

四轮反馈轮转一圈约 **72 ms**（12 项查询 × 6ms）：

| 速度 | 72ms 内位移 |
|---|---|
| 90 RPM | 33 mm |
| 120 RPM | **44 mm** |

减速段一般不会真冲 44mm，但偶发超调会更接近 15mm 阈值，
可能误报 `encoder distance overrun/reversed`。

→ 两个选择（建议都做）：
- `CAR_DISTANCE_OVERRUN_MM: 15 → 25`
- `CAR_VELOCITY_QUERY_MS: 5 → 3`（反馈轮转 ~43ms）

### 3.3 PPM 必须按新速度重标

打滑随速度非线性增长，**90 RPM 的 `10.36` 不能直接用到 120**。

| 速度 | 现状 | 动作 |
|---|---|---|
| 90 RPM | 10.36（从未按实测修正）| 先按实验 B 修正到 ≈10.16 |
| 110/120 RPM | 无数据 | 实测 3 次 1000mm，重新算 |

> 方法：`test → dist 1000 → rpm <新速度> → f ×3`，取平均值，
> `新 PPM = 旧 PPM × 实测距离 / 1000`。

## 4. 物理天花板

| 限制 | 影响 |
|---|---|
| 电机 | 24V + 42 步进，>150 RPM 扭矩明显下降，急停距离变长 |
| 麦克纳姆滚子 | 转速越高，横向滑移越大 → **crabbing 和转向平移都会恶化** |
| 地面 | 光滑地砖上 120 RPM 起步会打滑，脉冲与实际位移脱节 |
| 控制周期 | 固定 25ms；120 RPM 每 tick 走 15mm，`turn` 的滞后会放大超调 |
| 反馈周期 | 72ms；速度越高，"看到的距离"越滞后于真实位置 |

**经验上限：110~120 RPM 是这套底盘"还能保证不飘"的区间，再往上必须靠外部闭环兜底。**

## 5. 分阶段实施（每次只改一档）

### 阶段 0（前置，必做）
1. 修 `CALIBRATED_PPM_Y`（10.36 → 实测值，约 10.16）
2. 修航向死区（80 → 30~40，**不要到 20**，见诊断文档 11.8）
3. 跑 3 圈，记录终点偏差，作为基线

> 不做这一步，提速后无法判断误差是"速度带来的"还是"原来就有的"。

### 阶段 1（直线提速）
```c
CAR_RUN_RPM = 110
CAR_HEADING_DRIVE_TRIM_RPM = 25
CAR_DISTANCE_OVERRUN_MM = 25
```
→ 跑 3 圈，记录终点偏差。
**判定**：偏差比基线恶化 <100mm → 保留；否则回 100 RPM 再试。

### 阶段 2（转向提速）
```c
CAR_TURN_CLOSED_LOOP_RPM = 80
```
→ 先用 `left90 ×4` 测旋转平移是否变大，再跑整圈。
**判定**：4×90° 后回到原点的偏差 <30mm → 保留。

### 阶段 3（时间常数）
```c
CAR_HEADING_STABLE_MS = 150
CAR_HEADING_SETTLE_MS = 50
```
→ 观察是否出现"没停稳就判完成"（表现为下一段起步时车身还在晃）。

### 阶段 4（可选）
```c
CAR_MOTION_ACCELERATION = 200
CAR_VELOCITY_QUERY_MS = 3
```

## 7. 明确不建议做的两件事

| 方案 | 为什么不做 |
|---|---|
| **弧线过弯（不停车转向）** | 省 ~10s，但位置精度会明显下降，且需要视觉兜底；当前没有横向闭环 |
| **相邻同向段合并** | 18 段里只有 2 段同向，收益 <1s，改动却要动状态机 |

---

## 8. 提速后的连锁影响（提前知道）

1. **同一圈内不同速度的段**（起飞/返回）会打滑不一致 → 建议全程统一速度，不要混用。
2. **停车距离变长**：`CAR_DISTANCE_KP_X100=50` 的减速曲线在高速下偏软，
   若实测普遍冲过 5~10mm，把 KP 提到 60~70。
3. **IMU 延迟更敏感**：250ms 时效在高速度下对应 115mm 位移，
   如果出现 `IMU sample stale` 频繁报警，说明串口被阻塞（见诊断文档 11.9）。
4. **终点误差对速度更敏感**：同样的 0.8° 死区，速度不影响横向误差；
   但打滑影响沿程误差 → 提速后**沿程**会比**横向**更先恶化。

## 10. 一句话给接手人

**提速的收益在直线和转向，风险在打滑和转向平移。
先把 PPM 和死区修好、量出基线，再按"一次一档、三圈一测"往上加。
超过 120 RPM 之前，务必先有横向闭环（视觉/循线），否则会变成"很快但每次停的位置都不同"。**
